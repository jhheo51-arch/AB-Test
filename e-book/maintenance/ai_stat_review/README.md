# v0.22 AI 통계 검수

## 결론

사용자는 검수할 사람이 없으므로 미라 또는 봇이 통계 검수를 진행하도록 요청했다. 이에 수치 재계산 봇과 설계·해석 검토 봇을 나눠 실행하고, 부모 AI가 별도로 원자료와 후속 사례 및 표본계획을 계산해 교차 확인했다. 사람 검수자 지정을 진행의 선행 조건으로 요구하지 않는다. 독립된 사람 검수나 실제 독자시험을 완료했다는 의미는 아니다.

**검토 범위에서 새로 확정한 본문 통계 오류와 수정이 필요한 조건부 결함은 없다. 원고 유지가 결론이다.** 다만 기존 계획 파일의 LF/CRLF 표현에 따른 바이트 해시 불일치 한 건을 명시한다. 이 때문에 모든 엄격 해시 검사가 통과했다고 보고하지 않는다.

## 실제 실행과 결과

| 검수 흐름 | 실행 범위 | 결과 |
|---|---|---|
| 수치 검수 봇 | 원본 배정과 사건, 발송과 계약을 고객 단위로 연결하고 완료 주분석, 보호 탐색, 고객별 순기여와 Welch 및 비용 민감도를 별도 구현 | 명시 검사 154건 중 152 통과. 실패 2건은 아래의 동일한 역사적 계획 해시 차이 |
| 설계와 해석 검토 봇 | 원고 5·6·8·11·12장과 부록 A, 원 계획과 두 결과 장부를 대조 | 새 확정 오류와 조치가 필요한 조건부 결함 없음. 기존 한계 3건은 비결함 유보로 분리 |
| 부모 AI 주분석 | 원본 사건에서 배정별 결과를 새로 구성하고 완료와 보호, 고객별 순기여를 직접 계산 | 장부와의 스칼라 대조 52건 통과. 봇의 재계산과 스칼라 49개 추가 교차 대조 일치 |
| 부모 AI 표본계획 | 원 계획 격자 12조건의 최소 정수 표본을 직접 정규 근사식으로 찾고 라이브러리 결과 및 바로 전 인원을 대조 | 12조건 모두 일치. 6장 후속 설계의 검정력과 MDE도 일치 |
| 부모 AI 사례 4~6 | 원본 CSV에서 누락, 고정층화와 집단 차이, 동일 수요 세계의 FCFS 운영 규칙을 별도 재구성 | 스칼라 대조 150건 통과. 용량별 정책 9칸의 운영 CSV 108,000행 일치 |

각 검수의 검사 수는 범위가 겹친다. 합쳐서 독립된 통계 검정이나 독립된 표본 수로 세지 않는다. 생산 분석과 생성 코드를 import하거나 실행한 결과가 아니라 검수용으로 새로 만든 구현과 별도 계산을 사용했다. DB는 mode=ro와 query_only로만 열었다.

## 발견 사항: 역사적 계획 해시 표현 차이

현재 계획 파일의 실제 LF 바이트 해시는 장부와 DB에 저장된 역사적 계획 해시와 다르다. 현재 내용을 메모리에서 CRLF 표현으로만 변환해 계산한 해시는 두 저장 해시와 정확히 같다. 원고 1400줄에 이미 이 차이와 내용 동등성 및 정확 바이트 동일성의 구분이 공개돼 있다.

이는 이번 검수에서 생긴 변경이 아니며 수치나 계획 내용이 바뀌었다는 증거도 아니다. 그러나 실제 바이트 해시가 같다고 표시할 수는 없다. 실패 기록은 [수치 결과](numeric/RESULTS.json)에 그대로 남겼고, 부모 AI도 별도로 확인했다. 원본을 CRLF로 다시 저장하거나 역사적 해시를 현재 파일 해시로 덮어쓰지 않았다. 과거 결과 이전에 동결했다는 시간적 선행성을 이번 표현 비교로 새로 입증한 것도 아니다.

## 결과를 바꾸지 않는 경계

완료 B-A 우위의 근거는 유지되지만 사후 최소 사업 개선 +0.5pp 이상을 확증한 것은 아니다. 철회의 비유의는 안전의 증명이 아니며 원 계획에 정식 비열등성 설계가 없다. B-H 손익 구간은 0을 포함하고 비용과 기여액은 합성 가정이다. 집단 실습과 공유 용량 모형을 원래 큰 A/B/H의 현장 효과로 합치지 않는다.

현재 완료한 것은 AI 통계 검수다. 외부 시각 인증, 모든 모수에서의 정확 커버리지와 공동 FWER, 실제 OEM 원가와 고객 관계 및 학습 효용은 새로 검증하지 않았다. 이러한 범위 한계를 새 필수 과제로 만들어 자료 관리를 막지 않는다. PDF 인용 전수 대조와 전권 contact sheet, 외부 의뢰와 독자 모집은 진행하지 않았다.

원자료가 있는 저장소 루트에서 실행한다. 아래 코드는 검수 폴더 결과만 갱신하며 본책과 동결 입력을 재생성하지 않는다. 일부 부모 코드의 ROOT는 이번 검수 환경 경로를 명시한다. 다른 경로에서 재실행하려면 사본의 ROOT를 실제 저장소 위치로 지정한다. 이 검토 묶음만으로 원자료와 분석 환경 전체를 배포한 것은 아니다.

```bash
PYTHONDONTWRITEBYTECODE=1 uv run --no-project --with scipy --with statsmodels e-book/maintenance/ai_stat_review/numeric/CODE.py
uv run --with scipy python e-book/maintenance/ai_stat_review/parent/CROSSCHECK.py
uv run --with statsmodels python e-book/maintenance/ai_stat_review/parent/POWER_CHECK.py
python e-book/maintenance/ai_stat_review/parent/SCENARIO_CHECK.py
python e-book/maintenance/ai_stat_review/VERIFY.py
```

원고와 PDF, 웹 읽기본, 작성 양식과 기존 ZIP을 변경하지 않았다. 검수 단계에서는 검토 산출물과 작업 상태만 로컬에 저장했으며, GitHub 반영은 이후 사용자의 별도 동기화 요청에 따라 진행한다.
