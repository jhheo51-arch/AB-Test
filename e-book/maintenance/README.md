# GitHub 자료 관리

이 프로젝트의 전자책은 출판하거나 판매하지 않고 비공개 GitHub에서 학습 및 실무 참고 자료로 관리한다. v0.22 원고와 PDF, 웹 읽기본과 작성 양식은 유지하고, 본문 개발을 다시 열지 않는다. 출판사 선정과 투고, 판매처 규격과 출간 승인 과제는 완료가 아니라 중단으로 정리했다.

## 현재 작업의 기준

[TASKS.json](TASKS.json)이 현재 작업과 상태의 기준이다. [과거 출판 검토](../review/publication_v22/PUBLICATION_REVIEW.md)는 당시 원고 평가와 권리 근거를 보존한 기록이지 현재의 출판 계획이 아니다. 옛 체크리스트를 Git 저장의 선행 조건으로 요구하지 않는다.

| 작업 | 진행 및 확인 위치 |
|---|---|
| R1 저장소와 파일의 무결성 | [실행 결과](checks/repository_check.json). 원고와 PDF 및 ZIP, 기존 동결 입력과 로컬 링크를 확인한다. |
| R2 기존 동작 회귀 검사 | [실행 결과](checks/regression_check.json). 확대와 복귀, 복사와 저장, 긴 기록 인쇄를 기존 검사로 재확인한다. |
| R3 저자 직접 읽기와 작성 | [직접 확인 안내](AUTHOR_CHECK.md)와 [빈 관찰 기록](AUTHOR_OBSERVATIONS.csv). 별도로 요청받은 [AI 대행 수행](ai_walkthrough/README.md)은 완료했으며 저자 실제 수행 완료와 구분한다. |
| R4 확인된 오류만 관리 | [오류 기록](ISSUES.csv). [이번 점검 회차](ai_walkthrough/CHECK.json)에서 확정한 새 본문 오류는 없어 본문은 유지했다. 향후 실제 문제의 위치와 증상, 최소 수정과 재검사 근거를 남긴다. |

## 다시 확인하는 명령

저장소 루트에서 실행한다. 기본 명령은 기존 파일을 읽고 관리 기록만 갱신하며 본책이나 분석 결과를 재생성하지 않는다.

```bash
python scripts/check_ebook_maintenance.py
```

실제 브라우저 동작과 인쇄도 재검사하려면 설치된 uv와 Chrome을 사용하는 다음 명령을 쓴다.

```bash
python scripts/check_ebook_maintenance.py --regressions
```

회귀 검사는 기존 v22 검사 로직을 실행하되 출력 경로만 이 관리 폴더의 checks 아래로 분리한다. 이는 독립적인 통계 재감사나 사람의 수행시험이 아니다. 실제 고객 자료는 사용하지 않는다.

## 유지할 경계

- 새 장과 사례, 이론, 방법론 및 기능을 늘리지 않는다.
- 확인된 오류와 구체적인 읽기 장애만 수정한다. 정확성과 79쪽 결정문 보존 조건이 충돌하면 먼저 저자에게 알린다.
- 글꼴과 출처 고지, 원자료와 지난 판 및 감사 기록은 보존한다. 비공개 보관이 이용 조건을 없애지는 않는다.
- 사람 감수나 실제 독자시험을 완료하지 않았다는 한계는 계속 표시한다. 다만 이를 Git 보관을 막는 출판 승인 조건으로 두지 않는다.
- 외부 공유와 유료 의뢰, 독자 모집과 공개 전환, 기존 차단 검사의 재개는 자동 진행하지 않는다.
- tool/의 앱과 영상 작업은 별도 범위이며 이 작업에서 구현하거나 평가하지 않는다.
