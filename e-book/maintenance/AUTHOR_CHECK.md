# 저자 직접 확인 기록

이 문서는 출판 준비나 새 연습 개발을 위한 것이 아니다. 비공개 GitHub에서 관리하는 v0.22를 실제로 읽고 기존 과제를 작성해 보는 안내다. AI가 대신 수행한 결과를 실제 독자 시험으로 채우지 않는다. 현재 실제 수행 기록은 비어 있다.

## 사용할 파일

1. [웹 읽기본](../exports/v22/ebook_review_v22.html) 또는 [97쪽 PDF](../exports/v22/ebook_review_v22.pdf)를 연다. GitHub의 HTML 코드 화면 대신 로컬 파일을 브라우저로 열어야 확대 기능을 쓸 수 있다. ZIP을 받았다면 먼저 압축 해제하고 assets 폴더를 함께 둔다.
2. 작성은 [기존 여섯 항목 양식](../exports/v22/MINIMUM_RECORD.html)을 사용한다. 새 필수 기록 칸은 만들지 않는다.
3. 원고가 바뀌었다면 시작 전에 사용한 판과 파일을 적는다. 실제 고객 정보와 연락처는 넣지 않는다.

## 기존 과제로 확인할 것

| 기존 위치 | 직접 할 일 | 남길 관찰 |
|---|---|---|
| 2~4장 | 같은 비교 명세와 적용 대상, 현재 선택을 순서대로 고친다. | 어느 문장이나 선행 용어에서 멈췄는지 |
| 8장 | 기존 표를 보고 현재 선택과 근거를 적은 뒤 해설과 대조한다. | 완료와 보호, 대상 범위를 구분해 썼는지 |
| 9장 | 기존 요청과 회신 사례를 따라 같은 기록의 어느 부분을 바꿀지 적는다. | 불충분한 회신과 실제 승인을 혼동했는지 |
| 10장 | 조건이 달라진 상황에서 유지할 근거와 다시 열 조건을 고른다. | 무엇 때문에 선택을 다시 보게 됐는지 |
| 12장 | 해설과 완성 결정문을 보기 전에 기존 여섯 항목에 결정 기록을 쓴다. | 근거와 미확인, 허용할 행동 및 다음 확인을 연결했는지 |

답을 본 뒤 고친 문장과 처음 쓴 문장은 구분한다. 저자 자신이 하는 자기점검은 자기점검으로 적고, 다른 사람이 독립적으로 수행한 결과로 기록하지 않는다. 절차 안내를 받은 것과 답의 힌트를 받은 것도 구분한다. 외부 참가자를 모집하거나 자료를 보내는 일은 이번에 자동 진행하지 않는다.

## 실제 수행 기록

[AUTHOR_OBSERVATIONS.csv](AUTHOR_OBSERVATIONS.csv)에 실제 수행이 있을 때만 한 행씩 적는다. 현재는 머리글만 있으며 참가자나 결과를 만들어 넣지 않았다. 자신이 쓴 기록은 고객 정보 없이 로컬에 보관하고, Git에 올릴지는 직접 확인한다.

- 관찰 종류: 저자 자기점검 / 저자 주도 타인 수행 관찰
- 사용 판과 확인 구간
- 처음 쓴 답 또는 보관 위치
- 막힌 문장과 이유
- 도움이나 힌트 및 해설 열람 여부
- 수정할 문제가 확인됐는지, 추가 확인만 필요한지

## 오류가 확인됐을 때

[ISSUES.csv](ISSUES.csv)에 위치와 실제 증상을 기록한다. 단순 취향 차이나 설명을 더 넣을 수 있다는 이유만으로 새 작업을 만들지 않는다. 확인된 오류와 읽기 장애 후보를 구분하고, 최소 수정 후 영향을 받은 수치와 조판, 링크와 동작만 재검사한다. 79쪽 완성 결정문 보존과 정확성 수정이 충돌하면 먼저 판단을 요청한다.
