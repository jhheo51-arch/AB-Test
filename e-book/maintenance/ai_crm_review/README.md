# v0.22 자동차 CRM 업무 적용성 검토

## 결론과 현재 관리 방식

사용자 승인에 따라 CRM 기획, 고객 보호, 현장 운영을 서로 다른 봇에게 나누어 한 번 검토했다. 부모 AI가 세 보고서와 항목별 이유를 직접 읽고 원고 근거 및 기존 여섯 항목 양식과 대조했다. 실제 실무자 인터뷰나 현장 검증, 법률심사가 아닌 AI 역할 검토다.

**검토 범위에서 새로 확정한 원고 누락은 없다. 본문은 수정하지 않는다.** 이번 역할 검토 회차를 마치고 전자책은 보고된 오류와 구체적인 읽기 장애가 있을 때만 다시 여는 유지관리로 정리한다. 새 검수나 새 개발을 필수 과제로 이어 붙이지 않는다.

## 분류 결과

| 역할 | 이미 설명된 조건 | 현장 자료가 필요한 항목 | 확정 원고 누락 |
|---|---:|---:|---:|
| CRM 기획 | 8 | 2 | 0 |
| 고객 보호 | 8 | 2 | 0 |
| 현장 운영 | 7 | 3 | 0 |
| 합계 | 23 | 7 | 0 |

총 30개 역할 질문에 대한 분류다. 역할 사이에 같은 조건이 포함돼 있으므로 독립적인 검증 표본 30개나 별개의 현장 문제 7개로 세지 않는다. 현장 자료 미확보는 실제 적용 판단의 제한이지 원고에 새 내용을 넣어야 하는 오류가 아니다.

기존 설명에는 비교 정책과 적격 분모, 완료와 계약 및 보호의 지표 역할, 사전과 사후 기준, 세그먼트 적용 범위, 동의와 철회, 필수 안내의 H 보류 금지, 공유 자원 간섭, 시승 용량과 등록 상한의 구분, 제한 적용 및 복구 책임, 회신과 승인의 차이가 포함돼 있다.

현장 자료가 필요한 항목은 실제 고객의 예약 장벽, 조직의 도입 기준과 비용 및 승인 근거, 최신 동의 처리와 실제 피해 자료, 후속 보호 평가, 날짜 및 지점별 시승차와 인력 및 수요, 제한 적용의 복구 가능성 등이다. 책이 이미 확인할 조건과 역할을 명시하므로 임의 값이나 실제 회신을 만들어 채우지 않는다. 같은 설명을 새 필수문서로 중복 작성하도록 요구하지 않는다.

## 12장에 대한 현재 판단

- 기획: B를 후속 검토 후보로 유지하고 실제 도입 기준 및 변경 비용의 근거를 요청한다. 현재는 후속 설계 준비이며 전면 전환 승인이 아니다.
- 고객 보호: 발송 직전 동의와 철회 반영, 보호 비교와 평가 근거를 확인할 질문을 남긴다. 비유의를 안전으로, 보호 근거 부족을 확정 위해로 바꾸지 않는다. 실제 위반과 피해가 확인되면 성과 유의성과 무관한 보호 절차를 우선한다.
- 운영: 날짜와 지점별 수요 및 수용력, 미수용 처리와 중단 및 복구 경로의 근거를 요청한다. 사례6의 일 60슬롯을 12장의 실제 슬롯으로 가져오지 않는다.

세 역할 모두 현재 허용할 행동은 자료 확인 요청과 후속 설계 준비다. 충분한 역할 회신이 와도 다른 미확인 조건과 실제 승인까지 대신하지 않는다. 실제 승인자, 기한과 현장 회신 및 운영 성과는 만들지 않았다.

원고의 짧은 인용 71개를 각 원고 행에 대조했다. PDF 물리 쪽수나 전권 인용 전수 확인으로 확대하지 않는다. 원고와 PDF, 웹 읽기본, 작성 양식과 기존 읽기 ZIP의 기준 해시는 유지됐다. 기존 배포본 97쪽 구성과 79쪽 한 면 결정문을 바꾸지 않았다. 통계 재검수와 재시뮬레이션, 전권 contact sheet, 외부 모집이나 전송도 진행하지 않았다.

저장소 루트에서 다음 명령으로 항목 구조, 분류 일관성, 인용의 현재 원고 일치와 보호 파일 해시를 확인할 수 있다. 이는 판단 자체를 자동으로 증명하는 검사가 아니라 AI가 읽고 판정한 내용의 근거 무결성 검사다.

```bash
python e-book/maintenance/ai_crm_review/VERIFY.py
```

사람의 직접 수행, 실무자 검수, 실제 현장 동의 적법성 및 운영 가능성, 고객 성과와 학습 효용은 이번 검토로 입증하지 않았다. 사람 검수 미실시 상태는 유지하지만 이를 비공개 자료 관리의 진행 장애로 삼지 않는다.

## 이후에 다시 여는 조건

구체적인 오류나 읽기 장애가 실제로 보고되면 위치와 재현 근거를 기존 오류 기록에 남긴다. 확인된 문제만 최소 수정하고 영향을 받은 검사만 다시 실행한다. 숫자와 원자료 또는 가정이 바뀌었으면 기존 검증을 그대로 재사용하지 않고 해당 근거를 다시 확인한다. 새 장과 사례, 이론과 기능 개발 및 같은 범위의 반복 검수를 자동으로 시작하지 않는다.

검토 단계에서는 이 자료와 관리 상태를 로컬에 저장했고 GitHub 커밋과 푸시는 하지 않았다. 이후 사용자의 별도 동기화 요청에 따라 GitHub에 반영한다. 기존 원고, 원자료, 지난 판과 검수 기록은 보존한다.
