# TRI-V 실전 정리 v0.3

이번 개정은 새 축과 이름을 늘리지 않고 실행 후보로 넘길 때, 추가 근거가 필요할 때, 보호 대응을 먼저 할 때를 구분한다. PDCA와 TRI-V는 A/B 판단 틀로 유지하며 PDCA의 병행 확장은 하지 않는다.

## 먼저 볼 것

- `MINIMUM_RECORD.pdf`: A4 한 장의 인쇄용 빈 양식. 입력형 PDF는 아님.
- `MINIMUM_RECORD.html`: 브라우저에서 여섯 칸을 입력하고 인쇄할 수 있는 오프라인 양식. 서버 전송과 자동 저장은 하지 않음.
- `MINIMUM_RECORD.md`: 편집 가능한 최소 기록과 필요한 경우에만 여는 상세 기준.
- `MINIMUM_RECORD_WORKED.md`: 실행 후보 사례에 최소 기록을 실제 적용해 작성한 개발 예시. 사람의 사용성을 측정한 응답이 아님.
- `COUNTEREXAMPLES.md`: 실행 후보, 사전 집단의 실행 후보, 추가 정보, 보호 우선 검토로 나뉘는 반례와 계산.
- `EXPERIENCE_AND_ACCEPTANCE.md`: 제공 이미지의 경험에서 추출한 반드시 확인할 것, 멈출 조건과 실제 효용 관찰 기준.
- `SOURCE_EVIDENCE.md`: CRM LOOP와 Aurora의 원 프로젝트 문서 발췌와 blob SHA를 대조한 근거표. MC 원문은 이번에 특정하지 못해 이미지와 저자 진술로 구분한다.
- `e-book/manuscript/tri_v_author_origin_v03.md`: 저자 경험을 반영한 1인칭 서사 개정 초안. 최종 표현 승인과 전체 본책 적용은 별도.

## 이번에 확인한 것과 확인하지 않은 것

교육용 카운트를 구성해 기존 Newcombe 위험차 구간과 score 보호 비열등성 계산을 실행했다. 수동 Wilson 조합과 Newcombe 구간을 대조했고 보호 검정과 대응 단측 상한의 일관성을 확인했다. 사전 두 집단의 적용 주장에는 Bonferroni로 각 alpha .025를 사용하고 각 집단의 성과와 보호를 함께 요구한다. 같은 대상 안에서 적절한 확증 근거가 있는 집단을 새로 검증하라고 무조건 요구하지 않는다.

반례의 관측 기간, 대비, 무작위 배정과 독립 및 비간섭, 성숙한 측정, 사업 및 보호 기준은 교육용 설정이다. 실제 회사의 사전등록과 검정력 설계를 완료한 결과가 아니며 실제 승인을 내리지 않았다. 긍정 반례를 만들기 위해 기존 쿠폰 자료를 고치거나 유의성이 나올 때까지 시드를 돌리지 않았다. 명시적으로 설계한 고정 카운트를 별도 파일로 공개한다.

이미지와 저자 진술은 경험과 검토 기준의 출처다. 군 대안 비교를 당시의 무작위 A/B라고 부르거나, 원 프로젝트에 처음부터 TRI-V라는 이름을 사용했다고 추정하지 않는다. 프로젝트의 문서와 코드가 확인되면 그 범위의 구현과 기록 근거로 구분한다. 이번 작업에서 실제 조직의 누락 감소, 시간 절감이나 TRI-V의 비교 우월성을 측정한 것은 아니다.

## 양식을 줄이는 원칙

여섯 항목만 새로 기록하고 실험 명세와 분석 결과는 기존 링크를 재사용한다. 원래 명세가 없으면 최소 양식으로 누락을 덮지 않고 먼저 보완한다. 측정 결함, 적용 변화, 선택을 바꾸는 비용 및 용량, 필요한 보호와 승인 근거가 없을 때만 상세 기록을 연다. 모든 실험에 세분화, 금전 모델이나 새 실험을 강요하지 않는다.

## 도식과 양식 표현의 이유

입력 순서와 검토 순서를 맞춰 기존 자료의 재작성을 줄이도록 했다.
실행 후보와 실제 승인을 분리해 근거 충족이 자동 시행으로 보이지 않게 했다.
대비가 계산된 색과 인쇄 12pt 이상을 사용하고 한 장을 유지했다.

## 재현

프로젝트 루트에서 실행한다. Python과 uv, 필요한 패키지 및 설치 Chrome이 필요하다.

```sh
uv run --with statsmodels --with scipy --with playwright --with pymupdf python scripts/build_tri_v_refinement_v03.py
```

`counterexample_fixture.json`은 입력, `COUNTEREXAMPLE_RESULTS.json`은 계산, `VALIDATION.json`은 양식의 브라우저 입력, 키보드, 가로 넘침, PDF 한 장과 실제 글자 크기 검사다. 기술 검사가 실제 사람의 작업 부담 감소나 전체 접근성을 보증하지 않는다.

이 자료는 기존 v0.2 상세 양식과 조건변형, v0.10 본책과 원자료를 보존하는 실무 보완편이다. 새로운 전체 읽기본이나 출간 승인본으로 표시하지 않는다. 완성 답안이 있는 저자 검토 자료이므로 실제 참여자 시험에 전체 묶음을 그대로 주지 않는다.
