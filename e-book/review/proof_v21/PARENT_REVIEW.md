# v0.21 부모 검수: 부록과 작성 양식

## 범위

용어 해설 36개, 참고자료와 계산 범위 및 부록 A/B를 읽었다. 원고의 백틱 경로 중 실제 e-book/ 또는 scripts/로 시작하는 파일 참조를 현재 작업 사본에서 확인했다. 작성 양식에는 개인 정보가 아닌 시험 문구를 넣어 인쇄 렌더링과 텍스트 다운로드를 비교했다. 이는 실제 독자시험이나 원자료 통계 재감사가 아니며, 외부 출처 및 PDF 인용 전수 대조도 아니다. 원고와 PDF 및 웹 읽기본, 작성 양식은 변경하지 않았다.

## 확인된 읽기 장애

### P1. 부록의 보호 계산 설명이 존재하지 않는 아래 값을 가리킨다

- 위치: ebook_review_v21.md 1339행, 부록 A의 8장 보호.
- 원문 일부: `아래 반올림 표시와 실행 후보 판단은 바뀌지 않았다. 아래 값은 철회율 B-A의 상한이며`
- 관찰: 이 문단 아래는 10장 대안 설계 설명이다. 철회 상한을 제시한 8장의 표는 이 부록 아래에 없다. 본문에서 문단을 이동하면서 상대 위치 표현이 남았다.
- 분류: 확정된 참조 오류, 통계 수치 오류는 아님.
- 최소 수정: `8장의 반올림 표시와 실행 후보 판단은 바뀌지 않았다. 8장 표의 값은 철회율 B-A의 상한이며`처럼 실제 위치를 명시한다.

### P2. 부록 SQL 설명의 다음 표는 결과 집계표가 아니다

- 위치: 같은 원고 1351행, 부록 A의 12장 자료 구현.
- 원문 일부: `기존 DB를 읽기 전용으로 열어 배정과 완료, 철회, 계약 합계를 다음 표와 대조했다.`
- 관찰: 이어지는 표는 자료 경로 목록이며, SQL 뒤에도 A/B/H 사건 수 집계표가 없다. 실제 집계표는 12장에 있다. 아래 SQL 자체는 부록 뒤에 실제로 있으므로 SQL이 없다는 지적은 하지 않는다.
- 분류: 확정된 참조 오류, 집계 결과 오류는 아님.
- 최소 수정: `다음 표`를 `12장의 집계표`로 바꾼다.

## 재현된 작성 양식 오류

### P3. 긴 입력이 현재 입력 인쇄에서 잘린다

- 대상: e-book/exports/v21/MINIMUM_RECORD.html의 기존 현재 입력 인쇄 동작과 print CSS.
- 재현: 여섯 칸마다 번호가 다른 12줄과 종료 표지 한 줄을 입력하고 Chrome의 인쇄 CSS를 적용해 PDF로 렌더했다. 모두 비개인 시험 문구다.
- 실제 결과: 입력 칸은 13줄이지만 인쇄에는 각 칸의 11, 12번째 줄과 종료 표지만 남았다. 인쇄용 textarea 높이는 고정 15mm이고 실제 내용 높이보다 작았다. 입력 후 스크롤 위치에 따라 잘리는 부분은 달라질 수 있다.
- 대조: 같은 입력의 텍스트 파일 다운로드에는 모든 번호 줄과 종료 표지가 들어 있었다. 파일 저장 기능의 누락으로 확대 해석하지 않는다.
- 분류: 확정된 기존 인쇄 기능 오류. 빈 양식 PDF의 한 쪽 검사는 긴 입력 보존을 검증하지 못한다.
- 최소 수정: 인쇄할 때만 입력값을 높이 제한 없는 일반 텍스트로 출력한다. 긴 기록이 여러 쪽이 되는 것은 허용하고 전체 내용을 보존한다. 기본 화면과 빈 한 장 양식, 복사와 파일 내보내기는 바꾸지 않는다.
- 증거: PARENT_CHECKS.json. 시험용 인쇄 PDF와 이미지는 프로필 scratch에만 보관했다.

## 문제로 잡지 않은 사항

- 이번 확인에서 원고에 명시된 백틱 파일 경로의 누락은 없었다.
- 용어 해설에서 즉시 확정할 통계 개념 오류는 찾지 못했다. 모든 통계가 무오류라는 보장은 아니다.
- 확대와 복사, 파일 저장의 존재를 새로 보완해야 할 사항으로 되돌리지 않았다.
- 실제 독자가 겪은 문제는 아직 수집하지 않았다. P1/P2는 원고의 실제 지시 위치 불일치이며 P3는 브라우저로 재현한 오류다.

이 파일은 검수 결과만 기록한 것으로, 수정 적용 보고가 아니다. BASELINE.json에 고정한 원고/PDF/웹/양식 네 파일의 해시는 검사 뒤에도 같았다.
