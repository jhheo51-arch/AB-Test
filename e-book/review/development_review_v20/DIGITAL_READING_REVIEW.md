# v20 디지털 읽기와 작성 흐름의 추가 검토

## 실제 확인 범위

v20 웹 읽기본과 작성 양식을 Chrome에서 열었다. 웹 읽기본은 1200px와 390px 화면에서 실제 글자 크기와 그림 크기를 측정했고, 작은 화면의 완료 효과 그림을 캡처해 확인했다. 작성 양식은 빈 테스트 페이지에 비개인 시험 문구를 입력한 뒤 새로고침했다. 실제 독자의 사용성 시험이나 전자책 전체 접근성 인증은 아니다. 본문과 PDF는 변경하지 않았다.

## 1. 모바일에서 그림이 작아지는 문제

- 이미 있음: 웹 읽기본은 390px에서 가로 넘침이 없고 본문은 16px로 표시된다. 원래 PDF에서는 그림 라벨의 인쇄 크기도 검사했다.
- 관찰: 같은 모바일 화면에서 그림 너비가 354px로 줄며 일부 정량 그림의 가장 작은 텍스트는 실제 화면 환산 약 9.83px다. 실제 캡처에서도 큰 제목보다 축과 조건 문구를 읽는 데 부담이 있다. 가로 넘침이 없다는 사실과 읽기 쉬움은 다르다.
- 제안: 그림을 누르면 원래 크기로 확대해 읽게 하고, 돌아오면 읽던 위치를 유지한다. 기존 수치 표와 해석을 가까이 연결한다. 모든 모바일 라벨을 억지로 한 화면에 넣거나 기존 정보를 삭제하는 방식은 피한다.
- 덜어낼 것: 새 그림이나 설명을 추가하기보다 기존 벡터 그림의 읽기 동작을 보완한다.
- 경계: 이 크기만으로 WCAG 위반이라고 단정하지 않는다. 작은 글자 문제는 대비 계산이나 인쇄판 크기 검사를 통과했다고 사라지지 않는다.

## 2. 작성한 판단문을 가져가는 흐름

- 이미 있음: 여섯 항목을 직접 작성하고 현재 입력을 인쇄하는 버튼이 있다. 자동 저장하지 않는다는 안내도 기존 묶음에 있다.
- 관찰: 현재 양식의 조작 버튼은 인쇄 하나다. 비개인 시험 문구를 넣고 새로고침했을 때 입력이 사라졌다.
- 제안: 현재 입력을 로컬 텍스트로 내려받거나 명시적으로 복사하는 동작, 다시 불러오는 경로를 검토한다. 자동 저장이나 클라우드 동기화를 기본으로 켜 개인정보 위험을 늘리지 않는다. 기록의 버전과 미승인 상태도 함께 가져갈 수 있게 한다.
- 덜어낼 것: 새 양식이나 필수 기록 칸을 늘리는 대신 기존 여섯 항목의 작성 결과를 보존하는 동작에 집중한다.

## 수정 전후의 제안 범위

| 항목 | 현재 관찰 | 다음 보완 제안 |
|---|---|---|
| 모바일 본문 | 16px | 유지하며 실기기 읽기 확인 |
| 모바일 그림의 최소 텍스트 | 일부 약 9.83px | 기본 보기의 정보량은 유지하고 원본 확대 제공 |
| 그림 읽기 동작 | 축소된 그림을 본문에서 읽음 | 확대와 읽던 위치 복귀 |
| 기록 보존 | 현재 입력 인쇄, 새로고침 시 시험 입력 소실 | 명시적 복사 및 로컬 내보내기 검토 |

측정값은 READING_INTERFACE_CHECK.json에 저장했다. 실제 입력 내용이나 고객 자료는 사용하지 않았다. 이번 요청은 추가 보완점 검토이므로 이 동작은 아직 구현하지 않았다. 전권 contact sheet 재생성이나 이전에 차단된 PDF 인용 전수 검사는 하지 않았다.
