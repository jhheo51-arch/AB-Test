# B가 이겼다는 말을 검증하는 법

## 승리에는 서로 다른 문턱이 있다

회의에서 “B가 이겼습니다”라고 말하면 먼저 어느 문턱을 넘었다는 뜻인지 밝혀야 한다. 관측한 점추정이 높다는 뜻인지, 사전에 정한 검정 기준을 통과했다는 뜻인지, 사업적으로 의미 있는 개선인지, 고객과 운영의 위험까지 고려해 채택할 수 있다는 뜻인지는 다르다. 이 구분을 하지 않으면 예약에서의 개선이 차량 매출의 승리로 바뀌고, 클릭에서의 유의성이 고객 관계의 성공으로 확대된다.

첫 문턱은 유효성이다. 배정과 측정이 비교를 지지해야 한다. 두 번째는 통계적 근거다. 효과와 구간, 분석 가정, 반복 조회와 다중성을 검토한다. 세 번째는 사업적 의미다. 비용과 최소 관심 효과를 고려한다. 네 번째는 채택 가능성이다. 동의·안전·관계·운영·적용 범위와 승인 조건을 확인한다. 각 문턱은 다른 증거를 요구한다.

이 책은 다음 형식으로 말하는 것을 권한다. “배정 고객 전체의 28일 시승 완료율을 주지표로 보았을 때, B-A 차이는 얼마였고 구간은 어디까지였다. 예약에서는 어떤 신호가 있었지만 수신 거부와 이익에는 어떤 한계가 남아 있다. 따라서 지금의 권고는 무엇이며, 어떤 조건에서 재평가한다.” 숫자는 그때 결정 문장의 일부가 된다.

## 지표 계약을 만들기

‘전환율’이라는 이름 대신 지표 계약을 만든다. 이름, 역할, 분자, 분모, 관측 시작과 종료, 데이터 원천, 유일성, 취소·반품, 누락 처리, 좋은 방향, 갱신 지연을 적는다. 시승 완료를 예약 수로 나누면 예약 후 실행의 문제를 본다. 배정 수로 나누면 발송 정책 전체가 실제 완료를 얼마나 만들었는지 본다. 둘 다 유용할 수 있지만 같은 인과 질문은 아니다.

지표 역할은 결과 전에 정한다. 주지표가 불리하게 나오자 클릭을 주지표로 바꾸는 것은 결과 선택이다. 여러 주지표가 필요하면 공동 성공 기준과 다중성 계획을 정해야 한다. 가드레일도 ‘p가 크니 안전’이라는 식으로 쓰지 않는다. 허용 손실과 구간을 함께 볼 설계가 필요하다.

## 같은 말로 설명해도 서로 다른 질문

‘누가 더 많이 샀나’는 구매 건수의 질문이다. ‘보냈기 때문에 더 샀나’는 대조 정책과의 증분 효과 질문이다. ‘회사가 더 이익을 얻었나’는 비용·잠식·관측 기간까지 필요한 질문이다. ‘장기적으로 고객 관계가 좋아졌나’는 유지·불만·신뢰와 충분한 추적이 필요한 질문이다. 각 질문에 맞는 데이터가 없으면 다음 질문으로 점프하지 않는다.

OEM에서는 예약, 시승, 상담, 계약, 금융 승인, 출고를 한 이벤트처럼 다루지 않는다. 판매 접점의 원장과 고객 ID 연결이 필요하고, 단계별 지연도 다르다. 계약은 존재하나 출고 전인 고객은 매출이 관측되지 않은 상태일 수 있다. 이를 영구적인 무구매나 누락과 혼동하면 판단이 달라진다.

## 분석 범위와 방법

아래 결과는 JH Motors의 고정 시드 합성 자료를 사후 교육 분석한 것이다. 실제 사전등록 실험이 아니므로, 결과를 본 뒤의 분석을 실제 현장 확증 실험처럼 포장하지 않는다. 주지표는 교육용 명세의 28일 시승 완료, 예약은 진단, 수신 거부는 가드레일로 읽는다.

고객 단위의 독립된 이항 표본을 가정해 두 비율의 양측 pooled z 검정을 수행했다. 차이의 95% 구간은 Wilson 구간을 조합한 Newcombe 방법을 사용했다. 검정과 구간은 서로 다른 근사 절차이며, 둘의 경계가 항상 일치하는 것은 아니다. 이번 표는 지표별 미보정 결과다. 여러 지표에 대한 동시 신뢰구간이나 반복 조회 보정 결과가 아니다.

자체 구현과 statsmodels의 검정·구간 결과를 수치 대조했고, 집계 뷰와 원본 이벤트의 유일 고객 집계도 대조했다. 이는 계산 구현과 집계의 확인이지 실제 기업에서 방법론의 성과를 입증하는 검증은 아니다.

## 한 장 보고서 예시

**결정 질문:** 기존 차량 가치 안내 A 대신 시승 편의 안내 B를 확대할 근거가 충분한가?

**대상·기간:** 연락 동의가 있고 기존 시승 이력이 없는 합성 잠재 고객. 배정 기준으로 28일을 관측했다. 전달 실패도 주 분석 분모에 포함한다.

**결과:** 예약에서는 증가 신호가 있으나 주지표인 시승 완료의 구간은 손실과 개선을 모두 포함한다. 수신 거부의 비유의성은 안전을 보장하지 않는다.

**알 수 없는 것:** 실제 차량 매출·원가·계약·LTV, 현장 수용량과 장기 관계. 이 자료에는 무발송 대조군도 없다.

**권고:** ‘B 승리·전면 확대’로 보고하지 않는다. 시승 완료의 사업 최소 효과와 관계 가드레일, 슬롯·노쇼·측정 경로를 정리해 후속 실험을 설계한다. 현재 실험을 유의할 때까지 임의 연장하는 것과는 구분한다.

**재개 조건:** 운영 담당자가 예약-완료 원장을 대조하고, 사업 담당자가 최소 효과와 비용을, 분석 담당자가 표본·종료·다중성 설계를, 고객 보호 담당자가 허용 위험을 확인한 뒤 새 판단 기록을 만든다.

# 표본과 종료 · ‘더 모으면 되죠’가 답이 아닌 이유

## 효과의 크기는 결정과 연결된다

표본 수는 과거 전환율, 검출하려는 효과, 유의수준, 검정력, 배정 비율과 설계에 따라 달라진다. 작은 차이를 구분하려면 더 많은 정보가 필요하다. 사업적으로 무의미한 차이를 검출하기 위해 긴 실험을 운영하면 기회비용이 커지고, 중요한 차이를 구분할 수 없는 설계로 시작하면 불확실한 결과가 남는다.

이 예는 기존 데이터를 정당화하기 위해 뒤늦게 붙인 표본 계획이 아니다. 향후 별도의 실험을 설계할 때의 독립된 계산 예다. 가구·지점 군집, 이탈, 여러 대비, 비열등성, 적응 배정, 희귀 결과는 별도 설계가 필요하다.

## 언제 볼 것인가를 먼저 정한다

정해진 표본 또는 기간에 한 번 주 분석을 하는 설계와, 중간에 유효하게 판단하도록 계획한 순차 설계는 다르다. 고정 종료 검정의 p-value를 매일 보다가 유리한 순간 종료하면 원래의 오류 해석을 유지하기 어렵다. 안전·품질 감시는 필요하지만 그 감시와 효능 조기 종료의 규칙을 구분한다.

결과가 불확실하다고 무조건 더 수집하지도 않는다. 추가 정보로 실제 결정이 바뀔 가능성, 비용, 고객 위험, 기회비용을 고려한다. 선택적으로 기간을 늘리지 않고, 미리 정한 규칙을 따르거나 새로운 계획을 명시한 후속 실험으로 넘어간다.

# 반론을 증거 요청으로 바꾸기

다음 질문은 실제 인터뷰 인용이 아니라, 실험 담당자가 준비할 수 있도록 구성한 회의 시뮬레이션이다. 질문자를 이기는 기술이 아니라 결론의 범위를 정확히 말하는 연습이다.

## 목표·지표에 대한 반론

**“B가 이겼다는 게 클릭인가, 계약인가?”**
주지표의 역할과 정의를 먼저 보여준다. 클릭의 개선은 클릭에서의 관측이며 계약이나 이익의 개선으로 바뀌지 않는다. 주지표가 불확실하다면 그 상태를 결론에 남긴다.

**“왜 매출이 아니라 시승을 목표로 잡았나?”**
짧은 운영 기간의 시승 정책 질문이라면 시승 완료가 적합할 수 있다. 다만 판매의 대리지표로 장기 성과를 확정하지 않고, 계약·출고를 후속 추적한다. 주지표를 선택한 이유와 답하지 못하는 질문을 함께 설명한다.

**“원래 주지표가 안 좋으니 다른 지표를 가져온 것 아닌가?”**
버전과 작성 시점이 남은 실험 계약서를 제시한다. 사전 명세가 없었다면 없다고 말하고 분석을 탐색적 성격으로 낮춘다. 사후 기록을 사전등록처럼 꾸미지 않는다.

**“상대 개선율만 크게 보여준 것 아닌가?”**
절대 차이를 퍼센트포인트로, 상대 차이를 퍼센트로 구분해 함께 쓴다. 원래 비율과 분모도 보여준다. 두 표현이 같은 숫자를 다르게 부르는 것처럼 섞이지 않게 한다.

## 비교·측정에 대한 반론

**“B에 구매할 고객이 더 들어간 것 아닌가?”**
배정 코드·확률·대상과 사전 속성을 보여준다. 우연한 불균형과 수동 타기팅을 구분한다. 속성 차이가 조금 있다는 이유만으로 임의 제외하거나, 무작위라는 이름만으로 실행 확인을 생략하지 않는다.

**“실제 받은 사람만 봐야 하는 것 아닌가?”**
알고 싶은 효과가 배정 정책의 효과인지 노출 효과인지 확인한다. 전달 성공은 처치 이후 변수일 수 있다. 주 분석의 배정 기준을 유지하고 전달 문제는 별도 진단한다. 노출자 비교로 인과 효과를 자동 대체하지 않는다.

**“딜러가 기록을 덜 한 것 아닌가?”**
군별 ID 연결률·지연·원본 예약과 방문 원장을 대조한다. 외래키 검사 통과와 이벤트 완전성은 별개다. 원장도 없다면 누락을 배제할 수 없다고 말한다.

**“경쟁사 출시나 주말 효과 아닌가?”**
동시에 배정됐는지, 충격이 양 군에 어떻게 작용했는지, 처치 버전이 달라졌는지 확인한다. 공통 외부 충격이 언제나 무작위화를 무효화하는 것은 아니지만 적용 범위와 시간 변화의 한계는 남는다.

## 통계·탐색에 대한 반론

**“p가 0.05보다 크니 효과가 없는 것 아닌가?”**
구간에 어떤 사업적 개선과 손실이 포함되는지 보여준다. 유의하지 않음과 동등성의 근거를 구분한다. p-value 하나로 무효과나 안전을 확정하지 않는다.

**“오늘 유의해졌는데 왜 더 기다리나?”**
사전 종료와 중간 분석 규칙을 확인한다. 유리한 순간을 골라 종료하는 분석이면 결과의 선택 편향을 밝힌다. 반복 조회를 허용하는 검증된 설계를 즉석에서 소급 적용했다고 주장하지 않는다.

**“스무 개 지표 중 하나만 좋아진 것 아닌가?”**
주 대비, 지표 위계, 비교 가족과 탐색 이력을 제시한다. 여러 지표를 보고 선택한 승리를 단일 검정처럼 소개하지 않는다. 적절한 다중성 처리 또는 독립적인 후속 검증을 계획한다.

**“신규 고객에게만 보내면 되는 것 아닌가?”**
사전 정의와 집단 간 효과 차이의 근거를 확인한다. 한 집단 유의·다른 집단 비유의만으로 차이를 말할 수 없다. 사후 발견이라면 새 가설로 검증한다.

## 가치·관계에 대한 반론

**“매출이 늘었는데 왜 이익이 줄었나?”**
할인, 원가, 취소, 반품, 상담·시승·발송 비용과 상품 구성을 나눠 본다. 매출 지표가 비용을 포함하지 않는다는 사실을 숨기지 않는다. 배정 고객당 순기여이익의 정의와 민감도를 제시한다.

**“수신 거부는 유의하지 않으니 무시해도 되나?”**
허용 위험과 구간을 함께 봐야 한다. 검정력 부족 때문에 위험을 못 찾았을 수도 있다. 사전 가드레일 한계가 없으면 안전 판정을 새로 만든 척하지 않는다.

**“시승이 늘면 차도 더 팔리지 않나?”**
가능한 경로와 관측된 성과를 구분한다. 계약·금융 승인·출고·이익으로 이어지는 자료가 없으면 확정 매출로 환산하지 않는다. 추정 시나리오는 가정과 범위를 붙여 별도로 제시한다.

**“전국에 적용하면 숫자를 그대로 곱하면 되나?”**
지점 수용량, 재고, 고객 구성, 인력과 공유 자원 때문에 한계 효과가 달라질 수 있다. 작은 실험의 결과를 전면 도입 규모로 단순 외삽하지 않고 단계 확대와 롤백을 설계한다.

## 실행·책임에 대한 반론

**“담당자가 좋은 안을 이미 양 군에 쓰고 있었다면?”**
배정과 실제 실행의 차이를 기록한다. 프로토콜 이탈을 숨기지 않고 어떤 정책 대비가 남아 있는지 평가한다. 운영 로그를 고치거나 새 실행 조건의 실험이 필요할 수 있다.

**“개인정보 동의가 없는 고객을 넣은 것 아닌가?”**
기준 시점 자격과 철회 반영을 확인한다. 해당 연락을 제한하고 사내 절차와 담당 검토로 연결한다. 통계적 성과가 동의 위반을 상쇄하지 않는다.

**“다른 실험과 겹쳤으니 전부 무효 아닌가?”**
공동 배정 구조와 상호작용, 공유 자원을 확인한다. 독립 교차배정이 유효할 수도 있다. 참여 중복이라는 사실만으로 무효라 하지 않고 실제 비교를 검토한다.

**“결국 모르겠다는 말인가?”**
이미 아는 것, 모르는 것, 판단을 바꿀 증거를 구분해 답한다. 보류는 무책임한 결론이 아니라 책임자·자료·재개 조건이 붙은 작업 상태여야 한다.

# 방법 부록 · 계산과 재현의 경계

두 군의 비율 차이는 B의 사건 수/배정 수에서 A의 사건 수/배정 수를 뺀다. pooled z 검정은 귀무가설 아래 공통 비율로 표준오차를 계산한다. Newcombe 구간은 각 군의 Wilson 구간을 결합한다. 분석 코드는 원본 SQL 집계, 자체 수식, statsmodels 결과를 대조하고 실패하면 중단하도록 만들었다.

실행 명령은 저장소 루트에서 `uv run --with scipy --with statsmodels scripts/analyze_ebook_cases.py`이다. 결과는 `e-book/analysis/v02/verified_analysis.json`과 `metric_results.csv`에 저장한다. 데이터와 생성 시드, 관측 창은 기존 명세를 따른다. 분석 라이브러리·런타임 버전도 별도 기록한다.

자료를 확보하는 것, 구현을 대조하는 것, 연구 가정이 성립하는 것, 실제 기업에서 효과가 있는 것, 독자가 잘 사용하는 것은 서로 다른 검증이다. 이 책에서 완료했다고 표시하는 검증은 구체적인 파일과 검사 범위에만 적용한다.
