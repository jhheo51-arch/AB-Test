# 필수 독해와 분석 구현의 분리 장부

## 평가 범위

이 장부는 v18 본문을 바꾸지 않은 v19 적용 제안이다. 비전공 CRM 마케터가 결과를 읽고 명세와 보고문을 고치는 경로와 분석 담당자가 계산 방법을 선택하고 구현을 검토하는 경로를 분리했다. 최신 PERSONA_MARKETER의 필수 독해 층위화와 PERSONA_ANALYST의 계산 선택 책임 분리 의견을 반영한 편집 판단이며 실제 독자 수행이나 통계 재검증 결과는 아니다.

제목 '그래서, 이 캠페인 계속할까요?'와 CRM A/B 테스트 실무 장르 및 TRI-V 부제의 승인 범위는 건드리지 않는다. 세 축과 여섯 항목은 그대로 두며 새 단계나 승인 기록을 만들지 않는다. 다른 작성자와 충돌을 피하도록 1장, 9장, 11장은 선택하지 않았다.

## 적용과 부록 배치

JSON 최상위는 목록이다. 각 before는 v18의 독립 문단 전체이며 원문에 한 번만 나온다. 부모 편집자는 before를 after로 한 번씩 교체하고, 선택한 before를 글자 변경 없이 부록 A의 새 '분석 담당자와 확인할 계산 방법' 절에 보존한다. 절 앵커는 analysis-method-notes를 사용한다. 본 장부는 원고에 절이나 앵커를 직접 추가하지 않는다.

부록에서는 appendix_group별로 원고 순서를 유지한다. 5장 통계는 구간과 검정 계산의 차이, 6장 정보량은 계획값의 구현 대조, 7장 고객군 통계는 층화 분산, 8장 보호는 상한 계산과 교정 이력, 10장 대안 설계는 요건 개요, 12장 자료 구현은 SQL 실행 범위와 버전 교정을 묶는다. 옮기는 단위는 원문 문단 전체다. 원문 중 독해 조건이 부록에 다시 나타나는 것은 기술 내용 보존을 위한 의도된 중복이다.

12장의 SQL 코드, 경로와 필드명이 포함된 자료 안내 문단, 집계 표는 그대로 둔다. SQL 인접 안내만 선택 읽기로 바꾸므로 실제 코드 이동을 완료한 것으로 세지 않는다. 10장의 밴딧과 DID에서도 필수 가정을 본문에 남겨 축약 폭이 제한적이다. 부록의 요건 개요는 해당 방법의 완결 구현이나 검증을 제공한다는 약속이 아니다.

## 문단별 배치 이유

- 5장, v18 원고 244행, 5장 통계: 구간 폭의 직관은 본문에 두고 Wilson 경계 결합과 실제 보고 방법의 대조는 부록에 보존한다.
- 5장, v18 원고 250행, 5장 통계: 귀무가설과 양측 확률의 조건은 본문에 남기고 pooled 표준오차의 구성과 표준화 계산을 부록으로 분리한다.
- 5장, v18 원고 265행, 5장 통계: 방법명 암기 대신 자료 구조에 대한 확인을 독자의 작업으로 남기고 근사 절차 사이의 기술 대조는 부록에서 읽게 한다.
- 6장, v18 원고 317행, 6장 정보량: 후속 설계 선택에 필요한 모든 계획값과 근사 조건은 본문에 두고 구현 교차 대조만 부록으로 이동한다.
- 7장, v18 원고 557행, 7장 고객군 통계: 표적 구성과 주분석 및 참고분석의 지위는 유지하고 가중치 제곱을 이용한 분산 조합과 코드 대조를 부록으로 분리한다.
- 8장, v18 원고 671행, 8장 보호: 보호 방향과 상한을 읽는 동작은 본문에 남기고 제약우도와 score 및 MN 보정, 구현 불일치 교정 이력은 원문 그대로 부록에 보존한다.
- 10장, v18 원고 768행, 10장 대안 설계: 정보량과 적응 배정의 추론 경계는 본문에 유지하고 배정 확률 기록 등 직접 설계할 요건을 부록의 담당자 확인 대상으로 분리한다.
- 10장, v18 원고 770행, 10장 대안 설계: 기록 재사용 장의 필수 독해는 질문과 정밀도의 구분으로 좁히고 균형과 모형 아래 셀 정보를 합치는 설계 설명은 선택 경로로 옮긴다.
- 10장, v18 원고 776행, 10장 대안 설계: 무작위 배정의 대체 보장이 아니라는 해석 조건과 반대 설명은 본문에 남기고 차분 계산의 구조 및 점검 요건의 원문은 부록에서 확인하게 한다.
- 12장, v18 원고 873행, 12장 자료 구현: 코드나 표는 건드리지 않고 SQL 직접 실행을 선택 읽기로 표시한다. 표 대조와 통계 재실행의 차이 및 뷰 정의 확인 책임은 유지한다.
- 12장, v18 원고 892행, 12장 자료 구현: 재사용 전에 알아야 할 시간 경계와 집계 불변의 제한은 본문에 남기고 버전별 구현 결함 및 교정 검사 원문은 부록으로 분리한다.

## 본문에 남기는 가드 조건

- 효과의 핵심값, 분모, 비교 대상과 신뢰수준은 독해 대상이다. 구간과 p값의 질문이 다르다는 점, 자료 구조와 계산 가정의 일치 여부도 본문에서 확인한다. 5장 가족 보정 문단과 7장 결과 문단은 변경하지 않는다.
- 6장의 현재 검정력과 목표 검정력, 추가 모집 수와 MDE는 모두 본문에 남긴다. 계획값은 관측 효과나 발견 보장이 아니며 주지표 계획이 보호 정보량의 충족을 뜻하지 않는다는 인접 문단도 유지한다.
- 8장의 허용 악화 한계와 완료 기준, 표에 적힌 구간 및 단측 상한의 수준, 두 사전 적용 주장의 비교 가족 설명은 그대로다. 비유의를 안전으로 읽지 않으며 MN 구현 교정 원문은 부록에 온전히 남긴다. 실행 후보와 실제 승인의 구분도 바꾸지 않는다.
- 사전 기준과 사후 교육용 민감도 가정은 섞지 않는다. 5장 및 12장의 사업 기준과 보호 한계 설명은 선택 대상이 아니다. 고객 권리와 중대한 피해 대응 의무도 삭제하거나 부록 링크 뒤로 미루지 않는다.
- 밴딧의 적응 배정과 불확실성 평가, DID의 평행 추세와 반대 설명은 방법 이름만 남기는 식으로 축약하지 않는다. 결과를 읽는 사람도 별도 분석 요건이 필요함을 본문에서 알 수 있어야 한다.
- 자료 교정 전후 집계가 같은 것은 현재 합성 자료에 한정된다. 시간 경계와 다른 자료 재사용 때의 확인은 본문에 남기며 집계 대조를 통계 전체 재실행이나 현장 타당성 인증으로 바꾸지 않는다.

## 기계 검사와 한계

- 대상 원고 SHA-256: `a272c2ecb367a382566b510a264f4254d8e1a3c1b3054abb2cb1909a76ea934d`. 생성 전후 동일함을 검사한다.
- 선택 문단 11개: 실제 before 단일 출현, 빈 줄 경계의 독립 문단, 선택 간 포함 및 중첩 없음, 순차 교체 재생 성공.
- 선택 문단에는 노트, span, HTML, 코드, 표, 그림, 제목, 앵커가 없다. 인라인 코드 문단도 선택하지 않았다.
- after의 숫자 문자열을 before의 숫자 문자열 다중집합과 대조해 새 숫자 표기가 없음을 검사했다. 부호와 단위가 있는 계획값은 원문 문맥과 함께 수동 대조했다. 모든 선택 before를 부록 이동 원문으로 완전히 보존하므로 숫자 출현 총량의 동일성은 요구하지 않았다.
- JSON의 before, after, reason, appendix_group에서 중점 문자 여섯 종(U+00B7, U+318D, U+2022, U+2027, U+2219, U+22C5)이 없는지 검사했다. 이 설명 파일도 같은 금지 문자를 쓰지 않는다.
- 세 축과 여섯 항목의 정의 및 해당 구조를 바꾸는 편집은 없다. 원고와 원자료 및 기존 파일은 수정하지 않는다. 실제 원고 적용 후의 링크 해석, 페이지 배치, 전권 통계 의미 감사와 독자 수행 검증은 부모 편집 및 후속 검수 범위다.
