# v20 승인 범위와 편집 순서

저자의 요청은 ‘반복 설명 압축 → 2~4장의 같은 기록 연속 수정 → 기존 연습의 판단 전이 강화 순으로 진행’이다.

빌더는 v19 원고를 기준으로 다음 장부를 순서대로 재생한다. 뒤 단계를 먼저 적용하지 않으며 각 교체의 원문이 그 시점에서 정확히 한 번 존재해야 한다.

1. 01_COMPRESSION.json: 이미 앞에서 배운 정의의 반복을 압축하고, 뒤에서는 명세와 판단을 고치는 데 사용한다. 독립적으로 읽는 완성 결정문과 각 결과의 가정 및 보호 조건은 유지한다.
2. 02_GUIDED_RECORD.json: 2장부터 4장까지 같은 JH Motors 설계 메모를 이어 고친다. 비교 명세, 적용 범위, 현재 행동이 차례로 달라진다. 이는 결과를 보기 전의 교육용 계획 기록이며, 새 고객 결과나 실제 발송 승인을 만든 것이 아니다.
3. 03_TRANSFER.json: 기존 8장 조건 표에서 정답을 드러내는 분류와 판단 열을 해설로 넘기고 필요한 설계 조건은 문제 앞에 둔다. 기존 10장 재사용 과제는 유지할 근거와 다시 확인할 근거를 먼저 고르게 하며, 해설은 문장 일치보다 판단 이유를 대조한다.

TRI-V의 세 축과 여섯 항목, 기존 수치와 그림 및 원자료, v19 원고와 PDF 및 읽기 묶음을 보존한다. 3단계에서 문제 앞뒤로 옮긴 수치는 다중집합으로 검사하며 순서 불변 검사와 혼동하지 않는다. 반복 정의의 압축과 수치 이동, 새 안내 문장의 역할은 장부에서 구분한다.

세 단계를 실제 적용한 정식 PDF는 97쪽이다. 단계별 적용 장부와 글자 수는 exports/v20/MANUSCRIPT_CHANGES.json, PDF와 조판 결과는 validation_v20.json, 재생과 보존 검사 결과는 integration_validation_v20.json에 기록했다. 통합 검사 506건을 통과했으며, 이 횟수는 학습 효과나 출판 품질의 점수가 아니다.

검사 통과를 실제 독자 수행 향상이나 사람의 통계 검수로 표현하지 않는다. 최종 저자 표현과 권리 및 출간 승인은 별도다. 과거 동의 차단된 추가 PDF 인용 전수 대조와 전권 contact sheet 재생성은 이번에도 수행하지 않는다. 이번 요청만으로 외부 제출이나 GitHub 반영을 자동 실행하지 않는다.
