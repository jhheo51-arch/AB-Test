# CRM A/B 테스트 전자책 제작 방향·검수 체크리스트

## 문서의 상태
- 제작 방향 검토 초안 v0.1. 출간 원고·데이터·표지의 완성을 의미하지 않는다.
- 임시 독자 가정: CRM 입문 마케터·기획자. 사용자가 승인하면 확정한다.
- 주 사례: 가상 승용차 OEM. 다른 업종은 짧은 적용 예시로 제한한다.
- 판매·베스트셀러 여부는 보장하지 않는다. 독자 효용·재현성·편집 품질을 검증 목표로 삼는다.

## 1. 독자와 약속
대상: 캠페인을 운영하거나 결과를 보고하지만 실험 설계와 통계 해석에는 익숙하지 않은 CRM 실무자.
핵심 약속: 한 고객 여정을 따라 실험 설계서, 데이터 신뢰성 점검표, 결과 해석표, 비용·가치 판단표, 한 장 보고서를 완성한다.
범위 밖: 통계 백과사전, 실제 OEM 운영 매뉴얼, 법률 자문, 생산 환경용 CRM 도구.

## 2. 제목·관점
작업 가제: 《그래서, 이 캠페인 계속할까요?》
작업 부제: 자동차 고객 여정으로 배우는 CRM A/B 테스트와 의사결정
표지 저자명: 승인 전 미정. 자격·실적·추천사·판매 수치 임의 삽입 금지.
Tri-Ataxis: 저자가 의미를 부여한 관점 명칭. 검증된 새 통계 이론으로 소개하지 않는다.
TRI-V: Variable Control / Vector Segmentation / Value-Linked Decision. 학습·검토에 따라 수정 가능한 저자 제안 프레임워크.

## 3. 목차 작업안
1. 고객의 다음 행동에서 시작하기: CRM·라이프사이클·동의·가설
2. 무엇과 무엇을 비교할 것인가: 인과 질문·무작위 배정·주지표·가드레일
3. 언제 판단할 것인가: 표본·효과·검정력·종료 규칙
4. V1: 배정·노출·이벤트·측정 품질 점검
5. 결과 읽기: 효과 크기·p-value·신뢰구간·판단 불가
6. V2: 전체 결과·사전 세그먼트·사후 탐색·다중 비교
7. V3: 비용·가치·불확실성·실행/중단/재설계/보류
8. OEM 통합 실습과 한 장 보고서
9. 다른 업종으로 옮기기: 이커머스·SaaS의 짧은 전이 예시
부록: 용어·양식·데이터 사전·계산 가정·참고문헌
각 장 공통: 실무 질문 → 사례 → 개념 → 흔한 오판 → 작성 도구 → 다음 단계 조건.

## 4. 가상 기업 설계안
임시 기업명: Project OEM 가상 자동차 회사. 실제 상표 사용·상표 적법성 확인을 뜻하지 않는다.
시장·운영 가정: 단일 시장의 승용차 브랜드, 직영 CRM과 판매 파트너 접점이 연결되는 교육용 단순 모델. 특정 실제 OEM을 재현하지 않는다.
주 여정: 관심 등록 → 시승 예약 → 시승 완료 → 상담 → 계약 → 출고.
대표 질문: 사전에 정의한 관심 고객에게 시승 편의 중심 안내를 제공하면 기존 가치 중심 안내보다 실제 시승 완료가 늘어나는가?
주의: A/B 메시지 비교만으로 무발송 대비 효과를 주장할 수 없다. 무발송 효과는 별도의 배정·대조군·표본 설계를 갖춘 확장 실험에서 다룬다.
주지표 후보: 배정 시점부터 사전 설정한 기간 내 시승 완료 여부. 기간은 생성 전 설계서에 확정.
가드레일 후보: 수신 거부·불만·예약 취소·대기 부담. 지표 정의와 관측 가능성을 먼저 확정.
사업 판단: 예약·시승 증가를 계약·매출 증가로 자동 환산하지 않는다. 관측 비용과 미래 가치 가정을 분리한다.

## 5. 데이터 생성·검증 계획
개인·회사 원본 데이터는 사용하지 않는다. 모든 데이터는 생성 코드와 가정이 공개되는 합성 데이터다.

### 테이블
- customers: 합성 customer_id, 사전 고객 상태, 지역, 관심 모델, 채널별 연락 자격. 실제 이름·전화·이메일 불필요.
- assignments: experiment_id, customer_id, arm, assigned_at, 사전 세그먼트, 배정 확률.
- messages: 발송 시도·전달 상태·시간. 실패 발송자를 사후 제외하지 않도록 주 분석은 배정 기준으로 정의.
- journey_events: 예약·시승·상담·계약·취소·수신 거부 이벤트와 발생 시간.
- operations: 판매 접점·주간 시승 수용량·대기 등 단순 운영 가정.
- costs: 비용 항목·적용 단위·값·단위·가정 출처. 실제 시장 평균으로 표시하지 않는다.
- scenario_manifest: 생성 목적·난수 시드·확률·관측 기간·효과 설정·알려진 오류·버전.

### 시나리오
A. 정상 작동하는 기본 실습. 결과는 실제 실행 후 결정하며 유의한 결과가 나올 때까지 시드를 골라 바꾸지 않는다.
B. 실제 효과가 없는 검증 시나리오. 유의하지 않음을 무효과 확정으로 가르치지 않는다.
C. 누락·중복·배정 이상을 의도적으로 주입한 데이터 품질 실습. 오류 정답지는 학습용 파일과 분리.
D. 세그먼트 탐색·소표본·다중 비교의 위험을 보여주는 확장 실습. 인과적 집단 차이 주장에는 별도 근거 필요.

### 생성 순서
설계서 확정 → 생성 규칙·시드 고정 → 생성 코드 작성 → CSV 생성 → 무결성 검사 → 통계 계산 → 독립 계산 대조 → 표·차트 출력 → 실제 결과에 맞춰 원고 작성.

### 검증
- [ ] 배정 ID 유일성·기본키·외래키·필수값 점검
- [ ] 시점 순서·관측 기간·동의와 연락 자격 점검
- [ ] 배정 비율·이벤트 정의·분모·기간 일치 점검
- [ ] 주 분석은 사전 지정한 배정 기준, 사후 제외 금지 원칙 명시
- [ ] 합성 가정과 실제 표본 결과를 구분
- [ ] 효과 크기·p-value·신뢰구간·검정 방식·가정 명시
- [ ] 본문·표·계산 시트·보고서 값 일치
- [ ] 실제 효과를 아는 반복 시뮬레이션은 단일 사례와 별도로 수행
- [ ] 생성 시드·코드·의존성·실행 방법 기록

## 6. 출간물과 제작 방식
권장: Quarto 원고 → HTML 검토 → PDF 초판. EPUB은 판매처 요구와 실제 검수 가능성에 따라 추가한다.
제작 전 Quarto·PDF 엔진·한글 글꼴 가용성을 확인한다. 불가 시 대체 경로와 한계를 명시한다.
패키지: 본문 PDF, 편집 가능한 원고, 표지, 워크북, 합성 CSV, 데이터 사전, 생성·분석 코드, 정답 해설, 출처·권리 기록.
실무 배포용 CRM 도구는 초판 필수 범위에서 제외한다.

## 7. 표지 제작 브리프
콘셉트: 실무 질문이 전면에 오는 편집형 표지. 제목·부제·저자명의 정보 위계를 우선한다.
금지: 베스트셀러 배지·허구 추천사·가공 성과·실제 OEM 로고·허락 없는 차량 사진.
- [ ] 제목·부제·저자명 승인
- [ ] 판매처의 크기·비율·파일 요구 확인
- [ ] 사용 글꼴·이미지의 상업 이용 권리 확인
- [ ] 후보안 선택 후 작은 썸네일에서도 제목 확인
- [ ] 실제 HEX로 본문 대비 계산, 4.5:1 이상 확인
- [ ] 표지 이미지와 PDF 내 표지의 표기 일치

### A 방향
- [ ] 주 독자·핵심 약속 승인
- [ ] OEM 관통 사례와 다른 업종 범위 승인
- [ ] 학습 목표·목차 고정, 변경 기록 유지
### B 사례·데이터
- [ ] 가상 기업·데이터 생성 가정 승인
- [ ] 데이터 생성 및 코드 실제 실행
- [ ] 통계·무결성 검증 통과, 실패 기록 보존
### C 원고
- [ ] 전체 장 집필, TODO·빈 절·예시 문구 제거
- [ ] 사실·저자 제안·교육용 가정 구분
- [ ] 지표·수식·원문 인용·참고문헌 대조
- [ ] 실제 무작위 실험과 저자의 과거 업무 경험 구분
- [ ] 인간 통계 검토와 OEM 업무 검토의 실시 여부 명시
### D 독자 효용
- [ ] 대표 독자가 실험 설계서와 보고서를 작성해 봄
- [ ] 이해하지 못한 지점 수정
- [ ] 실제 독자 피드백과 가상 페르소나 평가 구분
### E 디자인·파일
- [ ] 표지·장 시작·본문·표·주의사항 스타일 일관

- [ ] 대비 계산·작은 화면·인쇄 가독성 확인
- [ ] PDF 목차·링크·검색·복사·글꼴 정상 확인
- [ ] 부속 파일 열기·실습 재현 확인
### F 판매 준비
- [ ] 판매·유통 경로 선택, 제출 규격 확인
- [ ] 출간 형태에 따른 ISBN·납본 등 적용 요건을 공식 안내로 확인
- [ ] 저자명·소개·책 소개·미리보기 확정
- [ ] 권리·개인정보·동의 관련 표현 검토
- [ ] 판매 전 파일 버전과 정오표·문의 경로 정리

## 9. 정직한 완료 표기
파일이 생성되고 계산이 실행돼도 외부 전문가 검토·실독자 테스트·판매처 확인이 남으면 '제작 완료/검토용'으로 표기한다. 미완료 관문이 있는 파일을 '출간 준비 완료'라고 부르지 않는다. 베스트셀러는 검수 통과나 내부 평가로 보증하지 않는다.
