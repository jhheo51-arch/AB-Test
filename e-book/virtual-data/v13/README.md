# v13 파생 데이터와 교정 실행 경로

새 실험이나 새 고객을 만든 버전이 아니다. v03 DB를 읽기 전용으로 복사한 뒤 `outcomes` 뷰의 사건 시간 조건에 배정일 하한을 추가한 파생 사본이다. 원테이블과 다른 스키마, v03 원본 파일은 보존했다. 현재 자료에는 배정 전 사건이 없어 교정 전후 집계가 같지만, 오염 사건을 주입한 메모리 복제본에서는 구형 뷰의 오류와 교정 뷰의 배제를 확인했다.

## 현재 사용 파일

- `data/jh_motors_v13.sqlite`: 교정한 뷰를 가진 파생 DB.
- `analysis_report_v13.json`: 5개 계획 검정력의 A/B 확률과 해당 군 n 대응을 바로잡은 결과. 다른 분석값은 보존.
- `DERIVED_MANIFEST.json`: 원 DB 및 파생 DB의 정확 바이트 해시, 입력 계획 이력, canonical 경로.
- `../v03/DATA_DICTIONARY.md`: 원자료 필드 명세.
- `../../analysis/corrections_v13/outcomes_v13.sql`: 교정한 뷰의 실제 SQL.
- `../../analysis/corrections_v13/REGRESSION_CHECK.json`: 실행한 회귀 검사.

## 실행

저장소의 별도 작업 사본에서 다음을 실행한다.

```sh
uv run --python 3.12 --with scipy --with numpy python scripts/correct_statistics_v13.py
```

이 명령은 교정용 v13 출력 폴더를 다시 만든다. v03 원자료와 계획 및 기존 결과, v12 책과 감사 파일에는 쓰지 않는다. 원 v03 분석 스크립트는 역사적 경로로 보존했다. 잘못된 확률/n 대응은 새 canonical 구현에서 수정했으며 구형 전체 작성기를 원자료 위에 재실행하는 대신 위 경로를 사용한다. 구형 전체 작성기를 이번에 실행하여 기존 결과를 덮어쓴 것은 아니다.

## 계획 해시와 검증 한계

원 계획의 실제 LF 바이트와 DB에 기록된 역사적 CRLF 표현의 해시는 여전히 다르다. `PROVENANCE.json`은 실제 읽은 파일의 해시, 역사적 해시와 줄바꿈 표현 동등성을 각각 기록한다. 내용 동등성이 역사적 정확 바이트 일치나 결과 전 동결을 입증한다고 쓰지 않는다. 원계획이나 DB의 저장 해시를 고쳐 맞추지 않았다.

보호 score의 새 canonical 구현은 검증한 내부 성공/실패 카운트에 한정하며 경계 카운트를 명시적으로 거부한다. 모든 A/B 유형을 지원하는 통계 엔진이나 사람 통계 검수 완료가 아니다. 실제 독자 시험과 현장 타당성 및 최종 출간 승인은 별개다.
