# v0.9 방법론 운용 보완 기록

저자: 허재혁. 최신 읽기본은 `../../exports/v09/ebook_review_v09.pdf`다. 이번 범위는 방법론 평가에서 지적한 세 가지 운영상 약점의 보완이며 나머지 출판 단계의 전권 편집과 사람 검수까지 수행한 것은 아니다.

## 전과 후

| 보완 항목 | 전: v0.8 | 후: v0.9 | 실제 확인 |
|---|---|---|---|

| 최소 경로와 심화 경로 | 심화 사례를 모든 실험의 필수 분석처럼 읽을 여지 | 세 질문은 항상 검토하되 집단, 경제, 용량 분석은 선택을 바꾸는 조건이 있을 때 추가 | 여섯 사례마다 경로와 판단 상태를 본문에 연결하고 독립 편집 대조표로 점검 |
| 사전 기준과 변경 이력 | 사전과 사후의 구별은 설명돼 있으나 하나의 공통 기록으로 연결이 약함 | 실험 전 공통 기준, 결과 후 세 축, 변경과 재검토를 같은 양식으로 관리 | 변경 전과 후, 제안 시각과 결과 열람 여부, 이유, 승인 역할과 새 자료의 확인 계획 필드 확인 |

설명과 양식에서 생기는 구조적 분산은 보완했다. 실제 독자가 더 빨리 또는 더 정확히 작성하는지는 아직 시험하지 않았으므로 사용성 개선과 학습 효과가 검증됐다고 하지 않는다.

## 사용하는 순서

1. `tri_v_operating_card_v09.pdf`를 곁에 두고 세 축의 질문과 산출물, 상태를 확인한다. 실제 A4 가로1쪽으로 출력했다.
2. `tri_v_decision_record_v09.md`의 A에서 실험 전 기준과 미정인 사항의 책임자를 기록한다. PDF는3쪽이며 편집은 Markdown이나 HTML 원본으로 한다. 입력형 PDF 양식이라고 소개하지 않는다.
3. 결과가 나오면 같은 기록의 B에서 V1 비교 명세, V2 적용 범위 문장, V3 결정문을 작성한다.
4. 기준을 바꾸면 C와 `tri_v_criteria_change_log_v09.csv`에 변경 이력을 남긴다. 원래 계획을 덮어쓰지 않는다.

CSV는 현재 헤더만 있다. 가상의 변경 승인, 실제 독자 기록이나 실제 발송 승인을 만들지 않았다. 미확인 담당자와 손실 한계를 임의로 채우지 않는 원칙을 양식에 포함했다.

## 본문 연결 위치

공통 기준은8쪽, 비교 축2장은11쪽, 적용 범위3장은13쪽, 결정 축4장은14쪽에서 시작한다. 사례1부터6은28,30,32,35,38,41쪽이며 각 사례 끝에 같은 운영 기록으로 무엇을 남길지 연결했다. 관통 실습12장은60쪽이며 끝의 결정문을 공통 양식과 변경 이력에 연결했다. 이 쪽수는 최종 `validation_v09.json`과 운영 검사 보고서를 기준으로 한다.

원래 통계 수치103항목과12장 SQL을 다시 대조했다. 분석 JSON과 원본 DB 및 계획은 변경하지 않았고 이전 판은 보존한다. 이번 여섯 사례 점검은 편집상 대응과 기록 구조의 확인이며 자동 승자 판정기나 새 통계 검증을 만든 것이 아니다.

## Contextvia를 들었을 때의 인상

사용자가 이번에 적은 철자는 `contextvia`이며, 표시명으로 쓴다면 `Contextvia`가 된다. 이전 추천 철자는 `Contexvia`다. 서로 다른 표기이므로 이번 보완 작업의 승인만으로 최종 이름까지 확정하지 않는다. v0.9 표지의 대표 이름은 기존 판을 유지하고 영문 이름은 검토 중으로 표시했다. 상표나 동명 이용 가능성도 이번 작업에서 확인하지 않았다.

제 인상으로 Contextvia는 분석과 전략 또는 의사결정 지원 도구의 브랜드처럼 들린다. Context가 철자에 남아 있어 뜻을 유추하기는 이전 후보보다 쉽지만, 발음은 다소 딱딱하고 이름만으로 CRM이나 A/B 테스트를 바로 떠올리기는 어렵다. 이는 미라의 작명 취향과 모의 인상 평가이며 실제 독자의 반응 조사나 채용 평가가 아니다.

신입이라는 맥락에서는 이름을 만들었다는 사실보다 무엇을 중요하게 보고 어떤 실수를 막으려는지 설명하는 태도가 주관을 드러낸다. 비교의 신뢰성, 적용 대상, 실행 책임을 일관되게 묻고, 한 사례에서 그 질문 때문에 결정을 어떻게 바꿨는지 보여주면 자기 기준을 가진 사람이라는 인상을 줄 수 있다. 반대로 검증된 독창 이론이라는 식으로 앞세우면 경험보다 이름을 크게 포장했다는 인상을 줄 위험이 있다.

권하는 소개 문장은 다음과 같다. “기존 실험 원칙을 CRM 의사결정에 연결하기 위해 직접 정리한 프레임워크입니다. 비교의 신뢰성, 적용 대상, 실행 조건을 세 축으로 검토하고 결정의 근거와 책임을 남깁니다.” 이름은 이 설명 뒤에 붙인다. 독창성을 과장하지 않으면서도 자신의 선택과 설계 의도를 분명히 하는 방식이다.

## 시각과 실행 검증

한 장 요약표와3쪽 작성 양식은 실제 브라우저에서 열고 PDF로 출력했다. 본문 및 양식의 실제 최소 글자 크기는12pt다. 한 장 요약표와 본책 공통 기준의 대표 화면을 이미지로 확인했다. 본문 SVG 라벨 경계, 내부 링크, 페이지 밖 글자와 꼬리말 겹침, 가운데 점6종을 검사했다.

기존 편집 시안의 색과 글꼴을 유지했다. `mira_contrast`에서 본문 #142D32 / #FFFFFF는14.471:1, 보조 본문 #4F625F / #FFFFFF는6.472:1, 표 배경 #F2F5F1의 본문 #142D32는13.166:1이다. 일반 본문 AA4.5:1과 큰 글자 AA3:1을 모두 충족한다. 이 계산은 전체 접근성이나 사용성 검증을 대신하지 않는다.

## 편집 선택의 이유

기준은 한곳에 모으고 각 장에서는 참조하게 해 서로 다른 규칙으로 읽히는 일을 줄인다.
질문과 계산의 깊이를 분리해 방법론을 쓰기 위해 불필요한 분석부터 늘리지 않게 한다.
사전 기준과 사후 변경을 같은 기록에서 보존해 판단의 근거와 재량을 추적하게 한다.

## 남은 범위

구조 보완의 구현과 출력 확인은 끝났고 저자의 표현 검토와 직접 시험이 남는다. 영문 최종 철자와 이름의 적용, 사람의 독립 통계 및 실무 검수, 재현 패키지 범위와 권리, 판매 형식 및 최종 출간 승인은 별도다. 기존 독자 시험 준비본은 v0.8을 후보 읽기본으로 기록한 상태이므로, 실제 시행 전에 사용할 판과 과제 버전을 다시 함께 고정해야 한다. 기존 시험 준비 기록의 해시를 새 판으로 몰래 교체하지 않는다.
