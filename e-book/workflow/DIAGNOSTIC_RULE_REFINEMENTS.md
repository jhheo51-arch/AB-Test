# 진단 규칙 보완 — 자동 결론 방지

## 워크플로우 v0.2에 적용할 세부 해석
1. **품질 실패는 추정 대상별로 판단한다.** 클릭 계측 오류가 독립 거래원장의 배정 고객당 매출 비교까지 반드시 무효로 만드는 것은 아니다. 어느 추정량이 어떤 오류에 노출됐는지 영향 지도를 만들고, 영향을 모르면 해당 결론을 보류한다.
2. **동시 실험이 자동 오염은 아니다.** 독립 교차배정은 적절한 설계와 분석 아래 유효할 수 있다. 공유 자원·상호작용·비대칭 변경을 구분한다.
3. **불확실하다고 무조건 더 수집하지 않는다.** 사전 종료 규칙, 추가 정보로 결정이 바뀔 가능성, 비용·기회비용·고객 위험을 함께 평가한다.
4. **가드레일을 한 점수로 상쇄하지 않는다.** 법·동의·중대한 안전은 이익으로 상쇄할 수 없다. 사업상 상충은 사전 한계와 승인 절차를 따르고 사례별로 평가한다.
5. **원인 후보와 관측 사실을 분리한다.** 클릭→방문→구매의 시간적 연결이 매개 인과를 입증하지 않는다. 경쟁 원인을 구분할 추가 증거를 요청한다.
6. **누락과 0을 구분한다.** 관측되지 않은 계약·연결 실패·추적 미성숙은 구매 없음과 다르다. 누락 메커니즘·군별 연결률·민감도를 확인한다.
7. **보류는 재개 조건을 포함한다.** 필요한 자료·책임자·예상 확인 시점·어떤 결과가 판단을 바꿀지를 출력한다.
8. **개별 효과와 전체 도입 효과를 구분한다.** 시승 슬롯·재고·상담 용량을 공유하면 처리 비중이 커질 때 효과가 달라질 수 있다.

## 다음 버전에 추가할 구조 패턴
아래 항목은 현재 60개 카탈로그와의 중복·행동 차이를 검토한 뒤 신규 ID 또는 기존 카드 하위 분기로 편입한다. 현재 카드 총수에 가산하지 않는다.
- 특정 메일 도메인·통신사에서만 전달 성과 악화: 인프라·평판과 콘텐츠 효과 분리.
- 이메일→상담과 상담→이메일의 순서 차이: 단일 메시지가 아닌 여정 정책 비교.
- 같은 고객의 반복 실험에서 이전 혜택·학습 잔존: 잔류 효과·지속 배정·재참여 조건.
- 소수 법인·고액 거래가 매출 효과 지배: 오류와 정상 꼬리 분리, 강건성 분석과 원래 추정치 병기.
- 연락에 따른 로그인 증가로 B의 오프라인 계약 연결률만 개선: 실제 효과와 관측 가능성 변화 구분.
- 설문 응답자 만족은 높지만 응답률·고객 구성이 다름: 비응답·선택과 전체 만족도의 구분.

## 검증 장부 구조
카드 ID / 회사 적용 조건 / 근거·반례 / 데이터셋·시나리오 / SQL·계산 / 예상 검출과 실제 검출 / 의도한 차단과 실제 차단 / 원고 절 / 검토자 / 미해결 한계.
카드를 작성했다고 데이터 검증·독자 효용이 검증된 것은 아니다. 현재 구현은 편집용 카탈로그와 문서 명세이며 실행 가능한 진단 엔진이 아니다.
