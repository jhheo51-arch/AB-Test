# CRM 실험 진단 워크플로우 v0.2 — 기업 적응형 설계안

저자: 허재혁. 검토용 명세이며 실제 기업·외부 전문가가 검증한 알고리즘이 아니다. ‘세상 모든 CRM 상황을 완전 열거’가 아니라 미지원·미확인 상태까지 기록하고 새로운 상황을 추가하는 확장 체계다.

## 1. 단일 흐름도에서 진단 시스템으로
마인드맵은 탐색 목차로, 상태 전이도는 작업 순서로, 결정표는 조건 조합으로, 진단 카드는 증거와 다음 행동으로 사용한다. 한 장의 거대한 나무에 모든 경우를 넣지 않는다.

### 네 레이어
1. Company Profile: 기업의 목표·고객 여정·권한·채널·데이터·트래픽·원가·운영 제약.
2. Experiment Contract: 인과 질문·대상·배정/분석 단위·지표·관측 창·분석/종료 규칙·사업 기준.
3. Evidence State: 품질·관측 성숙도·효과 구간·가드레일·경제성·외적 타당성 상태.
4. Decision Record: 실행/중단/재설계/보류, 근거·반대 증거·알 수 없는 것·승인자·감시·재평가 조건.

## 3. 단계와 차단 규칙
### G0 질문·정책·안전
무엇을 누구에게 바꾸며 비교 대상은 무엇인가? 개인정보·동의·안전·차별 위험을 확인한다. 부적합한 실험을 성과가 좋다는 이유로 통과시키지 않는다. 필수 안전 안내를 제공하지 않는 실험은 제외한다.
### G1 식별·실행 가능성
배정 단위·간섭·대조군·개입 실행 권한을 점검한다. 무작위 배정이 불가능하면 관찰/준실험 경로로 표시하고 A/B와 같은 인과 보증을 하지 않는다. 밴딧·클러스터·전환 설계 등은 별도 추론 절차가 필요하며 기본 분석을 그대로 적용하지 않는다.
### G2 데이터 품질
분모·중복·SRM·누락·동의·군 간 오염·프로토콜 이탈을 점검한다. 구조 무결성 통과와 결과 측정 완전성은 별개다. 미해결 중대 오류는 주 효과 판단을 차단한다.
### G3 관측 성숙·정보량
코호트별 같은 추적 기간·사건 수·사전 표본 계획·종료 규칙 확인. 계획에 없는 유의성 기반 연장을 하지 않는다. ‘불충분’과 ‘실질적 차이 없음’은 별도 상태다.
### G4 효과·불확실성
주지표의 절대/상대 효과·신뢰구간·최소 사업 효과·검정 가정을 기록한다. 지표/버전/세그먼트 다중성·반복 조회·이상치와 군집을 반영한다. 점추정 부호만으로 개선·악화를 확정하지 않는다.
### G5 상충 패턴·원인 가설
관심→행동→가치→관계/운영 상태를 연결하고 카탈로그의 가능한 설명을 제시한다. 원인은 확정하지 않으며 반증에 필요한 증거를 함께 기록한다.
### G6 집단·시간·다른 상황으로의 전이
사전 지정 효과 차이와 사후 탐색을 분리한다. 사후 좋은 집단으로 바로 출시하지 않는다. 지점·시기·규모·차종·고객 구성 변화가 효과를 바꿀 수 있음을 기록한다.
### G7 경제·자원·지속성
비용·마진·취소·반품·잠식·구매 당겨쓰기·포화·장기 유지와 불확실성을 검토한다. 단기 시승/계약을 장기 LTV로 확정 환산하지 않는다.
### G8 사람의 결정·모니터링
근거에 따른 권고와 사람의 승인을 분리한다. 선택지는 실행·제한 확대·중단·재설계·보류이며 조건 충족 여부와 잔여 불확실성을 남긴다. 출시 후 운영 임계값·롤백·장기 추적·재평가를 정한다.

## 4. 상태 모델
각 축은 value와 evidence_status를 함께 저장한다.
- evidence_status: known / estimated / unknown / not_applicable / unsupported.
- 판단 정보: effect_estimate, interval, metric_definition, denominator, observation_window, source, assumptions, competing_explanations.
- business_effect_state: material_benefit_supported / material_harm_supported / equivalence_supported / inconclusive / invalid.
- equivalence_supported는 별도 동등성/비열등성 설계와 허용 한계 근거가 있을 때만 선택한다.
- metric role: primary / guardrail / diagnostic / exploratory. 결과를 보고 역할을 바꾸지 않는다.
기본 분기에서 unknown은 자동 통과가 아니다. not_applicable과 누락도 구분한다.

## 5. 예시 결정표 — 자동 처방 아님
| 품질·성숙 | 사업 가치 | 관계·안전·운영 | 권고 후보 |
|---|---|---|---|
| 무효 또는 미확인 | 어느 상태든 | 어느 상태든 | 문제 진단·판단 보류 |
| 유효·성숙 | 개선 근거 | 중대한 위험 미해결 | 위험 검토·중단/재설계; 자동 확대 금지 |
| 유효·성숙 | 개선 근거 | 허용 조건 충족 | 사람 승인 아래 제한/전체 확대 검토 |
| 유효·성숙 | 악화 근거 | 어느 상태든 | 중단 또는 가치모형 검토·재설계 |
| 유효·성숙 | 불확실 | 허용 조건 충족 | 사전 계획·비용에 따른 보류/후속 실험 |
| 유효·성숙 | 성과 비열등 근거·비용 감소 | 허용 조건 충족 | 효율 개선 채택 검토 |

## 6. 진단 카드의 필수 필드
case_id / 기업 적용 조건 / 고객 상태 / 개입·대조 / 배정·분석 단위 / 측정 지표 / 관측 창 / 관측 패턴 / 효과·불확실성 / 경쟁 설명 / 구별에 필요한 증거 / 안전 차단 / 다음 행동 후보 / 반례 / 후속 실험 / 근거 출처 / 실제·합성 구분 / simulation_status / 검토자·버전.
현재 catalog는 observation·설명·증거·다음 단계의 초기 형식이다. 모든 필드가 채워진 완성 카드로 보지 않는다.

## 7. 기업 평가 경로
공개 정보 조사 → 사실·날짜·출처 기록 → 추정과 미확인 필드 분리 → 여정·제약 지도 → 공개 정보로 평가 가능한 범위 지정 → 가설·실험 설계 제안 → 내부 데이터 요청 목록 → 합성 시뮬레이션 → 잔여 위험·확인 계획.
공개 사이트 화면·공시만으로 내부 CRM 운영·전환율·실험 성숙도·매출 원인을 확정하지 않는다. 실제 기업 평가와 가상 수치 실습은 시각·표기·파일에서 분리한다.

## 8. 커버리지 관리
case_catalog_v01.csv는 구조적 범주별 대표 카드다. 특정 회사에 적용할 때 회사 프로필 각 축과 G0~G8에 대해 지원/미지원/해당없음/증거부족을 기록한다.
새 상황은 기존 카드에 억지로 맞추지 않고 신규 ID와 경쟁 설명·반례·필요 증거를 추가한다. ‘카드 수 증가’와 ‘검증 범위 증가’를 구분한다.
각 카드와 합성 시나리오·SQL·원고 절·검사·실제 출처를 연결하는 traceability 표가 필요하다. 현재 이 매핑은 미완료다.
