# CRM 실험 판단 프레임 v0.2

갱신: 2026-11-17 (Asia/Seoul). 사용자의 피드백을 반영한 **틀·기획 문서**이며 앱·통계 엔진·세그먼트 분석을 구현하거나 검증한 결과가 아니다.

## 1. 제품 정의
**CRM 캠페인·접촉 여정의 A/B 결과를 전체와 고객 세그먼트별로 비교하고, 어떤 안이 어느 고객에게 유리한지와 실행해도 되는지를 구분해 검토하는 도구.**

CRM은 임시 첫 적용 분야가 아니라 제품의 중심 범위다. 범용 웹·앱 실험 플랫폼으로 확장하는 것을 목표로 하지 않는다. 공급자 비종속성은 여러 CRM 원천을 지원할 수 있다는 뜻이지 모든 도메인의 실험을 다룬다는 뜻이 아니다.

### 반드시 함께 답할 질문
1. **A/B 중 누가 이겼는가?** — 사전 주지표·방법·판정 기준과 품질 조건에 근거한 전체/세그먼트 결과.
2. **누구에게 어떤 안이 유리한가?** — 사전 정의 집단의 효과·불확실성·관계 위험, 집단 간 차이의 근거.
3. **그래서 무엇을 적용할 것인가?** — 비용·접촉 정책·동의·운영 제약을 고려한 적용 범위와 사람의 승인.

승패는 없애지 않는다. 다만 승패와 출시 결정을 같은 값으로 저장하지 않는다.

## 2. CRM을 두 축으로 세분화
### 축 A: 고객 여정의 목적 — 왜 연락하는가?
- 첫 행동·온보딩: 관심 등록 후 프로필 완성, 첫 상담/예약 등.
- 전환 촉진: 문의→예약→실제 이용/구매 등 다음 단계 진입.
- 유지·반복 행동: 재방문·재구매·정기 이용 유도.
- 이탈 예방·재활성화: 사전에 정의한 이탈 위험/휴면 고객의 복귀.
- 관계·선호 관리: 소식·채널·빈도 선호 갱신 등 선택권 존중.

여정 목적이 목록에 있다는 것이 모든 장기 유지·구독·생존 지표를 첫판에서 통계 지원한다는 뜻은 아니다. 합의된 관측 창의 사용자별 이항 결과로 표현하고 지원 조건을 충족할 때 기본 경로를 쓴다. 필수 안전·법정 안내를 보류하는 실험은 제외한다.

### 축 B: 변경 요소 — 무엇을 비교하는가?
| 유형 | 비교 예 | 주의할 점 |
|---|---|---|
| 메시지·콘텐츠 | 가치 설명 vs 이용 편의 설명 | 클릭과 최종 행동 구분 |
| 혜택·오퍼 | 할인 vs 비가격 혜택 | 비용·마진·혜택 기대와 장기 영향 |
| 시점 | 즉시 안내 vs 계획된 대기 후 안내 | 공정한 결과 관측 창과 지연 |
| 빈도·접촉 정책 | 단일 접촉 vs 계획된 후속 접촉 | 캠페인 간 접촉 중복·피로 |
| 채널·채널 조합 | 동의·자격이 있는 고객에서 이메일 vs 다른 채널 정책 | 도달 가능성·식별·동의·선택 편향 |
| 여정·후속 분기 | 단일 경로 vs 행동에 따른 후속 경로 정책 | 처음 배정한 전체 정책 효과와 중간 행동의 선택 구분 |
| 접촉 유무·증분 효과 | 발송 vs 미발송 | 실제 무작위 미발송군이 있어야 함 |

이는 CRM 실험의 문제 분류다. 유형을 선택했다고 분석 가능성이 보장되지는 않는다. A/B는 최초 배정한 두 정책의 비교이며, 정책 안의 여러 요소를 동시에 바꾸면 각 요소의 개별 효과를 분리했다고 말하지 않는다.

### 초기 관통 사례
JH Motors의 **전환 촉진 × 메시지·콘텐츠**: A 차량 가치 안내 vs B 시승 편의 안내. 고객 단위 배정, 28일 시승 완료가 주지표, 예약은 진단, 수신 거부는 가드레일이다. 기존 자료에는 무발송군이 없으므로 캠페인 자체의 미발송 대비 증분 효과는 주장하지 않는다.

## 3. Segment를 핵심 구조로
**세그먼트는 부가 필터가 아니라 설계 → 비교 → 적용 범위를 연결하는 객체**로 둔다.

| 역할 | 질문 | 예 |
|---|---|---|
| 대상 세그먼트 | 누가 실험에 들어갈 수 있는가? | 동의가 있고 시승 이력이 없는 적격 고객 |
| 분석 세그먼트 | 어떤 사전 고객 특성에서 A/B 반응을 비교할 것인가? | 실험 전 관심 차종, 기존 접촉 이력, 사전 관심 단계 |
| 적용 세그먼트 | 검증 후 누구에게 어느 정책을 적용할 것인가? | 충분한 근거가 확보된 특정 사전 정의 집단 |

대상·분석·적용은 자동으로 같은 집합이 아니다. 고객을 나누는 기준과 처치를 무작위 배정하는 기준도 구분한다. 첫판은 주요 사전 정의 축 하나부터 깊게 검토하고 여러 축의 무제한 교차 탐색은 제외하는 안을 추천한다.

### Segment 명세의 최소 개념
segment_id / 정의·조건 / 기준시점·버전 / 사전·사후 구분 / 대상·분석·적용 역할 / 중첩 여부 / 누락 고객 처리 / 분모 / 집단별 목표 효과·정보량 / 비교 가족·가설·보정 계획 / 다음 행동.

### 해석 안전장치
- 기본 분석 집단은 배정 전 특성으로 정의한다. 읽은 사람·클릭한 사람처럼 처치 이후 행동으로 전체 효과 비교 대상을 바꾸지 않는다.
- 전체 결과를 먼저 남기고 세그먼트 결과를 함께 본다. 전체 불확실성을 유리한 집단만 골라 덮지 않는다.
- 각 집단의 A/B 표본·사건·효과·구간·품질·관측 성숙도를 함께 표시한다. 작은 집단을 억지로 승패 판정하지 않는다.
- ‘집단 X에서 유의, Y에서 비유의’만으로 두 집단의 효과가 다르다고 하지 않는다. 집단 간 효과 차이는 사전 지정한 상호작용/차이 검토와 적절한 불확실성 평가가 필요하다.
- 다중 지표·세그먼트·반복 조회의 주장 범위와 오류 통제 계획을 사전에 정한다. 보정·정보량·방법이 미지원이면 확증 결론을 내지 않는다.
- 사후 탐색은 다음 실험의 가설로 표시한다. 발견 즉시 집단별 자동 적용하지 않는다.
- 미확인·중첩·누락을 숨기지 않는다. 집단을 합해 전체라고 표시하려면 실제로 전체를 분할하는지 확인한다.

초기 핵심에 **세그먼트 설계·집단별 A/B 효과 검토·적용 범위 기록**을 포함한다. 계산 방법·교정·검증 기준은 구현 전에 고정해야 하며 현재 지원 완료라는 뜻은 아니다.

## 4. 결과는 네 층으로 분리
| 층 | 출력 | 의미 |
|---|---|---|
| 분석 자격 | 가능 / 제한 / 미성숙 / 불가 / 미지원 | 어떤 추정이 가능한가 |
| A/B 승패 | A 우세 근거 / B 우세 근거 / 승패 보류 / 판정 불가 | 사전 주지표·가설·기준에 대한 결론 |
| 세그먼트 | 집단별 A/B 결과 / 집단 차이 근거 / 탐색 신호 / 정보 부족 | 누구에게 어떻게 다른가 |
| 실행 판단 | 적용 검토 / 제한 적용 검토 / 기존안 유지 / 재설계 / 보류 | 사업·관계·운영 기준 아래 사람이 정하는 행동 |

양의 점추정·높은 전환율만으로 승리라고 하지 않는다. ‘관측상 B가 높음’과 ‘B 우세 근거’를 분리한다. 승패 보류는 동등함의 증명이 아니다. 가설이 개선 방향만 검정한다면 그 반대 방향의 통계적 승리까지 자동으로 주장하지 않는다. 동등/비열등은 별도 설계·방법이 검증된 경우에만 판정한다.

‘B 우세 근거’여도 수신 거부·비용·공급 용량 때문에 적용 보류일 수 있다. 전체는 보류지만 사전 정의 집단에 검토할 신호가 있을 수 있고, 이것이 곧 집단별 도입 근거라는 뜻은 아니다.

## 5. 사용자 작업 흐름
```text
CRM 여정 목적·실험 유형 선택
→ 대상·분석 세그먼트와 A/B 정책 정의
→ 주지표·가드레일·표본·관측·종료·비교 계획
→ 데이터 의미·품질·성숙도 확인
→ 전체 A/B 승패 + 세그먼트별 효과·차이 검토
→ 비용·동의·접촉 피로·운영 제약 확인
→ 적용 범위·다음 행동·승인·재평가 기록
```

기존 CRM 검토 항목(고객 상태, 행동 장벽, 동의/접촉 정책, 지표 충돌, 관측 시차, 비용, 관계 손상, 운영 제약)을 유지하고 위 흐름에 배치한다.

## 6. 화면 결과 구조 제안 — 구현 아님
- 요약: 주지표 기준 전체 A/B 승패, 효과·불확실성, 분석 제한.
- 세그먼트 비교: 사전 정의 기준과 역할, 집단별 A/B 결과, 전체 결과, 차이 검토 상태.
- CRM 진단: 증분 효과 주장 가능 여부, 접촉·관계·비용·여정·운영 위험.
- 결정 기록: 적용 대상/제외 대상, 이유, 책임자, 후속 확인·재검토 조건.

실제 수치 없는 문서 예시는 레이아웃·상태 설명일 뿐 결과 데이터로 제시하지 않는다.

## 7. 이번 변경과 경계
- 승패를 제외하는 인상 → **전체/집단별 A/B 승패를 기본 기능에 명시**.
- 포괄적인 CRM 활동 → **고객 여정 목적 × 변경 요소**로 세분화.
- 세그먼트 부가 분석 → **대상·분석·적용의 중심 구조**.
- CRM 첫 적용 후 범용 확장 → **CRM 특화 범위를 유지하며 검증된 지원만 확장**.

문서 프레임만 갱신했다. 발송·SDK·CRM 연결·통계/세그먼트 엔진 구현·새 실험 계산·실제 사용자 평가·외부 기능 재조사는 이번 범위가 아니다. 과거 시장 비교는 이전 조사일의 근거로 유지한다.
