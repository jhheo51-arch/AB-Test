- CRM 전체 관리가 아니라 A/B 테스트의 설계·분석·판단에 집중합니다.
- 사용자 우선순위는 결과·승패·고객군 차이 이해 → 설계 확신 → 다음 행동입니다.

- 처음부터 통계 설정을 요구하지 않고 목적·제약을 확인한 뒤 추천안을 제시합니다.
- 초기 MVP는 **외부 실험 + 도구 내 자연어 설계·분석·설명**으로 합의했습니다. 내장 실험·설문 배포와 수집은 초기 범위 밖입니다.
- 지표·위너·비율·변수 처리의 네 원칙을 보존했습니다. 업무·일상에서 낮은 진입 장벽을 지향하되 모든 일상 실험 지원이 확정된 것은 아닙니다.
- PRD는 질문 하나씩 함께 구체화하며, 초기 HTML은 참고 초안이고 실행 앱은 아닙니다.

## 제품 정의
**CRM 캠페인·접촉 여정의 A/B 결과를 전체와 고객 세그먼트별로 비교하고, 어떤 안이 어느 고객에게 유리한지와 실행해도 되는지를 구분해 검토하는 도구.**

CRM은 임시 첫 적용 분야가 아니라 제품의 중심 범위다. 범용 웹·앱 실험 플랫폼이나 CRM 시스템·발송기 제작을 목표로 하지 않는다. 특정 공급자에 종속되지 않는 CSV 기반 검토에서 시작하며, 확장도 CRM 실험의 검증된 필요 안에서 결정한다.

핵심 질문: **A/B 중 누가 이겼는가 → 어떤 세그먼트에서 어떻게 다른가 → 누구에게 적용할 것인가?** 승패와 실행 승인은 분리한다. 세그먼트는 대상 선정·분석·적용 범위를 연결하는 핵심 객체다.

## 현 단계의 결정
1. 실험 실행 플랫폼보다 설계·검증·분석·결정 기록을 먼저 만든다.
2. 첫 기본 경로는 두 그룹·사용자 단위 무작위 배정·고정 표본·이항 주지표이다.
3. 입력 오류·미성숙 관측·미지원 분석을 억지 결론으로 바꾸지 않는다.
4. 사업 기준과 가드레일은 결과 전에 정의한다. 사후 입력은 사후라고 표시한다.
5. 계산·차단 규칙과 AI 설명을 분리한다. 최종 승인은 사람이 한다.
6. 시장의 기존 제품보다 우월하다고 주장하지 않는다. 차별성은 고객·업무 적합성 가설로 검증한다.
7. 전체·세그먼트별 A/B 승패 판단을 포함하되 보류·판정 불가를 허용한다. 높은 점추정만으로 승리라고 하지 않는다.
8. CRM을 고객 여정 목적 × 메시지·혜택·시점·빈도·채널·여정·접촉 유무로 세분화한다.
9. 사전 세그먼트·정보량·다중 비교·집단 차이 검토를 설계에 포함하고 사후 탐색을 즉시 적용하지 않는다.

## 지금 하지 않는 일
구현, SDK, 발송, 실제 CRM 연결, 고객 데이터 업로드, 가격 책정, 운영 배포, 검증되지 않은 신규 통계 방법 개발.

공개 라이선스를 새로 부여하지 않는다. 실제 고객·인증정보·권한 없는 원문은 이 폴더에 넣지 않는다.
