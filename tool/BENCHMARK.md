# 시장 보급도와 경쟁 도구 비교

조사·작성: 2026-11-17 (Asia/Seoul). **공식 문서와 웹 기술 탐지 자료 조사**이며 제품 로그인·실험 실행·성능·가격 견적 비교는 하지 않았다. 우리 제품은 구상 단계이고 표의 기능은 **계획**이다. 기존 저장소의 교육용 합성 분석과 문서 자산이 실행 플랫폼의 구현을 뜻하지 않는다.

사용자 피드백 반영: [프레임 v0.2](FRAMEWORK_v02.md). 우리 방향은 CRM 특화를 유지하며 **전체·세그먼트별 A/B 승패 + 적용 판단**을 모두 포함한다. 이 보완은 새 시장 조사나 경쟁사 기능 재검증을 뜻하지 않는다.

## 1. ‘가장 많이 사용되는 도구’는 하나로 확정할 수 있는가?
보편적인 유료 고객 수·활성 사용자 수·실험 실행량 기준 1위는 이번 조사에서 확인하지 못했다. 공개 웹 기술 탐지는 비교 대상을 고르는 보조 근거로 사용한다.

BuiltWith의 A/B Testing Analytics and Tracking 표에는 CRM·메일·분석 제품과 레거시 기술 탐지까지 섞여 있다. 2026-11-13 갱신 표에서 Brevo가 선두이지만, 그것을 전문 실험 도구의 보편적 시장 1위로 바꾸어 말하지 않는다.

- 이 표는 선택 제품의 수치이지 모든 전문 도구의 순위표가 아니다.
- ‘전체 웹’은 BuiltWith의 탐지 범위이며 인터넷 전수조사가 아니다.
- live는 현재 코드가 탐지된다는 뜻이며 실제 실험 실행·유료 계약·고유 기업 수와 같지 않다.
- 한 사이트가 여러 제품을 쓸 수 있고, 카테고리 Detections 합계는 고유 사이트 수가 아니다.
- VWO와 Optimizely의 순서가 표본에 따라 바뀐다. ‘VWO가 무조건 1위’ 또는 ‘Optimizely가 무조건 1위’라고 하지 않는다.
- 검색 스니펫은 실제 본문보다 오래된 통계를 보여주기도 했다. WMTips는 통계 본문 접근이 차단되어 그 순위·점유율 숫자를 이 확정 표에 사용하지 않았다.

## 2. 비교 대상 선정
1. **VWO**: Top 1m에서 Optimizely보다 많이 탐지되는 웹 실험 도구이며 설계·품질·보고·기록 기능의 중복을 엄격하게 비교하기 좋다.
2. **Optimizely Web Experimentation**: 전체 웹 탐지에서는 VWO보다 높고, 실제 웹 실행과 품질·결과 보고를 제공하는 비교 대상.
3. **Braze**: 위 탐지 순위로 선정한 것이 아니라 CRM의 발송·미발송 홀드아웃이라는 사용자 업무 맥락을 위해 선택한 인접 비교 대상.
4. **Brevo**: 넓은 탐지 카테고리 선두임을 알리되, 이번 전문 실험 기능 비교의 대표로 대체하지 않는다. 공식 제품 소개는 이메일·메시징·자동화·CRM 맥락으로 확인했다.

## 3. 기능 비교: 현재 제품 대 우리의 계획

## 4. 반드시 피해야 할 잘못된 비교
### ‘경쟁사는 p값만, 우리는 품질·결정까지’
공식 문서와 어긋난다. VWO/Wingify는 품질·가설 계획·감사 로그·승인·결정 시점을 명시하고 Optimizely도 자동 SRM·보고·불확실성 표시를 제공한다. 품질·리포팅이라는 기능 이름만으로는 차별화가 아니다.

### ‘우리의 CSV 검사가 운영 중 감지와 동등하다’
종료 후 제한된 파일만 보는 도구는 원천 시스템의 전체 배정·추적 변경 이력을 모를 수 있다. 실시간 SRM·노출 제어·수집 인프라를 제공하는 플랫폼과 기능 범위가 다르다.

### ‘Braze 보고서를 그대로 넣으면 같은 분석이다’
확인한 GCG 문서는 반복 이벤트와 일별 그룹 사용자 수 합을 분모로 쓰는 보고를 설명한다. 이는 고정 코호트 사용자별 0/1 결과와 다르다. 원천 로그·설계·단위를 확인하지 않고 동일 수치를 기대하면 안 된다. 캠페인 A/B와 전역 홀드아웃도 같은 질문이 아니다.

### ‘단순한 고정 표본이니까 더 정확하고 쉽다’
지원 범위가 좁다는 것과 정확성·사용성이 높다는 것은 별개다. 극단 비율·미성숙·반복 관측·누락·표본 계획을 검증해야 한다. 사용자 비교 시험 전 편의성·시간 절감·지불 의사를 주장하지 않는다.

## 5. 방어 가능한 차별화 가설
**CRM 실무자가 메시지·혜택·시점/빈도·채널·여정·접촉 유무 실험의 전체/세그먼트별 A/B 승패를, 추정 대상별 품질·고객관계 위험·운영 제약·사업 가정·적용 범위·사람 승인과 더 일관되게 연결할 수 있는가?**

이는 기능 부재를 발견했다는 주장이 아니라 아직 검증해야 할 업무 적합성 가설이다. 기존 플랫폼 + 체크리스트/스프레드시트/노트북으로 충분할 수 있다.

추천 포지셔닝: **처음부터 Optimizely·VWO 대체가 아닌 CRM 실험 검토·의사결정 기록 레이어**. 계산 엔진도 필수지만 고객별 관측 창·외부 데이터 정의·보류의 다음 행동을 연결하는 좁은 작업을 우선한다.

## 6. 가상 페르소나의 구매/개발 선택
[김서윤의 문서 기반 평가](PERSONA_REVIEW.md)에서의 잠정 판단이다. 실제 고객 응답이 아니다.
- 웹 화면의 실행·타기팅·실시간 운영이 당장 필요하면 기존 실험 플랫폼을 우선 검토.
- 실제 메시지 발송·전역 미발송군 운영이 필요하면 Braze 등 기존 CRM 실행 도구 검토.
- 이미 도구가 있고 결과를 여러 원천과 함께 설명해야 하는 좁은 문제가 남으면 우리 보조 도구의 파일럿 가치가 있을 수 있음.
- 외부 CSV 제공 권한·원천 식별·관측 창이 없으면 초기 도구 적합성이 낮음.
- 기존 보고·Plan·감사 로그만으로 충분하다면 새 플랫폼 구축보다 운영 템플릿 개선이 나을 수 있음.

## 7. 최종 권고와 검증 우선순위
1. **방향 유지**: 설계·품질·분석·사업 판단 연결. 그러나 ‘통계 계산기보다 넓다’만으로 시장 차별화를 주장하지 않는다.
2. **범위 축소 유지**: 2군·사용자 단위·이항·고정 표본. 실행과 CRM 커넥터는 후속.
3. **차별화 검증**: 같은 가명 사례로 기존 방법과 제안 도구의 준비 부담·오판·반론 추적·재작업을 비교.
4. **데이터 계약 우선**: 업로드 전 배정·분모·관측 창·원천의 의미를 고정. 초기 성공의 가장 큰 위험은 CSV 준비 부담.
5. **확장 보류**: 초기 사용자 과제에서 가치가 확인되기 전에 범용 LTV·AI 원인 추론·모든 통계 방법을 추가하지 않음.

가격·시장점유율·속도·ROI·보안 인증·현장 신뢰·구매 우월성은 이 조사로 비교하지 않았다. 공급자 문서의 기능 설명과 제품 성능 검증을 구분한다.
