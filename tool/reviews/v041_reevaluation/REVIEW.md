# v0.4.1 재평가

## 평가 기준과 범위
CRM 마케터가 입력 → 결과 이해 → 판단 기록 → 공유를 끝낼 수 있는가를 기준으로 실행 중인 v0.4.1을 관찰했다. 1440×1100 데스크톱, 390×844 모바일 화면과 합성 데이터를 사용했다. 실제 사용자 시험이나 현장 성과 평가가 아니다. 앱 소스와 GitHub는 수정하지 않았다. 수정 회귀 실행으로 테스트 결과/PDF 증거는 갱신된다.

## 결론
입력·출력 최신성과 저장 왕복 문제를 보완한 로컬 MVP다. 표준 형식을 준비할 수 있는 사용자의 제한된 시범 사용을 검토할 단계지만, 통계가 주업무가 아닌 CRM 실무자의 낮은 진입 장벽과 전체 자연어 설계 흐름을 완성한 제품은 아니다. 다음 개선의 중심은 통계 방법 추가보다 입력 복구와 결과의 정보 위계다.

## 실제 확인
- tests/verify_fixes_v041.py를 재실행했고 수정 회귀 22개를 통과했다. 실제 해시·파일 바이트의 완료 시점만 통제한 합성 검사다.
- 집단별 합성 예시를 준비·분석했다. 전체 보류, 집단 보정 후 보류, 직접 차이의 판정 제한과 실제 적용 승인 구분이 표시된다.
- 별도 합성 A=80/100, B=20/100을 분석했다. 제목은 A 우세 근거인데 B 카드 배경은 #EDF3FF, A는 #F5F7FA로 B 강조가 유지됐다. 계산 오류가 아니라 고정된 시각적 강조 문제다. 색이 실제 승패 오독을 일으킨다는 현장 증거는 아직 없다.
- variant,converted,participants,cohort라는 다른 헤더의 합성 집계를 입력했다. UNKNOWN_HEADER 4개와 MISSING_HEADER 3개가 영어 설명과 함께 나타나고 분석 조건은 숨겨졌다. 차단은 올바르나 열 연결·한국어 복구 경로가 없다.
- 결과의 비교 맥락 카드가 전체 결과 수치보다 먼저 넓게 배치된다. 전체·집단·직접 차이와 방법·설명이 길게 이어져 결론과 다음 확인을 먼저 훑기 어렵다.
- 판단·공유 화면은 선택 이유와 재검토 조건을 자유 서술로 입력하게 한다. 미기록을 명시하고 공유 범위를 확인하게 하는 점은 좋다. 무엇을 기록할지 모르는 사용자에 대한 선택형 발판은 부족하다.
- 모바일 관찰 상태에서 문서 폭과 뷰포트 폭은 모두 390px이었다. 데이터 확인 버튼은 첫 화면 아래에 있었다. 이 한 상태의 관찰을 전 화면 반응형 검증으로 확대하지 않는다.

## 우선 수정 세 개 — 모두 제안

| 우선 | 문제/영향 | 수정안 | 예상 구현 비용 |
|---|---|---|---|
| 1 | 영문 고정 헤더 준비와 오류 해석이 사용자의 부담 | 원본 열 미리보기 → A/B·성공 수·분모·집단 열 직접 연결 → 변환 집계 확인. 의미 추정은 추천으로만 표시하고 사용자 확인 필요 | 중간 |
| 2 | 결과의 핵심이 맥락·상세 정보에 밀리고 B가 고정 강조됨 | 첫 카드에 관측 차이·통계 판정·미확인 사업/보호 조건·다음 확인 배치. A/B 카드 기본 스타일은 중립 통일, 판정은 별도 배지. 맥락·계산 근거는 상세 펼침 | 낮음~중간 |
| 3 | 판단 이유를 빈칸부터 작성해야 함 | 검토 방향 → 근거 → 추가 확인 → 재검토 조건으로 작성 발판 제공. 선택을 실제 승인으로 표현하거나 모델이 자동 확정하지 않기 | 중간 |

자유 상황 설명 → 후보 → 지표·배정·판정 계획 추천은 여전히 제품의 핵심 목표다. 현재 규칙 기반 설계 안내와 혼동하지 않는다. 위 세 개선을 전체 설계 대화의 완성이라고 부르지 않는다.

## 수정 전후 문구 제안

| 현재 | 제안 |
|---|---|
| UNKNOWN_HEADER / Header is not supported; exact English headers are required. | 이 열을 아직 연결하지 못했어요. A/B 구분·성공 수·전체 수에 해당하는 열을 선택해 주세요. |
| 승패 보류 | 관측 차이는 있지만, 통계적 우세는 아직 확정하지 못했어요. |
| 현재 선택과 이유 / 자동 승인 아님 | 이번 결과로 어떤 방향을 검토하나요? 선택 근거와 확인할 조건을 남겨 주세요. |

첫 제안은 열 연결 기능을 실제로 만든 뒤에만 사용할 문구다. 미구현 기능이 있는 것처럼 현재 화면에 표시해서는 안 된다.

## 색·타입·간격

실제 계산 스타일: 본문 #202B3A, 보조 #586779, 흰 버튼 글자/주행동 #1F62D1. mira_contrast_matrix로 계산했다.

| 항목 | 현재/계산 | 제안 |
|---|---|---|
| 본문/흰 표면 | #202B3A / #FFFFFF, 14.30:1 | 유지 |
| 보조/흰 표면 | #586779 / #FFFFFF, 5.78:1 | 유지 |
| 흰 글자/주행동 | #FFFFFF / #1F62D1, 5.64:1 | 유지 |
| A/B 수치 카드 배경 | A #F5F7FA / B #EDF3FF 고정 | 중립 표면 통일, 결과 상태는 별도 배지 |
| 제목 | 34px / 행간 47.6px | 큰 위계 유지, 결론을 먼저 배치 |
| 보조 문구 | 13px / 행간 23.4px | 핵심 안내는 14px 이상 제안, 세부 주석과 분리 |
| 수치 카드 간격 | 16px | 유지. 결과 요약·세부 영역은 24px 구획 제안 |

위 세 실제 텍스트 조합은 본문 AA 4.5:1과 큰 글자 AA 3:1을 모두 통과했다. 매트릭스의 미사용 조합 실패를 화면 결함으로 세지 않았다. 대비 계산은 전체 접근성 인증이 아니다. 제안 값은 확정 토큰이 아니다.

## 선택 이유 — 세 줄
입력 전처리를 줄여야 사용자가 계산 결과에 도달할 수 있다.
결론의 위치와 중립적인 A/B 표현이 색을 더 꾸미는 일보다 먼저다.
판단 작성 발판은 자동 승인 없이 다음 행동을 구체화하도록 돕는다.

## 다음 확인 상태
열 이름이 다른 파일을 사용자가 직접 연결할 수 있는지, A 우세/B 우세/보류/추론 미실행에서 같은 위계로 읽히는지, 집단 공유 제외와 판단 미기록을 보고서에서 분명히 구분하는지 확인한다. 실제 CRM 실무자의 동일 과업 수행으로 막힌 지점·수정·오독을 관찰해야 한다. 성공률이나 시간 절감은 아직 측정하지 않았다.
