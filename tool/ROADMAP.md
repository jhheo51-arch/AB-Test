# CRM A/B 테스트 도구 — v0.5 이후 과제

## 문서의 상태

현재 기준은 [v0.5 실행본](workspace/v05/README.md)과 [검증 요약](workspace/v05/VERIFICATION_v05.json)입니다. 아래는 남은 과제의 **제안 우선순위·완료 기준**이며, 구현 완료나 사용자 승인 일정이 아닙니다. CRM 전체 운영·발송·고객 관리로 범위를 넓히지 않습니다.

권장 순서: **기존 감사 잔여 보완 → 실제 실무자 과업 검토 → 설계 진입 흐름 → 조건 확인·데이터 준비 개선**. 설계 진입 초안과 사용자 과업 준비는 병행할 수 있습니다. 새 통계 방법과 CRM API 연동부터 늘리지 않습니다.

## 이미 완료한 것 — 다시 미구현으로 분류하지 않기

| 영역 | 현재 제공/확인 |
|---|---|
| 입력 | CSV/표/고정 문장 형식, 직접 열 연결, 명시적 A/B 값 변환, 행·숫자 검증 |
| 결과 | 전체·지원 집단 분석, 직접 효과 차이의 제한, 요약 우선 배치, 중립 A/B 카드, 상세 펼침 |
| 판단 | 검토 방향·근거·확인 조건·재검토 시점, 자동 승인과 분리 |
| 저장/공유 | 형식 4 저장, 2/3/4 복원, 집계만 보관, 범위 확인 후 HTML/PDF |
| 최신성 | 늦은 입력·해시 취소·인쇄 스냅샷·자체 저장 복원에 대한 수정 회귀 |
| LLM | 동의 후 실제 설명 연결. 수치 계산은 엔진, 전송은 최소 판정 상태 |

v0.5의 새 흐름 37개, 기존 흐름 43개(실제 LLM 포함), 이전 문제 회귀 22개, 맥락 19개, 연결 모듈 12개 및 스키마 27개 그룹을 확인했습니다. 별도 압축 해제본에서도 새 흐름 37개를 재실행했습니다. 합산해 독립 실험·사용자 수로 표현하지 않습니다. 실제 CRM 사용성·성과, 전체 접근성·보안 인증은 아닙니다.

## P0 — 다음 시범판 전에 권장하는 범위가 작은 보완

### R01. LLM 오류 코드 허용목록과 전송 보증 문구
- **상태:** 미착수. v0.4 감사 PC-02의 조건부 검증 공백이 v0.5 서버에도 남아 있습니다.
- **근거:** `server.py`는 `issues`를 식별자 정규식으로만 검사합니다. 정상 앱 경로의 원자료 전송을 발견한 것이 아니라, 같은 origin의 임의 클라이언트가 코드를 꾸며 보낼 때 의미를 제한하지 못하는 경우입니다.
- **작업:** 엔진 버전에 연결된 알려진 코드만 허용하고 알 수 없는 코드는 CLI 실행 전에 거절합니다. `raw_data_sent=false`를 모든 요청 내용의 비식별 인증처럼 쓰지 않도록 응답·문구를 정리합니다.
- **완료 기준:** 정상 코드 수용, 식별자처럼 생긴 미등록 코드 거절, 거절 요청의 CLI 미실행을 자동 검사. 새 원문·이름·숫자를 페이로드에 추가하지 않기.
- **예상 규모:** 낮음~중간. 일정 확정이 아닌 상대적 추정.

### R02. 복합 제한·빈 집단·invalid 설명 구체화
- **상태:** 미착수. 원 감사 N-01~N-03. v0.5는 `narrative.js`를 바꾸지 않았습니다.
- **작업:** 사후 탐색과 집단 결측이 동시에 있으면 두 제한을 함께 안내합니다. 빈 집단은 해당 군 분모 0을 구체화합니다. invalid는 입력 수정 전 수치 사용 불가로 안내하고 기술 통계가 있는 것처럼 말하지 않습니다.
- **완료 기준:** 세 고정 재현 입력의 문구 회귀, 전체/집단/직접 차이/보고서 일관성 검사. 엔진 수치와 판정은 불변.
- **예상 규모:** 낮음.

### R03. 원본·정규화·복원 집계의 해시 종류와 계보
- **상태:** 미착수. PC-03은 정적 관찰에 근거한 개선 사항이며 인증 우회가 재현된 것은 아닙니다.
- **작업:** 원본 입력의 해시와 열 연결 후 계산 표, 복원된 집계 표의 해시를 구분합니다. `원천 해시` 하나로 서로 다른 자료를 대표하지 않도록 종류·연결·변환 버전을 정의합니다. 원자료 자체는 저장하지 않습니다.
- **완료 기준:** 원본 → 열 연결 → 집계 저장 → 복원 → 재분석 → 재공유를 왕복해 각 해시의 대상과 검증하지 못한 범위를 설명할 수 있기. 구형 파일의 없는 계보는 만들지 않기.
- **예상 규모:** 중간. 파일 형식 변경 필요 여부를 먼저 결정.

## P1 — 제품 가치를 확인하고 핵심 진입을 완성

### R04. 실제 CRM 실무자의 동일 과업 수행 검토
- **상태:** 미착수. 현재까지 합성 자동화·가상 페르소나 검토입니다.
- **대상 제안:** 소수의 CRM 실무자와 통계 초보자. 실제 참여자 모집·일정·데이터 반출은 별도 동의가 필요합니다.
- **과업:** 다른 열 이름 연결, 분모·성공 의미 확인, 보류/보정 결과 설명, 집단 차이 해석, 판단 기록·공유, 저장·복원.
- **기록:** 막힌 위치, 도움 요청, 잘못 읽은 판정, 조건을 모르는데 체크하는 행동, 공유에서 빠진 항목. 기존 방식과 비교할 때는 같은 과업·평가기준을 사용합니다.
- **완료 기준:** 실제 관찰 기록과 오류/개선 목록, 그에 연결된 다음 수정안. 시험 전 성공률·시간 절감·구매 의사를 창작하지 않기.
- **예상 규모:** 준비는 중간, 진행은 참여자 확보에 의존.

### R05. 데이터가 없는 사용자의 설계 시작 흐름
- **상태:** 제품 핵심 목표이나 전체 구현은 미완료. 현재 안내는 규칙 기반입니다.
- **흐름:** 상황 설명 → 목적 확인 → A/B 후보 제안 → 지표·배정·판정 계획 추천 → 사용자 수정·확인 → 외부 실험 → 분석.
- **작업:** 한 번에 중요한 질문 하나로 제약·대상·성공 사건·측정 가능성·위험을 확인합니다. 제안과 사용자 확정 상태를 분리하고, 후보·계획을 결과 입력과 같은 실험 기록으로 저장합니다. 결과가 없으면 실제 효과나 승자를 만들지 않습니다.
- **완료 기준:** 데이터 없는 계획 저장 → 복원 → 후속 집계 연결까지 일관성 유지. 추천은 확인 전 제안이며 계획 변경 시 영향을 받는 확인 상태를 무효화. 기본 흐름 1~4를 채팅 밖 구조화 기록으로 보존.
- **주의:** 자유 문장 파싱 범위를 확대하는 것과 대화형 계획 설계를 혼동하지 않습니다. 표본 수·기간의 자동 산정은 별도 입력·계산 계약과 검증이 먼저입니다.
- **예상 규모:** 높음. 질문 구조/화면 → 규칙 초안 → 동의 기반 LLM 연결 순서 권장.

### R06. 분석 조건을 초보자가 확인할 수 있는 문답
- **상태:** 현재 무작위·독립·관측·고정 종료는 사용자 체크이며 독립 인증이 아닙니다.
- **작업:** 확인됨/아님/모름과 기록 근거, 고객·가구·지점 등 배정 단위, 반복 참여, 관측 기회와 누락, 결과를 본 뒤 종료 변경을 구체적으로 묻습니다. 데이터에서 확인 가능한 부분과 사용자 진술을 분리합니다.
- **완료 기준:** 모름/미지원 조건에서 추론을 열지 않고 기술 통계·미지원 이유를 구분. 체크만 하면 실험 타당성을 증명한 것처럼 읽히지 않기.
- **예상 규모:** 중간. 저장 형식과 기존 가정 무효화 계약을 함께 검토.

## P2 — 반복 사용의 부담과 실행 환경 개선

### R07. 데이터 준비·연결 재사용과 CRM 내보내기 예제
- **상태:** 일반 열 연결은 완료. 파일별 반복 설정과 공급자별 예제는 후속입니다.
- **작업:** 자주 쓰는 별칭, 한국어 오류 복구, 관측 상태 별칭을 놓치지 않는 안내, 원자료 없는 합성 내보내기 예제를 제공합니다. 공급자별 분모·관측 창·승자 선택/잔여 발송을 확인하고, 모든 내보내기를 동일한 고정표본 실험으로 취급하지 않습니다.
- **완료 기준:** 원본 → 연결 → 집계의 손실·중복·미성숙 경계 시험. 연결 설정 재사용은 사용자의 선택 아래 최소 구조만 보관하며 원시 값·개인정보를 섞지 않기.
- **범위 밖:** 고객 목록 관리, 실제 CRM API 발송·배포와 운영 자동화.
- **예상 규모:** 중간.

### R08. 배포·성능·접근성·회귀 실행의 정리
- **상태:** 로컬 Python 실행과 ZIP 압축 해제본은 검사했습니다. 광범위 환경 검증·일괄 회귀 진입점은 남아 있습니다.
- **작업:** Python/CLI 없는 환경, 시작·종료·포트·오류 복구, 약한 기기에서 대용량 입력/취소, 키보드와 스크린리더 흐름, 긴 한국어·다수 열·큰 글자 확대를 확인합니다. 필수 의존성과 오프라인 회귀 실행 절차를 정리합니다.
- **완료 기준:** 지원 환경 표와 실제 실행 결과. 실제 LLM 검사는 비용·인증이 필요한 별도 선택 경로로 두고 기본 자동화에는 합성 입력만 사용. 성능 수치는 측정 환경·범위와 함께 보고.
- **예상 규모:** 중간~높음. 공개 호스팅·계정 시스템 도입은 별도 결정.

## P3 — 실제 수요를 확인한 뒤 확장

### R09. 표본 계획·사업 기준·보호 지표와 추가 통계
- **상태:** 현재 비용·보호·사업적 충분성은 자동 판정하지 않습니다.
- **작업 후보:** 최소 관심 효과/기준율 기반 표본 계획, 배정 비율 이상 점검, 보호 지표 검토. 추가 지표·복잡한 설계는 필요성이 확인된 것만 개별 계약·독립 수치 기준을 만든 뒤 도입합니다.
- **완료 기준:** 가정·지원 범위·입력/판정 계약·고정 기준값·차단 경계와 통계적 우위/사업적 충분성/실제 승인 구분을 모두 검증.
- **지금 하지 않을 일:** 시간·금액·반복/군집·순차 결과를 기존 이항 엔진에 억지로 넣기, 자동 고객 적용, 무제한 세분화, 기능 수를 늘리는 범용 CRM 확장.
- **예상 규모:** 높음. R04 관찰과 설계 계약 후 선택.
