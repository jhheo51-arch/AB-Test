# 가상 페르소나 기반 설계 평가

평가일: 2026-11-17 (Asia/Seoul). **가상 페르소나와 문서 기반 작업 시뮬레이션**이다. 실제 사용자 인터뷰·사용성 시험·구매 의사 확인이 아니며, 작동하는 제품을 사용한 평가도 아니다. 점수나 시장 효과를 실증치처럼 제시하지 않는다.

## 1. 페르소나: 김서윤
- 가상 JH Motors의 CRM 마케터, 경력 2년이라는 설정.
- 업무: 시승 전 잠재고객 캠페인, 마케팅 수신 동의·제외 조건, 시승 예약/완료 결과 취합, 주간 의사결정 보고.
- 환경 가정: 기존 캠페인 시스템과 스프레드시트가 있으며 고객별 배정·결과를 가명 키로 내보낼 수 있음. 분석 담당자는 필요할 때 검토하지만 상시 전담하지 않음.
- 권한: 캠페인 설계·분석 요청·보고 초안. 전면 확대는 팀장 승인, 고객보호·운영 제약은 관련 담당자 확인.
- 현재 문제: 예약 증가를 시승 완료 효과로 바꾸어 보고하기 쉬움. 지점 데이터 지연·미연결과 0을 구분하기 어려움. 경영진은 확대 여부를 묻지만 통계 결과만으로 답하기 어려움.
- 원하는 진전: 현재 자료로 가능한 주장·불가능한 주장과 다음 확인 사항을 한 장으로 정리.
- 도입 장벽: CSV 준비·열 매핑 부담, 실제 개인정보 반출 승인, 계산 신뢰, 기존 플랫폼과 중복 작업.

가정이 바뀌어 데이터 반출이 불가능하거나 캠페인 배정 자체가 기록되지 않는다면 이 페르소나는 초기 고객으로 적합하지 않을 수 있다.

## 2. 관통 사례
기존 저장소의 합성 JH Motors 실험을 사용한다. A 차량 가치 안내 대 B 시승 편의 안내이며 무발송 대조군은 없다. 주지표는 배정 후 28일 내 시승 완료 / 전체 배정 고객이다. 전달 실패를 제외하지 않는다.

참고 기록: `e-book/workbook/workbook_v02.md`, `e-book/analysis/v02/verified_analysis.json`.
원격 문서에 기록된 예: 시승 완료 A 298/3,269, B 332/3,286, 차이 약 +0.99pp, Newcombe 95% 구간 [-0.44,+2.42]pp, 양측 pooled z p 약 0.1750. 예약에는 개선 신호가 있지만 진단 지표이다. 수신 거부의 사전 허용 한계와 실제 계약·매출·마진은 없다.

이 수치는 **기존 합성 분석 기록의 인용**이며 이번 평가에서 계산 엔진을 재실행하거나 현재 도구에서 얻은 결과가 아니다. 개별 p값과 구간은 지표별 미보정 분석이라는 기존 문서의 한계도 유지한다.

## 3. 여섯 작업으로 평가
| 작업 | 페르소나의 상황·요구 | 제안 구조의 대응 | 평가와 남은 장애 |
|---|---|---|---|
| 문제 정의 | 예약과 시승 완료 중 무엇을 결정에 쓸지 혼동 | 고객 여정·주지표·진단 지표를 분리 | 방향 적합. 기본 입력이 너무 길면 이탈할 수 있음 |
| 설계 기록 | 이미 끝난 실험을 입력할 수도 있음 | 사전/사후·작성 시점·변경 이력 구분 | 필요. 사후 업로드를 사전 계획처럼 보이지 않게 해야 함 |
| 데이터 준비 | 배정·예약·시승 원장의 정의와 키가 다름 | 표준 형식·열 매핑·결측 의미 확인 | 최대 마찰. ‘CSV만 넣으면 끝’이라고 홍보하면 안 됨 |
| 신뢰성 확인 | 미성숙 28일 추적과 누락 기록을 0으로 오해 | 고객별 관측 창·연결률·품질 영향 보고 | 중요 가치 가설. 자동 확인 가능 정보와 사용자 확인을 분리해야 함 |
| 결과 해석 | 예약 증가만 보고 B 승리라고 보고하려 함 | 주지표 구간·진단 지표·가드레일 상태 병기 | 방향 적합. 복잡한 수치를 업무 문장으로 설명할 필요 |
| 결정 보고 | 팀장이 확대·매출 효과를 질문 | 주장 가능한 범위·미확인 원가·안전·용량·승인 기록 | 가장 유용할 가능성. 데이터 없는 매출 수치를 만들면 실패 |

이 평가는 기획의 적합성에 대한 추론이며 실제 성공률·시간 절감·구매 의사를 측정하지 않았다.

## 4. 반드시 작동해야 할 반례
### A. 예약이 늘었는데 주지표는 불확실
- 잘못된 출력: ‘B안 승리, 전면 확대’.
- 필요한 출력: ‘예약 증가 신호와 시승 완료 효과의 불확실성을 구분하십시오. 주지표를 사후 교체하지 않습니다.’
- 다음 행동: 운영 용량·미완료 이유·고객별 성숙도를 확인하고 사전 종료 규칙에 따라 후속 실험 검토.

### B. 수신 거부 증가가 유의하지 않음
- 잘못된 출력: ‘안전성 확인’.
- 필요한 출력: ‘사전 허용 한계가 없어 안전 판정은 미확인입니다. 비유의성은 무해함의 증명이 아닙니다.’
- 다음 행동: 고객보호 기준과 필요한 검증 절차를 합의.

### C. 계약·매출 열이 없음
- 잘못된 출력: 시승 증가를 임의의 계약률·LTV로 환산해 ‘예상 매출 확정’.
- 필요한 출력: ‘이 자료는 시승 지표만 다룹니다. 계약·매출·이익 효과는 추정하지 않았습니다.’
- 다음 행동: 연결 가능한 거래 자료·가정·검토 책임자를 요청. 가정 시나리오는 관측 결과와 분리.

### D. 28일을 추적하지 않은 고객이 있음
- 잘못된 출력: 모든 미기록 시승을 0으로 계산.
- 필요한 출력: ‘관측 미성숙·미연결·사건 없음이 구분되지 않아 현재 분석을 제한합니다.’
- 다음 행동: 자료 기준시점과 관측 정책을 확인. 성숙 고객만 사후 선별하는 임의 해법도 자동 적용하지 않음.

### E. 클릭 로그에 장애가 있음
- 잘못된 출력: 모든 분석 무효 또는 모든 분석 정상.
- 필요한 출력: ‘클릭 추정은 제한됩니다. 독립 시승 원장의 영향은 별도 확인합니다.’
- 다음 행동: 지표 원천별 영향 지도와 배정 기준 분모 확인.

### F. 실험이 이미 종료됐는데 유의할 때까지 연장 요청
- 잘못된 출력: 추가 표본을 모으면 승리할 것이라고 안내.
- 필요한 출력: 사전 종료 규칙·추가 정보의 가치·방법 지원 범위를 확인하고 새 실험/적절한 설계로 분리.

## 5. 잠정 평가
### 채택할 가치가 있을 수 있는 부분
- 기존 발송 툴을 교체하지 않고 보고·검토의 빈틈을 메운다는 가설.
- 결과표보다 주지표·품질·사업 제약을 연결한 설명.
- ‘보류’에 필요한 증거·담당자·재검토 조건을 붙이는 구조.
- 실제/합성·사전/사후·관측/추정·탐색/확증을 분리하는 기록.

### 현재 가장 큰 약점
- 제품이 아직 없어 계산·입력·설명·보안·속도가 검증되지 않음.
- 기존 플랫폼에도 통계·품질 점검·세그먼트·보고 기능이 있어 이 기능 이름만으로는 차별화가 약함.
- 데이터 준비 비용이 보고서 작성 편익보다 클 수 있음.
- 단순 이항 A/B는 시작 범위로 적절하지만, 실제 기업·딜러·가구 간섭과 매출·장기 효과를 다루지 못함.
- 자동 진단은 로그에 없는 원인을 발견해 확정할 수 없음.

### 추천 포지셔닝
‘범용 실험 플랫폼 대체재’보다는 **CRM 실무자의 증거 검토·판단 기록을 돕는 보조 도구**로 시작한다. 발송·배포가 필요하면 기존 플랫폼을 사용하고 결과와 실험 계약을 연결한다. 독립 통계/실험 역량을 갖춘 팀에는 기존 도구의 기능과 중복될 수 있다.

## 6. 다음 실제 검증
- 실제 잠재 사용자가 가명 데이터 준비 → 설계 입력 → 품질 경고 해석 → 보고서를 검토하게 한다.
- 본인 현재 방식(스프레드시트/기존 플랫폼)과 같은 과제로 비교한다.
- 관찰 항목: 준비에 필요한 도움, 오해한 경고, 잘못된 승리 선언, 비유의성의 안전 오해, 원천·가정 추적 가능성, 재작업, 민감정보 노출, 사용·보안 승인 장벽.
- 성공 기준은 실험 전에 정한다. 지금 작업 성공률·시간 절감·지불 의사를 숫자로 만들어 제시하지 않는다.
- 새 도구의 존재 이유가 확인되지 않으면 기능을 늘리기보다 사용 사례를 좁히거나 기존 플랫폼용 보고·검토 레이어로 축소한다.
