# 실행 환경·입력 복구 점검 기록

> 이 문서는 288d166 기준 최초 R08 수정의 역사적 기록입니다. 원본 검증·ZIP은 부모의 로컬 커밋 b62323b와 scratch 백업에 보존합니다. 현재 확대 판단/schema 8을 포함한 a0b506 기준 통합은 [현재 통합 기록](../integration-evidence/IMPLEMENTATION_NOTES.md)과 상위 검증 요약을 보세요. 현재 R08 기능 재실행 장부와 최초 수정 전 기록을 구분합니다.

## 실증 범위와 근거

검사는 합성 자료를 사용하는 자동화입니다. 사람 관찰과 실제 모델 호출은 각각 0건입니다. [현재 브라우저 장부](BROWSER_VERIFICATION.json), [실행 환경 장부](ENVIRONMENT_VERIFICATION.json), [수정 전 브라우저 장부](PRE_FIX_BROWSER.json), [수정 전 실행기 장부](ENVIRONMENT_BASELINE.json)를 구분합니다. 소스와 ZIP 추출본의 반복 실행은 같은 고유 범위의 재검사이며 검사 수에 더하지 않습니다. 전체 고유 수는 상위 검증 요약이 실제 로그에서 집계합니다.

| 영역 | 실제 수행 | 해석 한계 |
|---|---|---|
| 실행기 | Windows Python과 CMD 실행, 한글·공백 경로, 브라우저 자동 열기 생략, 동시 두 인스턴스, 명시 포트 충돌, 종료 후 접속 거절·같은 포트 재시작, 빠진 핵심 자산 | 자동 종료는 소유 프로세스 트리 종료이며 실제 사용자의 창 닫기 관찰이 아님 |
| Python 의존성 | 설치된 Python, 설치된 `py -3` 대체 경로, 격리 PATH에서 둘 다 없는 상황 | 실제 Python 미설치 PC는 아님. 격리 PATH 실험만으로 설치 일반성을 보장하지 않음 |
| 키보드 | Tab 탐색, 붙여넣기, Enter 준비·분석, 방향키 조건 선택, Space 숫자/공유 확인, 판단 작성, 도움말 열기·Escape | 보이는 제어만 사용. 파일 선택은 Playwright `set_input_files`이며 네이티브 OS 파일 창 검사가 아님 |
| 도움말 | 실제 MP4 재생 후 Escape 정지, 포커스 복귀, 폼·결과·템플릿 동의·가져온 CRLF/CR 근거 원문 정확 대조 | 재생 시작은 미디어 API를 사용. 실제 키보드 미디어 컨트롤 전체 시험은 아님 |
| 확대·좁은 화면 | 폐기용 Chrome 프로필의 실제 기본 확대를 200%로 설정·API 재조회하고 입력→분석 실행, 별도 CSS `zoom:2` 1440px 및 390/320px 100% 화면, 실제 PNG·HTML·접근성 트리 | deviceScaleFactor가 아님. 실제 NVDA/Narrator 음성 사용·사람 접근성 검사는 하지 않음 |
| 큰 입력 | 정확히 2MiB·50,000행 개인형, 총 행/분모 보존, 모름 조건 제한 및 확인됨 조건의 실제 계산, 바이트 초과 읽기 전 거절·50,001행 분석 차단 | 바이트 상한 정합 검사를 위해 첫 합성 ID를 패딩. 일반 CRM CSV의 대표 성능 자료가 아님 |
| 취소·복구 | 실제 파일 읽기·실제 SHA 완료 시점만 지연한 뒤 새 입력, 이전 finally가 새 작업을 풀지 못하는지 확인; 실제 Worker 분석 요청 직후 취소 후 새 Worker 결과 | 타이밍 통제 재현이며 발생 빈도·모든 경합의 증명은 아님. 가짜 해시·Worker 응답을 만들지 않음 |
| 오류 복구 | 잘못된 UTF-8/크기 파일, 잘못된 프로젝트/템플릿의 기존 유효 데이터 보존, 잘못된 CSV 문법의 분석 차단, 이후 정상 입력·분석·실제 저장·보고서 다운로드 | 사용자가 직접 붙여넣어 교체한 CSV는 문법 오류여도 편집된 입력 자체를 되돌리지 않음 |

환경 장부는 실행한 인터프리터의 `sys.version`, Windows 플랫폼, CPU/논리 CPU, 실제 메모리 스냅샷과 관측 시각을 기록합니다. Chrome 버전은 브라우저가 실제 반환한 값입니다. 메모리 부하가 높은 관측도 특정 성능 문제의 원인이나 모든 약한 기기의 대표성으로 해석하지 않습니다. 단계별 `read`는 실제 File API, `prepare`/`analyze`는 실제 Worker 요청→응답입니다. UI 초 단위 시간에는 자동화 전달·DOM 검증·렌더링·브라우저 왕복 시간이 포함되어 Worker 자체 시간과 다릅니다. 지원 상한을 늘리거나 대기 상한 조정을 성능 개선이라고 주장하지 않았습니다.

## 재현한 결함과 최소 수정

1. **점유된 명시 포트에 두 실행기가 같은 URL로 시작**했습니다. Windows의 주소 재사용으로 발생한 실제 두 번째 시작을 원장에 보존했습니다. 서버를 Windows 독점 바인딩으로 바꾸고 실행기에 포트 사용 중/사용 불가 안내를 추가했습니다. 다른 빈 포트로 조용히 이동하지 않습니다.
2. **핵심 자산 `conditions.js`가 빠져도 정상 URL을 광고**했습니다. 필수 UI 모듈·테마·글꼴·미디어를 명시적으로 사전 확인하고 파일 이름을 포함해 종료합니다. 현재 회귀는 조건·설계·템플릿 모듈을 각각 제거해 확인합니다.
3. **`launch.cmd`가 `--no-browser`·`--port`를 버렸고**, Python이 없는 격리 PATH에서 설치 안내 없이 명령 오류와 pause만 출력했습니다. 인자를 전달하고 실제 설치된 `py -3` 대체 경로, Python 공식 설치 URL을 포함한 오류 종료를 추가했습니다. 모든 자동화 subprocess의 stdin은 DEVNULL이고 대기는 유한합니다.
4. **2MiB 초과 CSV 파일을 거절하면서 기존 결과·조건을 먼저 비웠습니다.** 파일 읽기·fatal UTF-8 디코드·기존 엔진의 CSV 문법/행 상한 검사를 스테이징하고 유효한 새 텍스트를 적용할 때만 기존 준비·결과·조건을 무효화합니다. 기존 데이터의 복구와 새 CSV에서 조건이 이어지지 않는 경계를 모두 검사합니다. 추가 재현에서 잘못 닫힌 CSV 인용부호 파일도 기존 입력·결과를 잃는 것을 확인했습니다(`CSV_SYNTAX_BASELINE.json`). 파일의 문법·행 상한은 적용 전 검사하고 역할/숫자/실험 품질은 기존 준비 단계에서 계속 검사합니다. 직접 붙여넣은 잘못된 문법은 기존 준비 오류로 차단하며 행 삭제/임의 수정은 하지 않습니다.
5. **STATUS의 수가 실제 실행 장부와 달랐습니다.** 공통 `tests/release_status.py`를 통해 검증 요약 생성 후 장부 기반 수만 동기화합니다. 소스의 `tool/STATUS.json` 또는 ZIP 내부 소유 STATUS만 대상이고 대상이 없으면 생성하거나 상위의 무관한 STATUS를 건드리지 않습니다. 다른 상태 필드와 사람 관찰 0은 유지합니다. 낡은 STATUS/현재 요약 수 거절, 임의 필드 보존, 대상 없음·상위 파일 보존을 격리 복사본에서 검사합니다.

엔진 수학, Worker 코드, 저장 형식 7, 조건·설계·개인정보 계약, 원문 CRLF/CR 보존, 헤더 지문과 이전 경계 수정은 보존합니다. 기존 160.16초 영상·자막·타임라인·글꼴을 수정하지 않았습니다. 새 UI 색 조합이나 UX 재설계·새 통계 기능은 추가하지 않았습니다.

## 그대로 남긴 한계와 최초 검사 자체의 문제

- Playwright의 큰 문자열 fill이 유한 시간 내 끝나지 않은 기록은 `PASTED_FILL_TIMEOUT.json/.log`에 그대로 남겼습니다. 추가 행 상한 주입은 DOM 값/input 이벤트 자동화로 바꾸고, 실제 파일 상한과 별도의 키보드 입력 경로는 유지했습니다. 대기 상한을 늘리거나 성능을 고쳤다고 주장하지 않습니다. 실제 Chrome 확대는 별도 일회용 프로필의 settingsPrivate 기본 확대 API로 2를 설정하고 다시 읽습니다. CSS zoom=1, DPR=2와 실제 inner/outerWidth 변화를 함께 확인하며, PNG는 확대 시 Playwright 전체 페이지 캡처의 CSS/장치 좌표 혼동을 피하도록 CDP의 실제 viewport를 캡처합니다.
- **320/390px 화면에 CSS 200%를 동시에 적용한 추가 관측에서는 가로 넘침**이 남았습니다(실제 scrollWidth는 장부 참조). 이 조합은 유효 폭 약 160/195 CSS px인 추가 스트레스 관측입니다. 320/390px 100%와 데스크톱 200% 통과를 이 조합의 통과로 바꾸지 않습니다. 보편적 접근성 합격이나 이 초협폭 조합 지원을 주장하지 않으며, 이번 변경에서는 추정 UX 전면 개편을 하지 않았습니다.
- 최초 자동화는 판단 textarea에 Space를 먼저 입력하고 앞 공백 없는 문자열을 기대했고, 2MiB fixture 생성에서 ID 길이를 잘못 잡았으며, JS 평가 문자열의 줄바꿈 escape가 잘못되었습니다. 이는 앱 결함이 아니라 검사 코드 문제입니다. 최초 기록은 `initial-audit/`에 별도 보존하고, 실제 앱 결함의 수정 전 기록은 별도 원장에 유지합니다.
- 첫 전체 통합의 환경 검사에서 netstat 빈 줄을 먼저 인덱싱한 검사 코드 오류가 발생했고, 예외 시 서버 종료 전 임시 폴더 정리가 시도되어 Windows 디렉터리 잠금 오류도 함께 기록되었습니다. `INITIAL_INTEGRATION.json`과 `INITIAL_ENVIRONMENT_FAILURE.log`를 보존했습니다. 빈 줄을 먼저 거르고 소유 프로세스 종료/포트 확인 후 폴더를 정리하도록 검사만 고쳤습니다. 앱 성능/엔진 결함으로 세지 않습니다. 이 실행 환경에서 netstat 목록으로 해당 실행기의 PID/수신 주소를 회수하지 못한 추가 한계도 `NETSTAT_PROBE_LIMIT.json`에 남겼습니다. OS 전체 목록을 추정하지 않고 같은 AppServer의 실제 소켓 API `getsockname()`으로 loopback 바인딩을 별도 확인합니다.
- 초기 도구 프로세스가 시스템 TEMP를 상속한 것을 발견했습니다. 처음 만든 로컬 백업을 활성 프로필 scratch로 옮겼고 이후 모든 실행에서 TMPDIR/TEMP/TMP를 그 scratch로 명시했습니다. 로컬 기준 백업은 배포 ZIP에 포함하지 않습니다.
- 실제 약한 기기, CPU throttle, 다른 OS, 실제 Python 미설치 시스템, NVDA/Narrator 음성 읽기, 실제 사람 과업, 실제 모델 호출은 수행하지 않았습니다. 접근성 트리는 실제 보조기술 사용과 구분합니다.

## 패키지 경계

소스 검증 뒤 명시 허용목록으로 ZIP을 만듭니다. 포장된 STATUS/요약·런타임 해시를 검증하고 CRC·모든 멤버 바이트를 소스와 대조합니다. 한글·공백 scratch 경로의 별도 추출본에서 같은 전체 회귀와 실행기 검사를 다시 수행합니다. 소스·포장 당시 요약·추출 재실행 요약을 구분하며 생성 시각 차이를 바이트 불일치로 오판하지 않습니다. 소스와 추출본 Markdown 링크도 각각 검사합니다. ZIP 자체 해시와 추출 결과는 자기 참조를 피하도록 패키지 바깥 배포 장부에 기록합니다.
