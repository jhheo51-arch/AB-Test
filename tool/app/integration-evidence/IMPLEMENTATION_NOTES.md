# 공개된 확대 판단 기능과 실행 환경 수정의 통합 검증

## 현재 기준과 과거 기록

현재 통합 기준은 `a0b506c2e9e199a3d00832b0411a49da35c3302d`입니다. 부모가 보존한 원격 기준 ZIP의 SHA-256과 각 Git blob 식별자를 읽기 전용으로 대조해 [기준 장부](BASELINE.json)를 만들었습니다. 엔진, 저장 스키마, `rollout.js`, index와 기존 확대 판단 스타일은 **이 최신 기준의 바이트**를 보존합니다. 오래된 엔진이나 schema를 복원하지 않았습니다.

`288d166f81f1a2872864bf2a7bd862fd309d4bc1` 기준의 최초 R08 검증은 과거 기준입니다. 부모가 보존한 로컬 커밋 `b62323bbf5e72b707bef596be3cccb24b86dfe3e` 에서 최초 R08 앱·검증·ZIP을 보존합니다. 활성 scratch의 `r08_paused_rebase_backup/`은 이번 충돌 해결 전 자동 병합 코드와 이전 검증/ZIP을 담은 재개 스냅샷이며, 최초 R08 앱의 pristine 복사본이라고 주장하지 않습니다. 기존 조건/프로필 기준 JSON은 고쳐 쓰지 않았습니다. 현재 요약은 역사적 차이와 최신 upstream 바이트 보존을 별도로 기록합니다. Git stage/commit/rebase-continue/push는 이 작업자가 하지 않았습니다.

## 실제 확인한 충돌·상태 경계

- `launch.py`와 ZIP 제작기의 충돌은 어느 한쪽을 선택하지 않고 합쳤습니다. 필수 자산에 `rollout.js`와 R08의 조건·설계·프로필·글꼴·미디어를 모두 포함합니다. 배포에는 기존 실행·검사·상태 동기화 파일, 확대 판단 검사, 제공된 세 프로젝트 예제를 함께 담습니다.
- 자동 병합된 app/server를 읽고 R08의 파일 스테이징, fatal UTF-8, 문법/상한 사전 검사, Windows 독점 포트와 확대 판단 자산 제공이 함께 남는지 확인했습니다.
- [수정 전 결합 검사](COMBINED_BASELINE.json)에서 두 경계가 실패했습니다. 정상 새 CSV 파일 적용 후 이전 확대 판단의 운영 확인이 남았고, 대기 중 CSV 읽기보다 나중에 한 확대 판단 편집의 소유권도 보호되지 않았습니다. 잘못된 CSV의 크기·UTF-8·문법은 이미 기존 확대 판단·상태·메모·공유 확인·인쇄를 보존했습니다.
- 최소 수정으로 **성공한 새 CSV 파일을 적용하는 시점에만** 이전 확대 판단을 비우고 관련 공유/인쇄를 폐기합니다. 실패하거나 취소된 파일은 확대 판단을 건드리지 않습니다. 확대 판단을 직접 편집하면 대기 중인 입력 작업의 소유권을 취소해 늦은 파일 완료가 최신 편집을 덮어쓰지 못하게 했습니다. 엔진과 확대 판단 수학은 수정하지 않았습니다.
- 기존 upstream의 같은 작업 안에서 직접 입력한 CSV 집계와 별도로 입력한 확대 판단을 함께 보고서에 표시하는 경로는 그대로 검사합니다. 이 경로와 **새 CSV 파일로 자료 출처를 교체하는 경로**를 혼동하지 않습니다. 어떤 경로든 공유 확인은 다시 해야 하며 운영 확인은 실제 승인 인증이 아닙니다.
- 최초 결합 검사에서 CSV 전용 판단 textarea를 확대 판단만 있는 화면에서도 보인다고 가정한 검사 오류는 `COMBINED_INITIAL_HARNESS.json`에 보존했습니다. 숨은 제어를 강제 조작하지 않고 보이는 실험 맥락 메모로 검사했습니다.

## 실제 제공된 예제와 저장 형식

저장 엔진은 현재 schema 8을 지원합니다. 확대 판단이 있는 저장은 8이며 **CSV/계획만 있는 저장은 기존 7을 유지**합니다. 읽기는 2–8을 지원하고 이전 파일은 7로 정규화합니다. 8의 확대 판단은 입력값으로 판단/근거를 다시 계산합니다. STATUS와 검증 요약은 최대/native 8, CSV/계획 7, 확대 판단 8, 구형 읽기 범위를 자동 동기화합니다. 새 형식을 만든 작업이 아니라 이미 공개된 upstream 계약을 정합하게 설명한 것입니다.

소스에는 README가 안내하는 `examples/projects/` 세 파일이나 생성기가 없었습니다. 안내된 **실제 공개 release의 JSON 세 개를 그대로 다운로드**하여 바이트·출처·SHA를 [제공 입력 장부](PROVIDED_EXAMPLES.json)에 보존했습니다. 예제를 추정 생성하거나 운영 승인을 채우지 않았습니다. 기존 공개 실행 ZIP도 실제로 내려받아 CRC와 세 JSON 멤버를 검사했고 개별 release 입력과 바이트가 같았습니다(`PUBLISHED_ZIP_EXAMPLES.json`).

- `routine-service-original-hold.json`: 원래 가상 입력, 확대 보류.
- `routine-service-metrics-met-hold.json`: 수치 기준 충족, 운영 조건은 미확인, 확대 보류.
- `routine-service-edited-review.json`: 공개된 수정 가상 입력과 운영 확인 상태, 확대 검토 가능. 실제 승인 아님.

세 입력은 실제 브라우저 복원·재계산·schema 8 다운로드로 대조합니다. schema 7 복원이 이전 확대 판단을 비우는 경계와 잘못된 schema 8의 원자적 거절도 검사합니다. 원래 독립 수치 fixture와 엔진 게이트를 변경하지 않고 재실행합니다. 추가 통계 기능이나 새로운 사업 승인을 만들지 않았습니다.

## 검사·패키지·한계

[현재 결합 검사](BROWSER_VERIFICATION.json)는 위 상태 경계를 실제 Chrome에서 확인합니다. upstream `verify_rollout.py`의 기존 단언을 유지한 채 1440/375px 흐름 두 그룹을 장부에 기록합니다. 두 그룹은 개별 단언 수가 아닙니다. R08·조건·설계·프로필·원문/계보·PDF·기존 수치 회귀도 전체 재실행합니다. 각 실행의 실제 수는 상위 `verification.json`과 STATUS에서 확인하며 소스/ZIP 반복은 고유 범위에 더하지 않습니다.

ZIP은 새 요약 이후 명시 허용목록으로 제작하며 모든 멤버의 현재 소스 바이트와 CRC를 대조합니다. 한글·공백 scratch 경로의 별도 추출본에서 같은 전체 검사와 실행기를 다시 수행합니다. 포장 당시 요약과 추출 재실행 요약은 구분하고 소스/ZIP의 Markdown 경로도 검사합니다.

기존 160.16초 영상은 R05/R06 설계·조건·분석 시연으로 바이트를 유지했으며 새 확대 판단 전용 시연을 제작한 것은 아닙니다.

실제 모델 호출과 사람 관찰은 0건입니다. NVDA/Narrator 음성, 실제 Python 미설치 PC, 실제 약한 기기와 다른 OS는 이번 검사 범위가 아닙니다. 이전 R08에서 기록한 CSS 초협폭 추가 스트레스 가로 넘침도 해결했다고 주장하지 않습니다. 실제 Chrome 200% 확대와 별도 좁은 화면 검사, AX 트리와 실제 보조기술 사용을 구분합니다.
