# A/B 테스트 작업실

CRM A/B 테스트의 설계 초안·데이터·결과·한계·판단 기록을 연결하는 로컬 앱입니다. 이 폴더는 현재 사용하는 앱 한 벌입니다. 이전 판과 수정 이력 묶음은 로컬에서만 관리합니다.

## 실행

Windows에서 Python 3가 설치된 상태로 `launch.cmd`를 실행하세요. 또는 이 폴더에서 `python launch.py`를 실행합니다. 표시된 `http://127.0.0.1:포트`를 Chrome/Edge에서 열고 실행 창을 유지하세요. HTML만 더블클릭해서는 Worker와 로컬 설명 브리지를 사용할 수 없습니다. 일반 사용에 Node는 필요하지 않습니다.

## 기본 계산과 선택 기능

- **CSV 확인·통계 계산·판단 기록:** LLM 없이 사용합니다. Python과 브라우저로 실행할 수 있으며 모델 인증이 필요하지 않습니다.
- **LLM 설명:** 별도의 Hermes CLI 설치와 `mira` 프로필, 사용 가능한 모델 연결·인증이 필요합니다. 기존 연결을 사용하는 선택 기능이며 ZIP에 Hermes나 인증정보는 포함하지 않습니다. 설정되지 않았거나 연결에 실패해도 로컬 계산은 사용할 수 있습니다. 모델 호출 비용은 연결한 서비스 조건에 따릅니다.
- **자유로운 자연어 설계 대화:** 아직 제공하지 않습니다. 현재 설계 안내는 규칙 기반입니다.

## 데이터 없이 계획부터 시작하기

왼쪽 **상황부터 설계** → **상황만 있어요 / 기존 계획 정리**를 선택하세요. 상황·목적·대상·기록 가능한 행동·위험·제약에 답한 다음 고정 후보를 선택하고 초안을 직접 수정합니다. 정해진 질문과 후보이며 실시간 AI 의미 분석이나 효과 예측이 아닙니다. 모르는 항목은 비워 두고 상태를 미확인으로 남깁니다.

대상·분석·적용 세그먼트는 별개입니다. 없는 고객 속성·표본·기간을 만들지 않습니다. 프로젝트 저장으로 빈 결과의 계획을 보관하고 새 페이지에서 복원할 수 있습니다. **같은 계획으로 CSV·결과 연결**은 목적·정책·지표·기간·대상을 유지하지만 분석 가정 확인은 해제합니다. 합성 예시는 별개 실험이며 계획을 비우기 전에 확인합니다.

계획을 바꾸면 현재 결과·공유 확인·인쇄 내용을 폐기합니다. 도구에서 결과를 본 뒤의 수정 표지는 남지만 외부 결과 열람·사전 등록이나 전체 수정 이력을 인증하지 않습니다. 설계 자유 서술은 프로젝트에 저장되며 자동 익명화되지 않습니다. 새 설계 전용 서술은 LLM 상태 페이로드나 기본 HTML/PDF에 자동 추가하지 않습니다. 기존 목적·정책·대상은 여전히 결과 보고서에 포함되므로 공유 전 확인하세요.

## 사용 흐름

1. 표를 붙여넣거나 CSV 파일을 가져옵니다. 첫 행은 열 이름이어야 합니다.
2. **데이터 확인하기**를 누릅니다. 열 이름이 다르면 원본 미리보기와 연결 초안을 보여 줍니다.
3. A/B 구분·성공 수·분모·집단 또는 가명 ID·성공 여부·관측 상태 열을 직접 확인합니다.
4. 원본 군 값도 확인합니다. 예를 들어 `control`은 A, `treatment`는 B로 명시합니다. 역할 연결과 군 값 연결은 서로 다릅니다.
5. 값을 수정하면 확인 체크가 해제됩니다. 다시 확인하고 **연결 적용하고 집계 확인**을 누릅니다.
6. 숫자·분모와 실제 설계 조건을 확인한 뒤 분석합니다. 모르는 조건은 모름으로 둡니다.
7. 요약 → 전체/지원 집단 결과 → 필요한 상세를 읽고, 검토 방향·근거·확인 조건·재검토 시점을 작성합니다.
8. 공유 범위를 확인한 뒤 HTML/PDF를 저장합니다. 보고서는 계산 근거를 펼쳐 출력합니다.

**설계 확인 사항 보기**는 기존의 짧은 규칙 기반 안내이며, 왼쪽 **상황부터 설계**의 고정 질문·후보 흐름과 별개입니다. 데이터 확인 버튼과도 다릅니다.

## 입력·계산·저장

- UTF-8 CSV/TSV 2MiB·50,000행, 연결 원본 최대 100열. 성능 보장은 아닙니다.
- 연결 추천은 제한된 별칭 사전이며 의미·실험 타당성 인증이 아닙니다. 모든 데이터 행을 유지하며 군 이름의 명시적 변환 외 값을 임의로 재코딩하지 않습니다.
- 오류·중복·미성숙을 조용히 삭제하지 않습니다. 개인형 원본 `observed` 열을 생략할 수 없으며, 다른 이름의 관측 상태도 올바르게 연결해야 합니다.
- 독립 고정 두 군 이항 결과에 집중합니다. Fisher 양측 검정, Wilson/Newcombe 명목 구간, 계획된 비교 가족의 Holm 보정을 사용합니다. 군별 합산 분모 200,000과 집단·설계 제한은 유지합니다.
- 저장 파일에는 계획·집계·판단·종류를 구분한 해시 기록을 담습니다. 원시 행·가명 ID·원본 미리보기·열 연결·LLM 출력은 담지 않습니다. 프로젝트 8MiB·50,000 집계 셀, 복원 CSV 2MiB 이하입니다.
- 화면·영상·배포명에는 제품 판 번호를 표시하지 않습니다. 구형 저장 파일을 읽고 코드 허용목록을 검증하는 내부 형식/엔진 식별자는 호환성과 안전을 위해 유지합니다.

## 안전한 해석과 설명

관측 순위, 통계적 우세, 사업적 충분성, 실제 적용 승인은 다릅니다. 기본 CSV 분석에서는 보호 기준과 비용을 판단 기록에 입력합니다.

### 방문 완료율과 수신 철회 기준으로 확대 판단

입력 화면에서 **방문 완료율과 수신 철회 기준으로 확대 판단하기**를 엽니다. 가상 정기점검 사례를 불러오거나 최초 배정 인원, 방문 완료와 수신 철회 고객 수, 기준, 수용량과 비용 확인 상태를 입력합니다. 두 수치는 동일한 배정 인원을 분모로 사용합니다.

- 방문 완료율 차이의 신뢰구간 하한이 최소 개선폭 이상이고, 수신 철회율 차이의 95% 신뢰구간 상한이 허용 상한 이하여야 합니다. 비교에는 반올림 전 수치를 사용합니다.
- 두 수치 기준을 충족해도 설계 조건, 센터 수용량, 비용 중 하나라도 미확인이거나 미충족이면 **확대 보류**입니다. 모든 조건을 충족하면 **확대 검토 가능**으로 표시합니다. 수용량과 비용은 사용자가 입력한 확인 상태를 따릅니다.
- 가상 정기점검 예시의 방문 완료율은 사전 지정 3개 비교를 보정한 약 98.33% Newcombe-Wilson 구간을 사용합니다. 수신 철회율은 별도의 탐색 지표로 95% 구간을 사용합니다. 단일 비교를 선택하면 방문 완료율에도 95% 구간을 사용합니다. [가상 사례의 계획과 결과](https://github.com/jhheo51-arch/jhheo51-arch/tree/main/portfolio/salesforce-mc-crm/service_revisit_demo)
- 이 화면은 브라우저에서 독립적으로 계산합니다. 이 입력과 판정은 기존 CSV 분석, 프로젝트 저장, 공유 보고서에 합쳐지지 않습니다.

LLM은 별도 동의와 버튼 요청 후 기존 Hermes `mira` 연결로 최소 판정 상태를 설명합니다. 수치를 계산하거나 원자료·원래 집단 이름·목적 원문·해시를 전송하지 않습니다. 서버는 알려진 엔진 오류 코드만 허용하고 미등록 값은 CLI 전에 거절합니다. 구조 검증은 임의 요청의 익명성·엔진 출처·사실 정확성 인증이 아닙니다. 연결 실패 시 계산 결과를 유지합니다. 인증정보는 앱에 포함하지 않으며 앱이 인증 파일을 직접 읽지 않습니다.

해시는 최초 입력 텍스트 UTF-8, 직전 계산 기록, 이번 계산 입력 CSV를 구분합니다. 파일 원본 바이트의 독립 인증이나 모든 중간 이력 보관이 아닙니다. 복원 기록은 원자료 재검증이 아니며 구형의 대상 미분류 값은 추정하지 않습니다. 해시는 진위·익명성을 보증하지 않습니다.

자유 서술은 자동 익명화되지 않습니다. 공유 전에 개인정보·기밀·소집단 정보를 확인하세요. CRM 발송/관리와 시간·금액·순차·군집 분석은 제공하지 않습니다.

## 줄바꿈·복원 경계

설계와 입력의 목적·성공 사건·기간·A/B 정책·대상은 여러 줄을 지원합니다. 직접 작성한 textarea는 LF를 사용하고, 가져온 CRLF·단독 CR·혼합 줄바꿈 맥락과 조건 근거는 해당 항목을 실제로 편집하기 전까지 원문을 보관합니다. DOM 표시만으로 편집 처리하지 않습니다. 편집하면 해당 항목을 새 화면 값으로 바꾸고 기존 결과·확인을 무효화합니다. 메모는 여전히 JSON에 민감한 원문으로 남으며 공개 HTML/PDF·모델 정보에서는 제외합니다.

CSV에서 겹치는 같은 군의 null/빈 집단(앞뒤 공백을 제거하면 같은 집단인 경우 포함)은 합산·삭제 없이 복원 전에 거절합니다. 현재 계보 없는 중복 해시도 거절하고, 구형 미분류 해시는 원래 범위로 유지합니다. [입력 계약](INPUT_CONTRACT.md)과 [경계 회귀](fix-evidence/semantic/BROWSER_VERIFICATION.json)를 참조하세요. 검토 문서는 공개 소스 링크와 ZIP 오프라인 기록의 실제 위치를 구분합니다. 현재 시연은 설계·조건 흐름을 설명하며 새 열 연결 템플릿 사용법은 아래 안내를 따릅니다.

## 검사와 다음 단계

현재 조건 검사는 `conditions_verification.json`과 `conditions-evidence/`에, 전체 검사 결과는 `verification.json`, `integration_verification.json`, `design-evidence/`, `tests/`, `evidence/`에 있습니다. 기존 화면·PDF 예시는 [GitHub 저장소의 검증 자료](https://github.com/jhheo51-arch/AB-Test/tree/main/tool/evidence)에 보존하며, 이 별도 예시 폴더는 ZIP에 포함하지 않습니다. ZIP의 정확한 포함 항목은 다운로드 허용목록을 따릅니다.

현재 실행 수·단위 그룹·별도 의미 회귀·브라우저 검사는 `verification.json`이 실제 통합 로그에서 집계합니다. 서로 다른 단위를 합치지 않으며 소스와 ZIP 반복 실행도 추가 고유 검사로 세지 않습니다. 기존 도움말 99검사와 원문 CRLF/CR 근거·선택 조건 보존 검사는 유지합니다. ZIP 제작은 소스·포장 직후·추출 실행 후 메타데이터와 실제 파일 해시를 대조합니다. 영상 자산과 엔진·조건·저장 형식은 이번 열 연결 작업의 별도 기준 해시로도 바이트 보존을 대조합니다.

`python tests/run_integration.py`는 임시 loopback 서버에서 Node와 실제 Chrome 합성 회귀를 실행하고 서버를 종료합니다. Playwright·Chrome, PDF 검사용 PyMuPDF, 전체 영상 디코드용 FFmpeg/ffprobe와 Node는 개발 검사 의존성이며 일반 앱 사용에는 필요하지 않습니다. 실제 모델을 호출하지 않습니다. 기존 모델 연결 실증은 과거 기준 기록이며 이번 통합의 재호출이 아닙니다. 합성 자동화는 실제 CRM 사용성·현장 효과·전체 접근성·보안 인증이 아닙니다.

첫 병렬 통합 검사에서 설계 이동 연결과 저장 형식 기대값 오류를 발견해 수정했습니다. 같은 실행의 초기 Worker 준비 대기 실패는 직렬 재실행에서 재현되지 않았으며 일반 성능 문제를 해결했다고 주장하지 않습니다. 최초 기록은 `evidence/integration-initial/`에 보존했습니다.

실제 사용자 과업 자료와 로드맵은 저장소의 도구 진입 문서를 확인하세요. 사람 과업 관찰은 0건이며 구현한 설계 진입도 실제 관찰로 후속 개선해야 합니다. AI 시연을 독립적인 사용자 검토로 계산하지 않습니다.

기존 제안 팔레트·글꼴·간격을 유지했습니다. 시연을 앱 안에 둔 이유는 입력을 잃지 않고 도움을 볼 수 있게 하기 위해서입니다. 영상 후에도 확인과 실제 판단은 사용자에게 남깁니다. 공개 토스 UI 원칙을 참고한 독자 구현이며 공식 TDS·전용 폰트·로고를 사용하지 않았습니다. Pretendard 라이선스는 `fonts/LICENSE.txt`에 보존합니다.



## 같은 CSV 형식의 열 연결을 다시 쓰기

1. 현재 CSV를 가져오고 집계형/개인형을 선택합니다. **열 연결·A/B 값 직접 수정**에서 역할·원본 군 값·제외 열을 확인하고 연결을 적용합니다.
2. **열 연결 템플릿 파일 재사용**을 펼쳐 저장 항목과 위험을 읽고 별도 내려받기에 동의한 다음 **열 연결 템플릿 내려받기**를 누릅니다. 자동 영구 저장·서버 보관은 하지 않습니다.
3. 새 페이지나 다음 CSV에서 **열 연결 템플릿 가져오기**로 이 파일을 고릅니다. 현재 파싱된 열 이름이 정확히 맞을 때만 역할 후보를 채웁니다. 열 순서는 달라도 되지만 누락·중복·다른 표 종류는 부분 적용하지 않고 거절합니다.
4. 원본 군 값 A/B는 비워집니다. 새 CSV의 값을 직접 입력하고 역할·제외 열 확인 체크 후 **연결 적용하고 집계 확인**을 누릅니다. 숫자와 실험 조건은 다시 확인해야 하며 조건·근거는 모름/빈값으로 초기화됩니다.

템플릿은 `ab-column-profile` 식별자, 내부 형식 1, 표 종류, 역할별 선택한 열 이름의 정확한 UTF-8 SHA-256 지문 또는 null만 담는 별도 최대 8KiB UTF-8 JSON입니다. 열 이름 목록·파일명·원시 행·ID·미리보기·원본 군 값·고객군 이름·조건 근거를 저장하지 않습니다. **지문은 익명성 보장이 아닙니다.** 열 이름 추측이 가능하고 로컬 파일 이름·시각 등 메타데이터도 공유 전에 검토해야 합니다. 기존 프로젝트 JSON·LLM·공개 보고서에는 이 템플릿이나 열 지문을 추가하지 않으며 실험 데이터 해시 계보와도 분리합니다.

`test_group`, `variant_name`, `conversion_count`, `recipient_count`, `subscriber_key`, `contact_key` 등 한정 별칭은 역할 후보일 뿐 의미 인증이 아닙니다. 모호한 후보는 자동 선택하지 않습니다. 현재 군 열 값 안내를 보고 정확한 원본 값을 지정하세요. 관측 완료 열과 결과는 생략해 품질 오류를 피할 수 없고 세 군 이상에서 행을 버려 두 군으로 만들지 않습니다.

**합성 연습 CSV 내려받기**는 [고정 합성 파일](examples/SYNTHETIC_CRM_MAPPING.csv)만 내려받고 현재 입력은 바꾸지 않습니다. 고객 데이터를 합성이라고 이름만 바꿔 내보내지 않습니다. 이 예제의 네 행은 전체 분모 2,000, 성공 280입니다. 실제 엔진 기대 결과는 `column_profile_smoke` 로그에 기록하며 원하는 승자 이야기를 고정하지 않습니다. 현재 160.16초 영상은 기존 설계·조건·분석 설명을 그대로 보존했으며 새 템플릿 튜토리얼은 아닙니다. ## 실행 조건을 모를 때

무작위 배정·독립·개인별 관측 완료·고정 종료에 **확인됨 / 아님 / 모름**으로 답합니다. 기본값은 모름이며 네 항목 모두 확인됨이 아니면 추론을 열지 않습니다. 집단 기준 사전성의 아님·모름은 집단을 탐색으로 제한하며 유효한 전체 추론까지 막지는 않습니다. 계획 확인은 이 상태를 자동 확인하지 않습니다.

선택 근거 메모(항목당 1,000 UTF-16 코드 단위)는 사용자 진술이며 독립 검증이 아닙니다. 메모는 로컬 프로젝트 JSON과 로컬 결과의 계산 방법에만 담고 공개 HTML/PDF·최소 AI 전송 정보에는 넣지 않습니다. 개인정보·비밀값을 적지 마세요. 상태와 메모를 바꾸면 이전 결과·확인·공유·인쇄를 폐기합니다.

구형 파일의 체크 true는 ‘구형 사용자 확인’으로 유지하고 근거를 만들지 않습니다. false는 ‘미확인/모름’이며 ‘아님’으로 바꾸지 않습니다. 새 실제 입력에는 합성 가정·메모가 이어지지 않습니다. 현재 영상은 설계·조건 기록을 포함한 합성 실제 앱 시연이며 사용자 과업 성공률·학습 효과·실제 성과의 증거가 아닙니다. 자세한 호환 정책은 [입력 계약](INPUT_CONTRACT.md)을 참조하세요.
