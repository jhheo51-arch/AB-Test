# 화면 흐름 검토 — v0.1 → 실제 입력 버전

검토 성격: 실제 브라우저 경로 확인과 디자이너의 휴리스틱 검토. 실사용자 인터뷰·완료 시간 측정은 아니다. 기존 v0.1과 검증 기록은 보존한다.

## 실제 관찰

- ‘결과가 있어요’로 시작해도 계획 화면의 편집 필드 10개를 먼저 지나며 예시 확인을 요구한다. 기존 결과를 가져오는 경로에 맞춰진 입력이 아니다.
- 대화는 고정 응답이고 CSV는 비활성 상태다. 이 경계 표시는 정확하지만 실제 데이터 검토를 시작할 수는 없다.
- 이전 반복 검토에서 모바일 결과의 표가 상위 그리드를 늘리는 가로 넘침을 수정했고, 5개 단계의 4개 폭에 대한 회귀검사를 수행했다.
- 계획 수정 시 고정 결과 연결을 끊는 방식은 정직하다. 실제 버전에서는 ‘막힘’에서 끝내지 않고 수정된 입력을 다시 분석하는 경로가 필요하다.

## 우선 수정 세 가지

| 우선 | 관찰과 영향 | 수정 | 비용 판단 |
|---|---|---|---|
| 1 | 결과가 있는 사용자도 긴 예시 계획을 거쳐 실제 입력을 못 함 | 결과 가져오기 경로에서는 실제 표·CSV 입력을 먼저 두고, 분석 조건을 짧은 명세로 확인 | 중간 |
| 2 | 품질 상태가 수동 데모 선택이라 실제 오류와 연결되지 않음 | 파서·입력 검증 오류를 행/열/코드와 함께 보여주고, 수정 후 재분석 | 중간 |
| 3 | 원래 계획을 복원해야만 결과를 볼 수 있음 | 계획·자료 수정 시 결과를 무효화하고, 실제 엔진으로 다시 계산. 현재 변경 회차를 표시하되 보안 감사 이력이라고 부르지 않음 | 중간 |

## 유지할 것

자연어 대화와 구조화 화면 분리, 관측·통계·실질 판단 구분, 합성 예시 표시, 집단 정보가 없을 때 집단 결과를 만들지 않는 원칙, 원자료를 외부에 자동 전송하지 않는 경계를 유지한다.

## 수정 전후 문구

| 전 | 후 |
|---|---|
| 고정 합성 예시 불러오기 | 합성 표로 체험 / 실제 표 붙여넣기 / CSV 선택 |
| 고정 예시 결과 보기 | 입력 확인 후 분석 |
| 통계 엔진 미연결 | 계산 방법·보정·가정과 실제 결과 상태 표시 |
| 고정 데모 답변 | 규칙 기반 안내 또는 실제 LLM 설명을 출처와 함께 구분 |

## 새 버전 완료 검토

정상 표와 CSV, 오류 입력과 누락, 전체·세그먼트와 직접 차이, 근거 부족, 변경 후 재계산, 원자료 미전송, LLM 연결 실패까지 실제 경로로 확인한다. 후속 보고서에서 구현·검증·미지원과 실제 LLM 호출 여부를 따로 말한다.
