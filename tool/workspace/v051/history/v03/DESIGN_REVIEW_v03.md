# 작업실 v0.3 디자인 검토

## 근거와 범위

- 참고: https://developers-apps-in-toss.toss.im/design/components
- 참고: https://toss.tech/article/43385
- 공식 페이지를 HTTP 200으로 열고 공개 설명을 확인했습니다. 공개 TDS의 사용 범위가 앱인토스 파트너 서비스에 제한됨을 고려해 UI Kit·전용 서체·로고·컴포넌트 코드를 가져오지 않았습니다. 소비자 토스 앱을 직접 조작·검증한 것은 아닙니다.
- 명확한 정보 위계, 한 행동에 집중하는 문구, 역할 기반 색의 일반 원칙을 독자적인 CRM A/B 작업 화면에 적용했습니다. 아래 수치는 토스 공식 토큰이 아니라 작업실에 맞춘 제안입니다.
- Pretendard는 별도 오픈소스 서체입니다. 토스 전용 서체로 소개하지 않습니다. 고정 버전 v1.3.9의 패키지에서 다운로드하고 SIL OFL을 함께 보관했습니다.

## 실제 대비 검사

`mira_contrast_matrix`로 계산했습니다. 본문/보조/강조/경고와 네 밝은 표면의 16개 조합 모두 본문 AA 4.5:1을 넘었습니다. 흰 글자와 주 버튼·hover·toast의 3개 조합도 본문 AA를 넘었습니다. 큰 글자 AA 3:1도 모두 통과했습니다.

|실제 사용 쌍|대비|
|---|---:|
|본문 #202B3A / 흰색|14.30:1|
|보조 #586779 / 배경 #F5F7FA|5.39:1|
|강조 #174EA6 / #EDF3FF|7.05:1|
|흰색 / 버튼 #1F62D1|5.64:1|
|흰색 / hover #174EA6|7.85:1|
|입력 경계 #7F8C9F / 흰색|3.41:1|
|입력 경계 #7F8C9F / 페이지 배경|3.18:1|
|입력 경계 #7F8C9F / 입력 표면 #FBFCFE|3.32:1|

경계색은 UI 요소 기준으로 평가하며 본문에 쓰지 않습니다. 연한 장식 구분선은 활성 입력의 유일한 경계로 쓰지 않습니다. 이 계산은 전체 접근성·실사용성 인증이 아닙니다.

## 선택 이유 — 세 줄

1. 파란색은 다음 행동에, 큰 숫자는 비교에 써서 한 화면에서 무엇을 해야 하는지 읽히게 했습니다.
2. 입력을 중심에 놓고 메모를 분리해, 결과를 가져온 사람이 설정 문서부터 읽지 않게 했습니다.
3. 친근한 화면으로 바꿔도 합성 표시·분석 한계·전송 확인은 유지해 쉬움이 근거 생략으로 바뀌지 않게 했습니다.

## 재확인

실제 Chrome에서 1440px와 390px 화면을 캡처해 위계·겹침·잘림을 확인했습니다. 첫 결과 입력, 오류, 조건 미확인, 수정 후 재분석, 저장·복원, 합성 출처 유지, 공유 제외, 실제 모델 성공과 주입한 실패를 시험합니다. 실제 시험 수와 최신 결과는 BROWSER_VERIFICATION.json과 UI_VERIFICATION_v03.json을 우선합니다. 최초·중간 캡처와 달리 최종 캡처는 final_ 접두사로 보관합니다.

Configure 중심 / Compare 보조 구조입니다. 형태적 자체 점검에서 장식 그라디언트·아이콘 타일·가짜 수치·좌측 장식 레일·유리 효과·중앙 영웅 구도를 쓰지 않았습니다. 이 자체 검토는 사람의 디자인 승인이나 사용성 시험이 아닙니다. 최종 시각 방향의 확정은 사용자에게 남깁니다.
