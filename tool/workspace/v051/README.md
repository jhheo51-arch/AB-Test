# CRM A/B 테스트 작업실 v0.5.1 — R01~R03 안정화

열 연결 → 결과 요약 → 판단 작성을 개선한 실제 로컬 앱입니다. 이전 v0.5 원본은 보존했습니다. CRM 발송·고객 관리·실험 배포 도구가 아닙니다.


## 이번 안정화와 현재 단계

- **R01:** 엔진 0.2.0의 38개 오류 코드 허용목록. 미등록 코드는 CLI 전에 거절하며 프런트엔드도 코드를 임의 수선하지 않습니다. raw_data_sent=false 대신 검사한 필드·허용 값·정상 생성기 범위를 응답합니다. 익명성·출처·사실 정확성 인증은 아닙니다. HTTP/sentinel/명시적 fixture 136개 사례 통과, 그 검사에는 실제 모델 호출이 없습니다.
- **R02:** 탐색과 결측을 함께 설명하고, 실제 결과에서 분모 0인 A/B를 특정하며, invalid는 입력 수정 전 수치 사용 불가로 안내합니다. 설명 26개 그룹 통과.
- **R03:** 최초 입력 기록·복원 전 직전 계산·이번 계산 입력의 종류와 SHA-256을 구분합니다. 계보 단위 16개·브라우저 14개 통과.

최초 입력은 앱 입력 텍스트 UTF-8이며 파일 원본 바이트의 독립 인증이 아닙니다. 현재 입력은 엔진에 전달한 정규 CSV 또는 복원 집계 CSV입니다. 원문/열·군 연결/고정 문장/집계 복원을 구분합니다. 최초·직전·현재의 제한된 계승이며 모든 중간 이력을 보관하지 않습니다. 복원 기록은 원자료 재검증이 아니고 구형 해시는 대상 미분류로 보존합니다. 입력 편집·교체 시 새 계보로 시작합니다. 해시는 진위·익명성의 보증이 아닙니다.

형식 5의 lineage가 종류를 명시하고 source_digest는 호환 필드입니다. 현재 해시가 있으면 중복 값의 일치도 검사합니다. UI 계획·입력 vN은 수정 번호이며 파일 형식 번호가 아닙니다.

이전 병렬 도구 호출의 시간 초과는 이번 개별 재실행에서 재현되지 않았습니다. 원인은 미확정이며 코드 수정으로 해결했다고 주장하지 않습니다. 새 흐름 37개·기존 전체 43개(실제 LLM 포함)·이전 문제 회귀 22개·맥락 19개를 재확인했습니다.

실제 사용자 검토는 아직 진행하지 않았습니다. 별도 AB_Test_User_Review_v051에 합성 자료·과업지·진행자 가이드·엔진 계산 참고·빈 기록지를 준비했습니다. 본인이 수행하면 저자 자기 검토로 기록합니다. 고객 자료 반출·녹화는 기본 조건이 아닙니다. 실제 관찰 후 설계 진입 흐름을 구현하며 AI 모의 발언으로 대신하지 않습니다.

## 실행

Windows에서 Python 3가 설치된 상태로 `launch.cmd`를 실행하세요. 또는 이 폴더에서 `python launch.py`를 실행합니다. 표시된 `http://127.0.0.1:포트`를 Chrome/Edge에서 열고 실행 창을 유지하세요. `index.html`만 더블클릭해서는 Worker·로컬 설명 브리지를 실행할 수 없습니다. 일반 사용에 Node는 필요하지 않습니다.

LLM 설명은 기존 Hermes `mira` 프로필을 사용합니다. 해당 연결이 없는 환경에서는 연결 실패를 표시하고 계산 결과를 유지합니다. 인증정보는 포함하지 않았으며 앱이 인증 파일을 직접 읽지 않습니다. 원자료 전송 동의로 확대하지 않습니다.

## 1. 열 연결

1. 표 붙여넣기 또는 CSV 파일 가져오기 후 **데이터 확인하기**를 누릅니다.
2. 영문 표준 헤더가 아니면 원본 5행과 열 연결 초안을 보여 줍니다.
3. A/B·성공 수·분모·집단, 또는 가명 ID·결과·관측 상태 열을 직접 확인합니다.
4. `control`/`treatment` 같은 원본 군 값도 사용자가 A/B에 명시적으로 연결할 수 있습니다. 표준 헤더여도 **열 연결·A/B 값 직접 수정**으로 열 수 있습니다.
5. 연결과 연결하지 않은 열의 제외를 확인하고 **연결 적용하고 집계 확인**을 누릅니다.
6. 집계 숫자와 설계 조건을 확인한 다음 분석합니다.

추천은 열 이름의 제한된 별칭 사전이며 AI 의미 이해나 자동 인증이 아닙니다. `id`, `result`처럼 추천에 없는 이름은 드롭다운에서 직접 선택하세요. 첫 행은 열 이름이어야 합니다. 모든 행과 선택한 값을 유지하며 A/B 군 이름 외 값은 재코딩하지 않습니다. 알 수 없는 군, 중복 연결, 잘못된 숫자, 미성숙·중복 참여자는 조용히 제외하지 않습니다. 개인형의 원본 `observed` 열은 생략할 수 없습니다. 다른 이름의 관측 상태 열도 올바르게 연결하고 실제 의미를 확인해야 합니다.

입력은 UTF-8 CSV/TSV 2MiB·50,000행, 연결 원본은 최대 100열입니다. 성능 보장이 아닙니다. 미리보기·열 연결·원시 행은 기기 안에서 처리하며 저장/공유/LLM에 포함하지 않습니다. 연결하지 않은 원본 열은 계산에서 제외되므로 의미와 품질에 필요한 열인지 직접 확인하세요.

## 2. 결과 요약

첫 카드에서 **관측 차이 B−A → 통계적 판정 → 미확인 사업·보호 조건 → 다음 확인**을 읽습니다. A/B 카드는 중립 색으로 통일했습니다. 실험 맥락과 계산 근거는 펼쳐서 확인합니다. 보고서·PDF의 계산 근거는 펼친 상태로 내보냅니다.

승패 보류는 효과 없음·동등·안전의 증명이 아닙니다. 통계적 우세는 실제 적용 승인이 아닙니다. 숫자 계산 엔진·Worker는 v0.5와 같은 바이트이며, 설명만 R02 범위에서 수정했습니다. 통계 지원 범위는 넓히지 않았습니다. 군별 합산 분모 200,000과 집단·설계 제한은 그대로입니다.

## 3. 판단 작성

**검토 방향 → 근거 → 적용 전 확인할 조건 → 재검토 시점**으로 기록합니다. 통계적 우세와 반대 방향을 검토하면 안내하지만 자동으로 선택을 바꾸거나 승인하지 않습니다. 미기록은 미기록으로 남깁니다. 판단·공유 범위 변경 시 공유 확인과 인쇄 스냅샷을 폐기합니다.

프로젝트 JSON은 **형식 5**로 저장하고 2/3/4/5를 읽습니다. 구형 복원에서는 새 판단 방향·확인 조건을 빈값으로 두며 추정하지 않습니다. 새 파일은 구버전 앱이 지원하지 않을 수 있으니 이 앱으로 복원하세요. 저장 범위는 최대 8MiB·50,000 집계 셀이며 복원용 CSV도 2MiB 이하여야 합니다. 저장 가능과 추론 가능은 다릅니다.

새 판단 필드는 프로젝트·보고서·실제 PDF에 연결되지만 LLM 전송 상태에는 추가하지 않습니다. 직접 적은 자유 서술은 자동 익명화되지 않으므로 개인정보·업무 기밀을 쓰지 말고 공유 전에 확인하세요.

## 실제 검사 결과

- 새 흐름 브라우저 37개 통과: 열 연결 확인, 실제 파일 업로드, A/B 값 변환, 원시 값 제외, 미성숙 차단, 저장/복원, 판정별 색·위계, 390px 화면 포함.
- 기존 전체 브라우저 43개 통과: 실제 LLM 응답·표시와 상태 전송 경계 포함.
- 이전 네 문제 회귀 22개, 맥락 회귀 19개 통과.
- 열 연결 Node 12개, 프로젝트 스키마 27개, 엔진 19개 그룹, 로컬 설명 26개 그룹 통과.
- 독립 기준: 일반 224개, 직접 차이 수치 5개, 조건 차단 5개, API 상한 차단 1개 통과. 별도 Holm 단위 기준과 실제 엔진 가족 검증은 구분합니다.
- 기본 보고서 PDF 3쪽 / 새 판단 PDF 3쪽, 실제 추출 최소 12pt. 새 판단·재검토 조건 포함 및 제외한 원본 열 부재 확인.
- 실제 사용 조합의 본문 대비: 흰 표면 본문 14.30:1, 보조 5.78:1, 중립 카드 보조 5.39:1, 주 버튼 글자 5.64:1. 본문 AA 충족. 전체 접근성 인증은 아닙니다.

자세한 결과는 `VERIFICATION_v051.json`, `WORKFLOW_VERIFICATION_v05.json`, `BROWSER_VERIFICATION.json`, `tests/UNIT_VERIFICATION_v051.json`, `v05-evidence/`를 참조하세요. 숫자는 상호 관련된 assertion이며 독립 사용자 시험 수가 아닙니다.

구현 중 회귀가 발견돼 수정했습니다. 기존 맥락 검사는 새 펼침 버튼을 연 뒤 확인하고 저장 형식 5를 검사하도록 갱신했습니다. 추가 설명이 붙은 자연문장이 열 연결 대상으로 들어가던 경로는 필요한 열 수를 확인해 명시적으로 거절했습니다. 미성숙 회귀는 실제 `IMMATURE_OBSERVATION` 코드까지 검사합니다.

## 한계와 이력

자유로운 상황 설명에서 후보·계획을 생성하는 전체 대화는 아직 완성되지 않았습니다. 계획 안내는 규칙 기반입니다. 전자책의 모든 분석·지표, CRM 연동, 시간·금액·순차·군집 설계를 지원하지 않습니다. 이전 감사의 복합 제한 설명·코드 허용목록·해시 종류는 이번 R01~R03에서 보완했지만 전체 보안 인증을 뜻하지 않습니다. 실제 CRM 실무자 사용성·현장 효과·보안 전 범위 검증은 남아 있습니다.

이 앱은 공개 토스 UI 원칙을 참고한 독자 구현입니다. 토스 TDS·전용 폰트·로고를 사용한 공식 제품이 아닙니다. Pretendard 및 라이선스는 `fonts/`에 보존합니다. `history/`와 이전 판 이름의 일부 이미지는 보존 자료이며 현재 화면은 `v05-evidence/`를 우선하세요.

이 문서는 검증한 앱의 사용 안내입니다. 원격 등록 상태와 최신 과제는 저장소의 진입 문서·로드맵을 함께 확인하세요. 현재 검증 상세는 R01_VERIFICATION.json, R02_VERIFICATION.json, R03_BROWSER_VERIFICATION.json, v051-evidence/를 우선합니다.
