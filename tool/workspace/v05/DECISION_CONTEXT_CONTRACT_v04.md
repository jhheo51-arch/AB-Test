# v0.4 설명·맥락 계약

## 범위

UI의 주요 표면은 기존 Configure/Compare를 유지한다. 색·서체를 다시 바꾸지 않고 실험 맥락과 판정 이유의 연결을 보강한다. 값은 사용자 기록과 실제 엔진 결과에서만 읽는다.

## 실험 맥락

- policyA/policyB, metric, window, purpose를 기존 입력에서 재사용한다.
- audience는 선택 서술, UI와 복원에서 최대 300자. 고객 목록이 아니라 이번 실험의 대상 범위를 기록한다.
- 설명 미기록·대상 미기록을 명시한다. 집단 이름만으로 전체 적용 모집단을 추정하지 않는다.
- 사용자 텍스트는 결과·다운로드·인쇄에서 HTML 이스케이프한다.
- 새 project version=3. version=2 복원 시 audience가 없으면 빈 문자열로 둔다. 같은 원자료를 재검증했다는 인증으로 표현하지 않는다.

## 이유 분류

|상태|설명 근거|금지할 해석|
|---|---|---|
|HOLD|실제 보정 판정이 hold|효과 없음·안전·동등 증명|
|HOLM_HOLD|raw p<=0.05, adjusted p>0.05, m>1, 엔진 hold|명목 구간만으로 승리 판정|
|SUPERIOR|엔진 A/B 승패와 실제 관측 방향|사업 이익·보호·실제 적용 승인 확정|
|ASSUMPTIONS|추론 미확인 상태|임의로 체크하면 실제 설계가 검증됨|
|EMPTY_ARM|전체 한쪽 분모 0|무작위 조건 미확인과 같은 원인으로 설명|
|UNSUPPORTED|설계·alpha·규모 등 지원 밖 상태|지원하지 않는 p값 생성|
|EXPLORATORY|집단 사전성 미확인|실제로 언제 기준을 정했는지 알고 있다고 주장|
|MISSING_SEGMENT|집단 결측으로 집단 추론 제한|해당 참여자를 전체에서 제거|
|GROUP_UNSUPPORTED|군·집단의 정보 부족|없는 자료를 채워 추론|
|INTERACTION_*|실제 직접 위험차 비교의 상태·조정 p|한 집단만 유의하면 고객군 효과 차이 확정|

설명은 검정·구간을 재계산하지 않는다. alpha는 기존 경로의 0.05 고정이다. 실제 표의 원 p·조정 p·명목 구간을 함께 유지하고 Holm 동시 구간 또는 Fisher와 완전한 쌍대라고 하지 않는다. 다음 확인은 기록·사전 계획·보호·적용 범위를 검토하는 안내이며 추가 표본이 반드시 결론을 바꾼다는 보장이 아니다.

## 공유와 모델

- 기본 보고서는 전체 결과와 실험 맥락을 포함한다. 집단 상세 제외 시 집단 설명과 직접 차이 설명도 실제 DOM·파일에서 제외한다.
- 사용자 자유 서술은 별도 공유 범위다. 대상·정책에 집단 이름이나 민감정보를 직접 쓰면 자동으로 지워지지 않으므로 확인 문구를 표시한다.
- LLM payload는 v0.3의 판정 상태 계약을 유지한다. 정책·대상·목적·원자료·새 설명 본문을 전송하지 않는다.
- 규칙 설명과 실제 모델 응답의 출처를 구분한다. 모델 실패가 원래 통계·로컬 설명을 없애지 않는다.

## 표현과 선택 이유 — 세 줄

1. A/B 이름과 대상을 숫자 옆에 남겨 결과를 다른 사람에게 전달할 때 실험의 의미가 사라지지 않게 했다.
2. ‘보류’와 ‘판정 미실행’의 원인을 구분해 다음 확인을 숫자 해독이 아닌 기록 검토로 연결했다.
3. 기존 검정과 전송 계약을 보존해 설명을 쉽게 만드는 일이 분석 기준의 완화나 추가 반출이 되지 않게 했다.

색은 v0.3 제안 토큰을 유지했다. 새 본문도 #202B3A/#586779와 #FFFFFF/#F5F7FA 표면을 사용하며 기존 대비 도구 결과의 본문 AA 통과 조합이다. 별도 브랜드 확정·Open Design 게시를 하지 않았다. 구조적 자체 점검에서는 장식 수치·아이콘 타일·새 영웅 화면을 추가하지 않았다. 실제 사람의 이해 개선 여부는 아직 검증하지 않았다.
