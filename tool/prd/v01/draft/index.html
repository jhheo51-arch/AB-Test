실험 한 건을
제대로 설계하고 판단하기.

CRM에서 하는 A/B 테스트를 제대로 설계·분석·판단하는 전문 도구. 전자책의 TRI-V를 사용자의 실제 실험으로 연결합니다.

제품 방향 사용자 합의요구사항·UI·기술 방식 제안실행 앱 아님

이 파일은 작동하는 탐색·필터·메모 기능을 갖춘 HTML PRD입니다. 통계 계산, CSV 분석, 고객 데이터 처리, CRM 연결과 실제 승인 기능은 구현하지 않았습니다. 아래 수용 기준은 앞으로 검증할 조건이며 통과 실적이 아닙니다.

01 / INTENT

제품의 중심은 CRM이 아니라 A/B 테스트입니다.

A/B 테스트를 설계하고, 전체·세그먼트별 결과를 분석해, 어떤 결론까지 내릴 수 있는지 알려주는 도구.

고객을 관리하거나 메시지를 보내기 위해 여는 제품이 아닙니다. CRM 실무자가 실험을 맡았지만 설계와 해석에 확신이 없을 때, 비교의 근거와 승패, 적용 범위를 확인하기 위해 엽니다. CRM은 중심 적용 맥락이며, 모든 도메인을 지원하는 범용 실험 플랫폼으로 확대하지 않습니다.

전자책에서 가져올 판단 구조

축제품의 질문남기는 결과
V1 / Variable Control이 비교와 결과를 믿고 해석할 수 있는가?설계·품질·성숙도와 제한된 주장
V2 / Vector Segmentation누구에게 어떤 효과가 있고 어디까지 적용할 수 있는가?전체·사전 집단의 결과와 적용 범위
V3 / Value-Linked Decision이 근거로 지금 어떤 선택을 할 수 있는가?결론·보호 조건·추가 확인·재검토

TRI-V는 저자 제안 실무 틀입니다. 새로운 통계 검정법이나 현장 성과가 검증된 이론으로 표현하지 않습니다. 기존 계획과 분석을 재사용하고, 모든 실험에 세분화·금전 모형·재실험을 강제하지 않습니다.

02 / USER & PROBLEM

실험을 맡았지만 결과 해석에 확신이 없는 실무자.

주 사용자 / 가상 페르소나 김서윤

경력 2년 CRM 마케터. 기존 발송 도구와 스프레드시트가 있고, 가명 배정·결과 자료를 권한 내에서 확보할 수 있다고 가정합니다. 분석가는 필요할 때 돕지만 상시 전담하지 않습니다.

예약은 늘었는데 실제 완료가 늘었는지, 신규·기존 고객에게 같은 안을 적용해도 되는지 설명해야 합니다.

완료하고 싶은 작업

  • 실험 전에 질문과 판정 기준을 정한다.
  • 결과를 해석할 수 있는지 먼저 확인한다.
  • 전체·세그먼트 승패와 불확실성을 이해한다.
  • 가능한 결론과 다음 확인을 짧게 남긴다.
  • 충분한 근거가 있으면 불필요한 분석을 끝낸다.

가상 업무 시나리오이며 실제 인터뷰·구매 의사 검증이 아닙니다. 승인자와 분석가는 결과를 검토하는 보조 역할입니다. 초기부터 조직 전체의 승인 시스템을 만들지 않습니다.

첫 관통 사례

JH Motors의 A 차량 가치 안내와 B 시승 편의 안내를 비교합니다. 정한 관측 창 내 시승 완료가 주지표, 예약은 진단, 수신 거부는 보호 지표입니다. 이는 기존 전자책의 가상 기업·합성 교육 사례이며 실제 OEM 성과가 아닙니다. 파일럿 통계의 숫자를 이 PRD에서 새로 만들지 않습니다.

03 / SCOPE

좁은 분석 범위, 끝까지 이어지는 사용 경험.

첫 버전에 포함 / 제안

  • A/B 두 안, 고객 단위 무작위 배정
  • 사전에 정한 고정 표본·종료 규칙
  • 고객별 발생/미발생으로 표현한 주지표
  • 표본·기간 설계와 최소 사업 효과 구분
  • CSV 구조·관측·지원 조건 검증
  • 전체 승패와 효과·불확실성
  • 사전 정의한 주요 집단 축의 비교
  • 짧은 판단 기록과 파일 내보내기

첫 버전에 포함하지 않음

  • 고객 DB·영업·상담·CRM 전체 관리
  • 메시지 발송·여정·실시간 개인화 운영
  • SDK 배정과 모든 CRM 자동 연동
  • 무제한 세그먼트 탐색 후 자동 적용
  • 군집·밴딧·순차·다수 정책의 자동 분석
  • 장기 LTV·순이익·ROI 자동 확정
  • 동의·계정·기업 승인 시스템 대체
  • AI가 원인·숫자·최종 승인을 생성

Segment는 핵심 기능입니다. 고객군별 실험 효과와 적용 범위를 검토하지만, 고객 목록을 관리·배포하지 않습니다. V2 적용 대상 확인은 항상 수행하고, 상세 집단 계산은 질문과 근거가 있을 때 엽니다.

전자책의 A/B/H·비용·공유 용량 사례 전체를 이 초기 엔진이 계산한다고 주장하지 않습니다. 미지원 조건은 이유와 필요한 검토를 남깁니다.

04 / USER FLOW

설계부터 시작해도, 기존 결과를 가져와도 같은 실험으로.

질문 정의 → 설계 확인 → 데이터 확인 → 전체·집단 분석 → 결론 기록

  1. 지금 결정할 것무엇을 누구에게 바꾸려는지와 A/B 정책을 적습니다. 설계 중인지, 이미 결과를 본 사후 검토인지 기록합니다.
  2. 실험 계획 연결지표·분모·배정·관측·종료·비교 계획을 입력하거나 기존 명세를 참조합니다. 결과를 본 뒤 쓴 기준은 사후로 표시합니다.
  3. 지원 범위와 데이터 확인가명 고객 결과를 매핑하고 중복·누락·미성숙·배정 기록을 확인합니다. 오류가 제한하는 지표와 주장을 구분합니다.
  4. 전체 결과와 필요한 집단 비교효과·구간·검정 결과·승패를 확인합니다. 세그먼트는 사전/탐색과 집단 차이 검토를 분리합니다.
  5. 결론과 다음 확인책의 여섯 항목 기록을 만들고, 필요한 확인 또는 생략 이유와 재검토 조건을 남깁니다. 도구의 실행 후보가 실제 시행 승인은 아닙니다.
05 / REQUIREMENTS

요구사항과 수용 기준

P0는 초기 완결 경로의 필수 요구사항입니다. P1은 후속 개선입니다. 아래 우선순위는 제안이며, 구현 완료나 사용자 최종 승인을 뜻하지 않습니다.

R01 / P0

실험 질문과 시점 기록

A/B 정책, 대상, 배정 단위와 현재 결정, 계획 작성·결과 열람 시점을 연결합니다.

수용 기준: 필수 비교가 비어 있으면 설계 확정 불가. 사후 입력을 사전 계획으로 표시하지 않음.

R02 / P0

지표와 판정·종료 계획

주지표 하나, 보호·진단 역할, 분모·방향·관측 창·가설·종료 규칙을 기록합니다.

수용 기준: 주지표를 결과 열람 후 바꾸면 변경 이력과 영향 경고가 남고 기존 결론 확인 상태가 해제됨.

R03 / P0

표본과 관측 기간 설계

기준율·검출 목표 효과·유의수준·검정력·배정 비율에 따른 계획을 제시합니다. MDE와 최소 사업 효과는 별도 필드입니다.

수용 기준: 사용한 방법과 가정을 표시. 적격 유입 정보가 없으면 기간을 확정하지 않음. 낮은 사건 수와 미지원 설계는 제한 표시.

R04 / P0

표준 CSV와 열 의미 매핑

가명 고객 결과 파일과 별도 설계 명세를 연결합니다. 모든 CRM 파일을 자동 해석한다고 약속하지 않습니다.

수용 기준: ID·군·시점·관측·주지표의 의미가 불명확하면 분석 준비 완료 불가. 원본 파일의 해시와 매핑 버전을 기록.

R05 / P0

데이터 품질과 관측 성숙도

중복, 잘못된 군, 범위 밖 값, 배정/분석 단위, 누락과 미성숙을 구분합니다. SRM은 설계에 맞는 경우에만 평가합니다.

수용 기준: 미성숙·미연결을 자동 0 처리하지 않음. 배정 열만으로 무작위화를 확인했다고 하지 않음. 경고마다 근거와 제한할 주장을 명시.

R06 / P0

전체 A/B 효과와 승패

A/B 분모·사건 수, 절대차·상대차, 구간·검정 결과·방향과 승패를 함께 제공합니다.

수용 기준: 사전 방법·가설·비교 가족 안에서만 판정. 상대차의 기준율이 0이면 정의 불가로 표시. 비유의성을 동등성으로 표현하지 않음.

R07 / P0

사전 세그먼트 비교

배정 전 주요 축 하나와 초기 두 비중첩 집단을 지원하는 안을 제안합니다. 기준시점·결측·표본·집단별 효과와 직접 효과 차이를 연결합니다.

수용 기준: ‘한 집단만 유의’를 집단 차이 증명으로 표시하지 않음. 비교 가족·다중성·정보량 상태와 탐색 지위를 병기. 사후 클릭자만 골라 주효과를 대체하지 않음.

R08 / P0

보호 상태와 적용 판단 분리

주지표 승패와 보호·사업 조건, 실제 적용 선택을 다른 상태로 저장합니다.

수용 기준: 수신 거부 차이가 비유의하다는 이유로 안전 표시 불가. 허용 한계·검증 방법이 없으면 보호 판단 미확인. 이익으로 동의·안전 문제를 상쇄하지 않음.

R09 / P0

여섯 항목 판단 기록

현재 결정, V1 근거·제한, V2 적용 대상, V3 선택, 추가 확인·생략, 재검토 조건을 기존 근거와 연결합니다.

수용 기준: 원천이 없는 값을 AI가 채우지 않음. 충분한 근거가 있으면 불필요한 심화 분석을 강요하지 않음. 도구의 실행 후보와 사람의 승인을 구분.

R10 / P0

분석 재현과 파일 내보내기

원자료·설계·매핑·계산 방법·버전·제한·결정 기록을 내보냅니다. 최초 제안 형식은 JSON과 인쇄 가능한 HTML입니다.

수용 기준: 동일 입력·설정에서 허용 오차 안의 동일 결과. 입력·설정 변경 시 영향받는 결과는 ‘재계산 필요’가 됨. 새로고침 후 복원은 사용자가 명시적으로 저장한 파일로 시험.

R11 / P0

설명과 계산의 분리

규칙과 통계 코드는 검증 가능한 결과 객체를 만들고, 설명은 그 값을 참조합니다. 초기 버전은 AI 없이도 핵심 경로를 완주합니다.

수용 기준: 수치·경고·결론마다 결과 키 또는 근거 연결. LLM이 검정을 임의 변경하거나 원인을 확정하지 않음.

R12 / P0

개인정보와 로컬 처리 경계

가명 키를 기본으로 하고 이름·전화·이메일을 요구하지 않습니다. 제품의 로컬 우선 처리와 명시적 파일 저장은 제안입니다.

수용 기준: 고객 원자료를 localStorage·분석 로그·외부 AI로 자동 저장/전송하지 않음. 네트워크·저장·삭제 동작을 검사. 브라우저 캐시·다운로드·공유 PC 위험을 안내.

R13 / P1

기존 플랫폼 결과 참조

플랫폼 결과와 그 방법·분모·기간을 근거로 연결하는 모드입니다. 원자료 재분석과 구분합니다.

수용 기준: 순차·적응배분·승자 후 발송 자료를 고정표본으로 자동 재계산하지 않음. 독립 검증을 하지 않은 참조 결과에 검증 완료 표시 불가.

R14 / P1

책의 예제로 배우기

합성 사례를 같은 흐름으로 읽고 자신의 실험과 구분해 시작합니다. 책을 구매·완독해야 사용할 수 있게 만들지 않습니다.

수용 기준: 교육용 배너가 모든 예제 결과에 유지됨. 예제와 실제 프로젝트를 섞어 저장하지 않음.

R15 / P1

실험 기록 재사용

이전 지표·설계·적용 범위를 새 실험 초안에 재사용하되, 과거 결과나 승인을 승계하지 않습니다.

수용 기준: 새 실험 ID와 기준시점 확인. 사전 고객 속성과 보호 기준을 새 실험에 맞게 검토.

일치하는 요구사항이 없습니다. 검색어 또는 우선순위 필터를 바꿔 주세요.
