# CRM A/B 테스트 도구 — PRD 문답과 현재 합의

## 먼저 읽기

**현재 합의의 기준은 [DECISIONS.md](DECISIONS.md)입니다.** 기존 HTML은 초기 참고 초안이며, 전체 PRD를 승인하거나 앱을 구현한 상태가 아닙니다. PRD는 사용자와 중요한 질문 하나씩 논의하며 구체화합니다.

## 합의된 제품 방향

CRM에서 하는 A/B 테스트를 제대로 설계·분석·판단하는 전문 도구. CRM 전체 관리나 범용 캠페인 실행 플랫폼은 만들지 않습니다. 전자책 TRI-V에서 발전하며 업무와 일상에서도 진입 장벽이 낮은 자연어 사용을 지향합니다. 업무 밖 사례의 상세 지원 범위와 개별 통계 방법은 미확정입니다.

우선순위:
1. 결과를 보고 승패와 고객군 차이를 제대로 이해하기.
2. 실험을 시작할 때 설계에 확신을 갖기.
3. 결과를 바탕으로 다음 행동을 결정하기.

## 합의된 흐름

**상황 설명 → 목적 확인 → A/B 후보 제안 → 지표·배정·판정 계획 추천 → 사용자 확인 → 결과 분석과 설명**

사용자는 상황·목적·현실 제약을 설명합니다. 도구는 계획 초안을 제안하고 사용자에게 이해 가능한 형태로 확인받습니다. 결과 데이터가 없는 상태에서 실제 승자나 효과를 만들지 않습니다. LLM의 제안·설명과 검증 가능한 통계 계산을 분리합니다.

## 첫 버전의 경계 — 사용자 동의

- **외부에서 실제 실험을 수행하고, 도구는 자연어 설계·분석·설명에 집중합니다.**
- 결과 입력은 CSV만 강요하지 않는 방향입니다. 표 붙여넣기·가이드 양식의 지원 범위를 검토하되 집계표와 원자료로 가능한 판단을 구분합니다.
- A/B 화면·설문 배포와 참여자 데이터 수집은 초기 MVP에서 제외합니다.
- 외부 실행의 부담이 실제 사용을 막는다면 후속에 제한된 내장 비교 시험을 검토할 수 있습니다. 반드시 구현한다는 확정은 아닙니다.
- 두 군·고정표본·이항 결과와 주요 사전 집단 축은 기존 초안의 초기 지원 제안입니다. 세부 방법·범위·검증 기준은 문답으로 확정해야 합니다.

## 보존한 네 원칙

1. 통계 설정보다 사용자의 목적·현실 조건을 먼저 확인하고 도구가 설정을 제안합니다.
2. 위너 판단에서 관측 순위·통계적 근거·실질적 적용 판단을 구분합니다.
3. 배정 비율, 지표의 분자·분모, 기준율·목표 효과, 통계 오류 기준을 구분합니다.
4. 변수는 바꿀 것·같게 유지할 것·배정에서 고려할 것·사전 분석 집단·측정 결과로 분류합니다.

자세한 내용과 사용자가 보존 요청한 표는 [합의 기록](DECISIONS.md)에 있습니다.

## 아직 정하지 않은 것

- 첫 실제 지원 사례와 업무 밖 실험의 지원 범위.
- 구체 입력 스키마, 가명 키·분모·누락·관측 창 계약.
- 검정·구간·집단 차이·다중성·보호 평가·표본 계획의 확정 방법과 검증 기준.
- 자연어 추천을 확인·수정하는 상세 화면과 정보 부족 시 질문 흐름.
- 지원 데이터 규모·처리 위치·저장·보안·LLM 공급자와 모델.
- 최종 제품 이름·디자인·개발 일정.

## 현재 상태

방향과 초기 경계를 합의한 문답형 PRD 작성 단계입니다. 초기 HTML 문서는 존재하지만 제품 앱, 일반화된 통계 엔진, 외부 CRM 연결, 실제 고객 데이터 처리·실험 실행·사용자 효과 검증이 완료된 것은 아닙니다. 기존 전자책·데이터·통계 자산과 과거 도구 문서는 그대로 보존합니다.
