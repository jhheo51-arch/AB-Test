# CRM A/B 테스트 도구 — PRD 기준안 

## 문서의 상태와 우선순위

사용자가 Q01~Q10에 답했고, ‘남은 10문제는 너가 추천하는 방향으로 갈게’라고 선택을 위임했다. 이 문서는 직접 합의한 사항과 위임받아 선택한 제품 기본 방향을 묶은 기준안이다. Q11~Q20은 사용자가 개별 답변한 것으로 기록하지 않는다.

구체 통계 알고리즘, 보안·저장 구현, 지원 규모와 계산 정확성이 검증됐다는 뜻은 아니다. 이전 index.html은 문답 이전의 참고 초안이며 현재 기준안보다 우선하지 않는다. 이 파일은 로컬에 저장했고, 현재 실행 상태는 도구의 진입 문서와 앱 안내를 우선한다.

## 제품 정의

**CRM에서 하는 A/B 테스트를 제대로 설계·분석·판단하는 전문 도구.** CRM 전체 관리, 발송, 고객 목록 배포나 범용 실험 실행 플랫폼을 만들지 않는다. 전자책 TRI-V를 실제 사용 흐름으로 연결하며, 업무와 일상의 쉬운 자연어 진입을 지향한다. 일상에서의 모든 실험 설계를 지원한다는 뜻은 아니다.

우선순위: 결과·승패·집단 차이 이해 → 설계에 대한 확신 → 다음 행동 결정 지원.

기본 흐름:

**상황 설명 → 목적 확인 → A/B 후보 제안 → 지표·배정·판정 계획 추천 → 사용자 확인 → 결과 분석과 설명**

실제 실험 수행과 데이터 확보는 외부에서 한다. 데이터가 없으면 방향과 계획까지만 제공하고 승자를 만들지 않는다.

## A. 사용자가 직접 정한 Q01~Q10의 기준

- 낮은 진입 장벽과 LLM 자연어 안내. 후보를 모르는 상황에서도 시작한다.
- 통계 설정 전에 목적·대상·수집 가능성·위험·현실 조건을 묻는다.
- 도구가 후보·지표·분모·배정·판정 계획을 추천하고 사용자가 확인·수정한다.
- 위너는 관측 순위, 통계적 근거, 실질적 적용 판단을 구분한다.
- 배정 비율, 측정의 분자·분모, 기준율·목표 효과, 통계 오류 기준을 구분한다.
- 변수는 변경 요인, 유지 요인, 배정 요인, 사전 분석 집단, 결과·보호 지표로 분류한다.
- 첫 버전은 외부 실험 + 도구 안의 설계·분석·설명. 내장 설문·배포·수집은 제외한다.
- 자연어·표 입력과 파일 입력을 모두 지원한다. 파싱된 숫자와 분모를 사용자에게 확인받는다.
- 주 분석은 성공 여부·비율 중심. 시간·금액의 평균을 억지로 이항 결과로 바꾸지 않는다.
- 도구가 세그먼트 기준을 추천하되 직접 지정·수정할 수 있다. 사전 계획과 사후 탐색을 구분한다.
- 자연어 대화와 별도 실험 계획·결과 화면을 함께 제공한다.
- 개인이 설계·분석하고 결과를 공유한다. 공동 편집·팀 권한·다단계 승인은 제외한다.
- Q10 합의: 고객별 원자료는 기기에서 검증·계산하고, LLM에는 추천·설명에 필요한 최소 정보만 전송한다. 원자료 업로드 승인이 외부 AI 전송 승인은 아니다. 대화 속 민감정보와 소집단 집계의 위험도 점검한다.

자세한 기존 네 원칙은 DECISIONS.md 2절, 사용자 발언은 INTERVIEW.md에 보존한다.

## B. 위임받아 선택한 나머지 열 항목

### Q11. 시작 경로 — 세 가지 진입, 하나의 실험 기록

‘상황만 있어요’, ‘실험 계획이 있어요’, ‘결과가 있어요’로 시작한다. 어느 경로든 동일한 실험 객체와 화면을 사용한다. 이미 있는 계획과 결과를 처음부터 다시 작성하게 하지 않는다. 결과를 먼저 가져오면 사후 검토라는 상태를 보존한다.

수용 기준: 결과 없이 분석 완료로 이동하지 않으며, 기존 명세 재사용과 사전·사후 구분이 가능하다.

### Q12. 첫 파일 지원 — CSV 우선, 표 붙여넣기 병행

처음에는 CSV와 자연어·표 붙여넣기를 지원한다. UTF-8 안내와 열 미리보기·매핑을 제공한다. Excel 직접 읽기는 후속으로 두되 스프레드시트의 표를 붙여넣어 시작할 수 있게 한다. 업로드 파일을 실행하거나 셀 값을 코드로 평가하지 않는다. 다운로드 CSV의 수식 삽입 위험도 방어한다.

수용 기준: 잘못된 인코딩·열·범위를 알아볼 수 있게 안내한다. 지원하지 않는 파일이나 해석 못 한 값으로 임의 분석하지 않는다. 실제 스키마·크기·인코딩 지원 목록은 시험 후 확정한다.

### Q13. 저장·로그인 — 제품 가입 없이 시작, 명시적 프로젝트 파일 저장

제품 자체의 회원가입을 초기 필수로 두지 않는다. 실험 계획·확정 입력·집계·결과·방법/버전·제한을 프로젝트 파일로 저장·복원한다. 고객별 원자료와 비밀값은 기본 저장에서 제외하고, 원자료 재분석이 필요하면 같은 파일을 다시 선택한다. 데이터 원본의 해시로 일치 여부를 확인한다.

브라우저 저장공간에 원자료를 자동 영구 저장하지 않는다. 닫으면 사라질 수 있는 미저장 상태와 파일 저장 상태를 알린다. 제품 가입이 없다는 것과 외부 LLM 인증·네트워크가 불필요하다는 것은 다르다. 클라우드 동기화는 초기 제외다.

수용 기준: 저장·복원과 원자료 재선택 경로, 잔여 데이터 삭제, 버전 불일치 및 저장 실패를 실제로 시험한다. 현재는 구현된 저장 보안이 아니라 요구사항이다.

### Q14. 공유 — 읽기용 HTML 보고서와 인쇄 PDF

요약, 전체·세그먼트 결과, 불확실성, 제한과 판단 근거를 읽기용 HTML로 내보내고 인쇄 PDF를 제공한다. 공개 공유 링크와 서버 업로드는 초기 제외한다. 프로젝트 파일과 읽기용 보고서를 구분한다.

원자료·식별자는 기본 공유에서 제외한다. 소집단·민감 속성의 집계도 무조건 안전하다고 하지 않고 공유 미리보기에서 포함 범위를 확인한다. 숨긴 집단을 반영해 결론의 제한도 표시한다. 집단 크기의 보편적 안전 기준을 임의로 정하지 않는다.

수용 기준: 출력 버전·시점·방법·분모·한계가 남고, 숨기기로 선택한 원자료나 집단 정보가 파일에 포함되지 않는지 검사한다.

### Q15. 결과 설명 — 결론 먼저, 근거를 펼쳐보기

첫 화면은 ‘무엇을 확인했는가 / 무엇은 모르는가 / 다음에 무엇을 확인할까’를 먼저 보여준다. 이어 전체 A/B 사건·분모·효과·구간, 필요한 집단 비교, 계산 방법과 원천을 펼친다. 검증 가능한 수치 참조를 사용하고 꾸며낸 승리 확률을 표시하지 않는다.

통계적 승패와 실질적 충분성·보호 상태는 다른 값이다. 주지표가 불확실하면 진단 지표의 좋은 결과로 대체하지 않는다. 설명은 비전문가용으로 하되 수치와 원천은 검증자가 찾을 수 있어야 한다.

수용 기준: 요약 문장과 상세 결과가 동일 결과 객체를 참조하며, 불확실·미지원 상태를 성공 표현으로 바꾸지 않는다.

### Q16. 정보 부족과 오류 — 안내는 계속, 근거 없는 판정은 중단

필요한 정보가 없으면 다음 판단을 바꿀 질문 하나를 우선한다. 이미 받은 정보는 재질문하지 않는다. 데이터·배정·관측 상태가 불명확하면 가능한 기술 비교와 불가능한 인과/승패 주장을 구분한다. 중대한 오류는 영향을 받는 계산·주장을 막되 설계 초안 작성과 안내까지 불필요하게 막지 않는다.

분석·관측을 더 하면 반드시 승리한다는 식으로 권하지 않는다. 누락·미성숙은 0으로 채우지 않는다. 충분한 근거가 있으면 추가 세분화·금전 모형을 강제하지 않는다.

수용 기준: 오류마다 근거·제한된 주장·수정 방법 또는 필요한 정보가 표시된다.

### Q17. 초기 통계 지원 — 검증 가능한 좁은 범위

두 안, 독립 고객/참여자 단위, 고정 표본·사전 종료, 이항 결과를 초기 계산 범위로 삼는다. 세그먼트는 주요 사전 축 하나와 비중첩 두 집단의 비교부터 구현·검증한다. 속성 결측 고객은 전체 결과에서 숨겨 제거하지 않으며 집단 분석의 제한을 남긴다. 그룹을 나눈 것만으로 정보량이나 다중 비교 문제가 해결됐다고 하지 않는다.

개인 반복·교차, 군집·공유 용량, 순차·적응배분, 다수 정책과 시간·금액 분석은 초기 자동 계산에서 제외한다. 이런 상황도 설명·계획 안내는 하되 지원 범위를 넘는 판정을 하지 않는다.

정확한 검정·구간·집단 직접 차이·다중성·보호 평가·표본 계획 방법, 기본 오류 기준, 수치 허용 오차와 희귀 사건 처리는 통계 명세를 작성하고 검증한 후 고정한다. 이 문서의 지원 선택만으로 계산 정확성을 보증하지 않는다.

### Q18. 변경·재현 — 계획과 결과를 버전으로 연결

A/B, 지표, 분모, 관측, 집단, 계산 방법이 바뀌면 영향받는 결과를 ‘재계산 또는 재검토 필요’로 표시한다. 원래 결과는 이력으로 남기고 현재 결과와 구분한다. 수정 시점과 결과 열람 여부를 기록한다. 사후 가설을 사전 기준으로 소급하지 않는다.

수용 기준: 동일 입력·방법의 재현, 원자료 해시와 방법 버전 추적, 변경 후 예전 승패의 오표시 방지를 시험한다.

### Q19. LLM 연결 — 교체 가능한 설명 계층과 고장 시 대안

LLM 연결은 통계 엔진과 분리한다. 공급자·모델·비용·호스팅은 아직 선정하지 않고 연결 계층을 교체 가능하게 설계한다. 원자료 대신 허용된 목적·열 의미·집계·검증 결과를 최소 전송한다. 대화 원문도 민감정보를 포함할 수 있어 전송 범위를 안내한다.

LLM 출력은 정해진 구조와 계산 결과 참조를 검증하고, 임의 코드·SQL 실행이나 도구 권한으로 연결하지 않는다. 파일·문서 안의 지시는 데이터로 취급한다. 키는 HTML·저장 보고서·고객 프로젝트 파일에 넣지 않고 별도 안전한 연결 계층에서 취급한다.

연결 실패 때 기존 입력과 결과를 잃지 않는다. 수동 계획 입력과 검증된 결과·기본 설명을 사용할 수 있게 한다. 완전 오프라인 LLM이나 무료 사용을 약속하지 않는다.

### Q20. 개발·검증 — UI와 통계를 따로 시험하고 합치기

현재 기준안을 바탕으로 실제 클릭 흐름의 HTML 프로토타입을 먼저 검토한다. 가상·고정 데이터는 데모임을 표시하고 실제 결과와 섞지 않는다. 병행해 입력·통계·전송·저장 계약을 명세하고 시험한 다음 엔진을 연결한다.

제품 완료는 단순 화면 표시가 아니라 한 실험의 설계→입력 확인→전체/집단 분석→판단→저장/공유 완주로 정의한다. 정상·효과 불확실·0 사건·잘못된 분모·누락/미성숙·집단 오해·보호 미확인·미지원 설계·저장 실패·LLM 실패를 포함한다. 통계는 별도 구현 또는 신뢰할 수 있는 기준 계산과 비교한다.

사용자 효용은 기존 CRM 결과와 제대로 된 검토 양식을 기준으로 누락·오판·불필요한 확인·전체 준비 부담을 비교한다. 실험 전 평가 기준을 정하고 시간 절감·성과·지불 의사 수치를 만들어내지 않는다. 실제 참여자 모집과 데이터 처리는 별도 실행 범위로 다룬다.

## C. 구현 전에 남은 기술 명세

기본 질문을 반복하는 대신 아래는 개발 명세 작업으로 해결한다.
- 정확한 CSV·프로젝트·보고서 스키마와 버전 마이그레이션.
- 통계 방법, 지원 가정, 비교 가족, 수치 검증 픽스처와 허용 오차.
- 민감정보·소집단·대화 전송의 검사와 전송 전 안내, 키 보관·삭제 정책.
- 실제 기준 기기의 파일 크기·행 수·성능·브라우저 지원 범위.
- LLM 공급자·연결 인증·비용·실패 처리와 계산 근거 참조 계약.

새 비용 지출, 외부 서비스 연결, 실제 고객 데이터 전송, 공개 배포를 이 문서가 자동 승인하지는 않는다.

## D. 현재 완료 상태

제품 방향과 첫 버전 정책을 정리한 PRD 기준안이다. 실제 분석 앱·통계 엔진·보안·저장·LLM 연결·내보내기 기능은 아직 구현·검증 완료가 아니다. 기존 HTML PRD의 문서 기능 검사 결과를 제품 시험으로 사용하지 않는다.
