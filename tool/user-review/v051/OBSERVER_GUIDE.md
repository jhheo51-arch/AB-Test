# 진행자 관찰 가이드

## 관찰과 해석을 구분하기

아직 실제 검토 결과가 없습니다. 참가자의 발언은 들은 그대로 적고, 진행자 추정은 별도 칸에 씁니다. AI가 만든 모의 발언·예상 성공률은 넣지 않습니다. 녹화나 개인정보 수집은 별도 동의 없이 하지 않습니다.

## 과업별 관찰 기준

| 과업 | 관찰할 행동 | 해석 시 주의 |
|---|---|---|
| T01 연결 | 추천을 그대로 확정하는지, 의미·A/B 값을 읽는지, 집계 수를 확인하는지 | 연결은 실험 타당성 인증이 아님. 과업지에 제공한 예시 설계 기록 외 조건을 만들어 주지 않기 |
| T02 전체 | 관측 비율과 통계 판정을 구분하는지, 모르는 조건을 말하는지 | 보류를 무효과·동등·안전으로 바꾸지 않기 |
| T03 집단 | 개별/보정 결과와 직접 차이를 구분하는지 | 한 집단만 유의하다고 집단 효과 차이를 확정하지 않기 |
| T04 판단/공유 | 검토 방향·이유·미확인 조건·재검토를 남기는지, 공유 제외를 실제 보고서에서 확인하는지 | 특정 검토 방향을 유일한 정답으로 요구하지 않기. 사업적 선택은 통계 결과와 별도 |
| T05 복원/오류 | 원본 기록과 이번 집계 해시를 구분하는지, 미관측 오류를 읽고 중단/질문하는지 | 복원이 원자료 재검증이나 진위 인증이라고 말하지 않기. 미성숙 행을 지우게 유도하지 않기 |
| T06 인터뷰 | 결과 없는 상황에서 먼저 필요한 질문과 입력을 말하는지 | 현재 미구현인 설계 대화를 성공/실패율에 합산하지 않기 |

## 계산 근거

`observer/ENGINE_GROUND_TRUTH.json`은 과업지의 합성 설계 가정을 모두 확인한 표준 집계에서 엔진을 실제 실행한 참고 결과입니다. 참가자 응답이 아닙니다. 참가자가 모르는 조건을 확인하지 않았다면 먼저 실제 선택 조건과 화면 결과를 기록하고, 참고 수치를 맞추라고 강요하지 않습니다. 전체·집단·직접 차이의 `p_raw`, `p_adjusted`, `winner`와 `family`를 원래 키로 대조하세요. 구간은 명목 구간이며 가족 동시 구간이 아닙니다.

해시 과업에서는 값 자체를 외우거나 검산하게 하지 말고 각각의 대상과 한계를 이해하는지 묻습니다. 최초 입력은 앱 입력 텍스트 UTF-8이고 파일 원본 바이트의 독립 인증이 아닙니다. 복원은 기록을 계승하며 모든 중간 이력을 자동으로 보관하지 않습니다. 구형 해시는 대상을 미분류로 남깁니다.

## 개입과 기록

- 사용자가 막히면 먼저 어디서 무엇을 기대했는지 물어봅니다.
- 도움을 주면 개입 시각/과업/내용과 이후 행동을 분리해 적습니다.
- 정확한 원문 발언과 화면 상태를 남기되 고객 정보·회사 기밀을 기록하지 않습니다.
- `SESSION_TEMPLATE.json`을 참가자별 사본으로 사용합니다. 동의가 없거나 중단된 과업은 성공으로 채우지 않습니다.
- 실제 시간을 측정하지 않았다면 `elapsed_seconds`는 null로 둡니다. 시간이 짧다고 이해가 정확했다고 가정하지 않습니다.

## 다음 설계 진입으로 넘기는 양식

각 관찰을 **과업 ID → 실제 행동/발언 → 막힘 또는 오독 → 필요한 질문/화면 → 제안 → 재검토할 상태**로 정리합니다. 우선순위는 영향·반복 관찰·수정 비용으로 제안하고 참가자 수보다 많은 시장 수요로 일반화하지 않습니다.

실제 기록이 들어오기 전에는 설계 진입 구현의 근거를 ‘사용자 검토 결과’라고 쓰지 않습니다. 기존 제품 합의는 유지하되 참가자의 발언에서 얻은 수정과 기존 제안을 구별하세요.
